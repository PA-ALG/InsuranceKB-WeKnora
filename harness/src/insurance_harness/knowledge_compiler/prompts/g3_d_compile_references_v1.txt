G3 Gemini D semantic compile references v1
Return one canonical JSON object matching the supplied semantic-reference schema. Cover every field_ref exactly once. Select evidence only from the supplied source_ref values and echo a non-empty exact substring as quote, preferably one that occurs uniquely and supplies sufficient context. Author every business value, body, condition, exception and valid_time yourself from the supplied sources; the local projector only resolves evidence and machine-owned identities. Preserve negations, subjects, versions and time limits. Use unknown only when the sources do not support a known value. Do not calculate hashes, offsets, assertion IDs, concept IDs, page IDs, request identities or audit keys. Do not create release authority.
Obey the supplied fixed extraction policy and window kind. An ENTITY_SYNTHESIS window has no fields and may return definitions and pages only for its one entity. Every new definition must be linked by a page returned in that same response. A FIELDS window must return definitions=[] and pages=[] and cover its supplied 1–10 field_ref values exactly once; its concept_ref values may select only the supplied existing concept reference index. Full existing definition bodies are supplied only when linked to this entity's existing fields or pages. A pure carry entity with no new field target receives no model compile window; local code preserves and validates its existing members.
For every evidence quote, copy one short, sufficient, contiguous substring from the offered source spans. Prefer a uniquely occurring quotation; if the same exact quotation occurs more than once inside the offered spans, every matching position is retained as evidence. Preserve every character and line ending exactly. Never concatenate fragments, normalize CR/LF, or copy a whole unrelated block merely to obtain a match.
Prefer a sufficient quotation contained on one source line. If a value needs several separate facts, cite separate exact substrings as separate evidence entries; never join wrapped lines into a sentence. If a quotation must cross a line break, preserve the original CR and LF characters in the JSON string exactly.

For every requested field, use exactly one of these semantic forms:
- present: value is a nonempty string, evidence contains exact source quotes that directly support this value, and unknown_reason is null.
- absent_explicitly: value is a nonempty string stating the explicit exclusion or absence, evidence quotes the source statement that explicitly establishes this absence, and unknown_reason is null. A list of other benefits, a heading, or a missing mention does not establish explicit absence.
- unknown: value is null, evidence is an empty array, and unknown_reason is a nonempty explanation of what the supplied sources do not establish.
Do not infer that an unmentioned feature is excluded. Do not emit absent_explicitly with a null value. If no direct supporting quote exists, use unknown instead of inventing a value or evidence.
