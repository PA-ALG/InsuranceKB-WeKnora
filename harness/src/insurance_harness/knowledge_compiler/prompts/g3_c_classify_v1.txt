G3 C semantic classification v1
Return one canonical JSON object matching the supplied response schema. Include EVERY required property for EVERY material, entity, label and evidence row. In particular, every entity MUST include name; use the product name supported by the supplied source, or null if unavailable. A nullable required property must be present with null, never omitted.
Use only the supplied sources. Follow the supplied response schema: when blocks provide evidence_locator_refs, each evidence row MUST select one supplied locator_ref whose quote supports the claim. Copy only that exact locator_ref; do not return a locator object, offsets or a rewritten quote. The source locator_ref is distinct from your local evidence_ref. Never invent or combine source references.
For the legacy schema only, each block contains unchanged text and locally computed evidence_locators. For each evidence row, copy one complete evidence_locators object verbatim into locator, including block_ref, start, end and the entire quote. Select a locator whose quote supports the claimed value or classification. Do not shorten the quote, calculate character positions, invent a block reference, or guess missing evidence. Repeated text has different valid positions; preserve the position of the chosen supplied locator. If evidence is insufficient, leave the unsupported entity/value unasserted and preserve uncertainty.
Do not infer source scope, page identity, hashes, policy receipts, or final dispositions. Check all required keys and every copied locator against the supplied schema/input before returning JSON.
Evidence scope is exact: material_role evidence must have entity_ref=null and field_key=null. issuer/product_code/name/version/classification evidence must have entity_ref equal to its entity and field_key=null. Only purpose=field may have a non-null field_key. Entity identity_evidence_refs may reference only issuer/product_code/name/version evidence for that entity. Label evidence_refs may reference only classification evidence for that entity. Material material_role_evidence_refs may reference only material_role evidence. All local identifiers and reference lists must be unique. For the legacy locator schema all material/entity/evidence/label lists and reference lists must also be lexicographically sorted by their identifiers.
Every non-null issuer, name, product_code and version_label MUST appear verbatim in the quote selected by an identity_evidence_ref with the corresponding purpose (issuer/name/product_code/version). Do not expand a brand into an inferred corporate name, add an inferred product-name prefix, or invent a version suffix such as “版”. Choose a different supporting source reference or return null for the unsupported property. filing_or_registration.value must be supported by purpose=version evidence in identity_evidence_refs. Each non-null valid_from/valid_through date must occur exactly in that version evidence; otherwise return null. Source support must come from that entity's own identity_evidence_refs, not from an unrelated quote elsewhere in the document.
Build evidence first, then complete the claims it supports. Check version_label and filing_or_registration.value separately: a filing-number quote alone does not support a version label elsewhere. If two quotes are needed, create two distinct evidence_ref rows with purpose=version and include BOTH in identity_evidence_refs. The same offered locator_ref MAY be reused in multiple evidence rows with distinct evidence_ref values and the appropriate purposes; only evidence_ref identifiers must be unique.
Example: an offered quote contains “示例保险（优选版）”, and another contains “备案号 EXAMPLE-2026”. Claiming version_label="优选版" and filing_or_registration.value="EXAMPLE-2026" requires a version-purpose row for EACH supporting quote. The product-name quote may also support a separate name-purpose row. A label must reference its own classification-purpose row, even when the same quote also supports the name. These example values are illustrative only; never copy them into a result.
Before returning, check each non-null product_code against its OWN product_code-purpose selected quote, each version claim against version-purpose evidence, and each label against classification-purpose evidence. A matching value in another row or another material is insufficient. Never rewrite a quote, invent a reference or borrow another material's identity. Keep unsupported claims null and uncertainty explicit under the original rules.
