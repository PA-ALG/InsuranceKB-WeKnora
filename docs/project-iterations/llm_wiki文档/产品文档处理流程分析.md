# 产品文档上传处理流程完整分析

> 本文档详细分析当前系统对保险产品文档的完整处理流程、支持的文件格式、以及需要优化扩展的地方。

---

## 一、完整处理流程总览

### 1.1 端到端流程图

```
用户上传文件
    ↓
[1] 上传接收与安全检查 (upload.rs)
    ├── 文件类型白名单校验
    ├── 文件大小限制 (最大 200MB)
    └── 路径安全检查 (防止路径遍历)
    ↓
[2] 文件预处理 (fs.rs + preprocessOcrText)
    ├── PDF 四级 fallback 处理
    ├── Office 文档 (docx/xlsx/pptx) 文本提取
    ├── 图片 OCR (vision LLM)
    └── OCR 文本清洗与修复
    ↓
[3] Ingest 缓存检查 (ingest-cache.ts)
    ├── 检查文件内容 hash
    └── 未变更文件直接跳过
    ↓
[4] 产品目录抽取 (product-catalog-extractor.ts)
    ├── Section 拆分 (targetChars=6000)
    ├── Group-round LLM 抽取 (5-8模块/轮)
    ├── Module → Field 桥接映射
    ├── 字段值标准化与清洗
    └── Phase 5 精炼 (针对缺失字段二次处理)
    ↓
[5] Markdown 文件生成与写入
    ├── 模块文件 (1模块/文件)
    ├── 字段文件 (1字段/文件)
    ├── 主产品文件 (汇总表格+知识缺口)
    └── 增量原文文件 (多次上传时)
    ↓
[6] 知识后处理 (knowledge-postprocess.ts)
    ├── DomainSkill 分发处理
    ├── 实体标准化与去重
    └── 来源列表合并
    ↓
[7] 身份解析 (knowledge-identity-resolution.ts)
    ├── 4-phase LLM 识别
    ├── 相同实体/别名/兄弟/父子关系判断
    └── 关系边写入
    ↓
[8] 全局关系生成 (knowledge-global-relation.ts)
    ├── 跨文档关系推断
    ├── 关系评分 (confidence × strength)
    └── 阈值过滤 (0.65)
    ↓
[9] 冲突检测与 Review 队列 (conflict-detector.ts)
    ├── 字段值冲突检测
    ├── 新旧值对比
    ├── Review 记录持久化
    └── 知识演化记录
    ↓
[10] Concept 聚合 (concept-aggregator.ts)
    ├── 跨产品概念聚合
    ├── 模块+字段实体统一处理
    └── 跳过 rejected 状态文件
    ↓
[11] 向量嵌入 (embedding.ts)
    ├── 文本 chunk 化
    ├── 向量化与 LanceDB 存储
    └── 动态维度支持 (1152维)
    ↓
[12] 数据版本更新与 UI 刷新
    ├── dataVersion 递增
    ├── 文件树实时刷新
    └── 预览同步更新
```

## 二、支持的文件格式详解

### 2.1 文件类型分类表

| 类别 | 扩展名 | 处理方式 | 说明 |
|------|--------|----------|------|
| **PDF** | `.pdf` | 四级 fallback pipeline | 核心业务文档格式 |
| **Word** | `.docx`, `.doc` | docx-rs 提取 | 产品条款、服务手册 |
| **Excel** | `.xlsx`, `.xls`, `.ods` | calamine 提取 | 费率表、对比表 |
| **PPT** | `.pptx`, `.ppt` | ZIP+XML 提取 | 产品宣讲材料 |
| **图片** | `.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.bmp` | vision LLM OCR | 扫描页、截图 |
| **Markdown** | `.md`, `.mdx` | 直接读取 | 已整理的知识页 |
| **文本** | `.txt`, `.csv`, `.json` | 直接读取 | 结构化数据 |
| **其他** | `.html`, `.htm`, `.rtf`, `.epub`, `.yaml`, `.yml` | 直接读取 | 辅助材料 |

### 2.2 PDF 四级 Fallback 处理机制

```
PDF 输入
    ↓
[Tier 1] 内部 OCR API (如果配置了 OCR_ENDPOINT)
    ├── 优先使用企业内部 OCR 服务
    ├── 最高精度
    └── 多模态识别
    ↓ 失败时降级
[Tier 2] pdf-extract (纯 Rust)
    ├── 直接提取文字层
    ├── 快速，无需外部依赖
    └── 乱码检测 (unique_char_ratio < 0.015 或 top_word_dominance > 0.20)
    ↓ 乱码或失败时降级
[Tier 3] pdftotext (Poppler)
    ├── 更高质量的文本提取
    ├── 需要系统安装 Poppler
    └── 同样做乱码检测
    ↓ 仍失败时降级
[Tier 4] pdftoppm → 图片页 → Vision LLM OCR
    ├── 将每一页转为 JPEG (DPI 150)
    ├── Vision LLM 做 OCR (并发 3 页)
    ├── 表格结构化输出 (Markdown 格式)
    └── 超时 180 秒/页
```

**乱码检测算法：**
- `unique_char_ratio < 0.015`：唯一字符比例过低，说明是重复乱码
- `top_word_dominance > 0.20`：单个词占比过高，说明是重复乱码

## 三、各类型文件详细处理策略

### 3.1 PDF 文件处理（最核心业务格式）

#### 3.1.1 处理工具链

| 层级 | 工具/库 | 技术实现 | 用途 |
|------|---------|---------|------|
| **Tier 1** | 内部 OCR API | `OCR_ENDPOINT` 环境变量配置 | 企业级高精度 OCR，优先使用 |
| **Tier 2** | pdf-extract | 纯 Rust 库 `pdf_extract::extract_text_from_mem()` | 快速提取 PDF 文字层，无外部依赖 |
| **Tier 3** | pdftotext | Poppler 工具集，`Command::new("pdftotext")` | 更高质量文本提取，带布局保留 |
| **Tier 4** | pdftoppm + Vision LLM | `pdftoppm` 转 JPEG (DPI 150) + VLM OCR | 扫描件 PDF 兜底方案 |

#### 3.1.2 定制化策略

**乱码检测算法（核心创新）：**
```rust
// 两个指标同时判定
unique_char_ratio < 0.015  // 唯一字符比例过低 → 重复乱码
top_word_dominance > 0.20  // 单个词占比过高 → 重复乱码
```

**图片 PDF 处理流程：**
1. `pdf_to_images_base64()` 将每页转为 JPEG
2. 包装为 `__PDF_IMAGE_PAGES__` + JSON marker
3. 前端 `pdf-ocr.ts` 拦截，调用 Vision LLM
4. **并发控制**：同时处理 3 页，防止 LLM 限流
5. **超时保护**：每页 OCR 超时 180 秒
6. **表格优化**：Vision LLM 输出 Markdown 表格格式

**Vision LLM OCR Prompt（定制化保险场景）：**
```
请对这张图片做高精度 OCR，直接输出可供知识库入库的原文。
必须遵守：
1. 提取所有可见文字，不要摘要、不要概括、不要省略。
2. 如果包含表格，必须逐行保留表格结构；序号、产品名称、代码、交期、1、1*、N、是、空白单元格、备注都要尽量原样保留。
3. 对长表格，不要只输出示例行；必须从第一行连续输出到最后一行。
4. 保持标题、页码、注释、表头、换行和列顺序。
5. 看不清的单元格用 [无法识别] 标注，不要猜测。
6. 直接输出原始文本内容，表格用 Markdown 表格格式。
7. 【严禁】用代码块（```）包裹输出内容，直接输出裸文本，不要加任何代码块标记。
```

**代码围栏清洗（post-Vision-LLM）：**
```typescript
// stripOcrCodeFences()
- 移除开头的 ```markdown 或 ```
- 移除结尾的 ```
- 处理 Vision LLM 不听话加的代码块包装
```

#### 3.1.3 PDF 图片提取

从 PDF 中提取嵌入图片（非扫描页图片）：
- 保存路径：`wiki/media/<source-slug>/img-<index>.png`
- 元数据：MIME 类型、宽高、SHA-256、页码
- **缓存策略**：SHA-256 去重，相同图片（Logo、页头）只调用一次 Vision LLM
- Markdown 注入：在原文末尾追加 `## Embedded Images` 章节

### 3.2 Word 文档处理（.docx）

#### 3.2.1 处理工具

| 工具/库 | 用途 |
|---------|------|
| **docx-rs** | Rust 原生 .docx 解析，读取 DocumentChild → Paragraph → Run → Text |
| **ZIP + XML** | 底层技术（.docx 本质是 ZIP 包） |

#### 3.2.2 实现逻辑（fs.rs）

```rust
fn extract_docx_text(path: &str) -> Result<String> {
    let data = fs::read(path)?;
    let doc = read_docx(&data)?;
    
    let mut paragraphs = Vec::new();
    for child in &doc.document.children {
        if let DocumentChild::Paragraph(p) = child {
            let text: String = p.children.iter()
                .filter_map(|c| if let ParagraphChild::Run(r) = c {
                    let t: String = r.children.iter()
                        .filter_map(|rc| if let RunChild::Text(t) = rc {
                            Some(t.text.clone())
                        } else { None })
                        .collect();
                    if !t.is_empty() { Some(t) } else { None }
                } else { None })
                .collect();
            if !text.trim().is_empty() {
                paragraphs.push(text);
            }
        }
    }
    Ok(paragraphs.join("\n\n"))
}
```

#### 3.2.3 限制与说明

- ❌ **.doc 旧版二进制格式**：当前仅返回占位符文本
- ❌ **.wps 国产格式**：完全不支持
- ✅ **图片提取**：支持从 .docx 提取嵌入图片
- ✅ **段落保留**：按原文档段落结构输出

#### 3.5.2 图片缓存机制

- **缓存结构**：
  ```json

    "<sha256>": {
      "caption": "图 1：保险责任说明",

      "model": "gpt-4o",
      "capturedAt": "2026-07-06T00:00:00Z"
    }
  }
  ```
- **回退哈希**：WebCrypto 不可用时用 FNV-1a 变种（非加密但足够去重）

### 3.8 OCR 文本后处理流水线

#### 3.8.1 三阶段清洗

```
原始 OCR 输出
    ↓
[阶段 1] stripOcrCodeFences()
    └─ 移除 Vision LLM 加的 ```markdown 代码块
    ↓
[阶段 2] cleanOcrArtifacts(productName?)
    ├─ 移除页码："第 3 页 共 25 页", "- 3 -", "3 / 25"
    ├─ 移除重复产品名页眉
    └─ 压缩空行：3+ → 2
    ↓
[阶段 3] repairOcrLineBreaks()
    ├─ 断句修复：无句末标点 + 下句非段落开头 → 合并
    ├─ 中文无空格，英文加空格
    └─ 保留表格、列表、标题结构
```

#### 3.8.2 断句修复规则

**合并条件（同时满足）：**
1. 当前行非空，下一行非空
2. 当前行**不以**句子结尾标点结尾（`。！？；：""…`）
3. 下一行**不以**段落开头标记开头（列表、标题、表格等）
4. 两行都不是表格行（`|` 开头）

**段落开头模式（PARAGRAPH_START）：**
```typescript
- 数字列表：(1)、1.、一、第一条、①
- 符号列表：•、-、·
- Markdown 标题：#、##、###
- 表格行：|
```

**分隔符智能选择：**
```typescript
if (中文字符) → 无空格直接连接
else → 加空格
```

## 五、核心模块详解

### 5.1 产品目录抽取器 (product-catalog-extractor.ts)

#### 3.1.1 处理架构（V4）

```
OCR 全文
    ↓
splitIntoSections (targetChars=6000)
    ├── 按语义分割成多个 Section
    └── 从 25000 降到 6000，平衡精度与性能
    ↓
Group-round LLM 抽取 (5-8 模块/轮)
    ├── A: basic_info (基础信息)
    ├── B: coverage (保险责任)
    ├── C: cost_rules (费用规则)
    ├── D: exclusion_uw (免责与核保)
    ├── E: claim_service (理赔与增值服务)
    ├── F: contract_admin (合同管理)
    └── G: disease_definition (疾病释义)
    ↓
parseModuleBlocks (解析 LLM 输出)
    ├── 提取关键字段表格
    └── 不依赖 LLM 生成全文
    ↓
mergeFragmentContents (合并片段)
    ↓
注入原文 (100% 保留，确保可追溯)
    ↓
Phase 5 精炼 (针对缺失字段二次聚焦)
    ├── 对 "未明确" 字段做二次 LLM 调用
    ├── 跨模块字段桥接
    └── 长文本字段自动合成
```

#### 5.1.2 险种分类与模块定义

支持的 6 大险种类别：
1. **医疗险**
2. **重疾险**
3. **意外医疗险**
4. **意外险**
5. **寿险**
6. **年金险**

每个险种对应：
- **专属字段**（Excel 对齐）
- **模块白名单**（防止越域生成）
- **抽取提示优化**

#### 5.1.3 字段值标准化与清洗

**占位符清洗规则：**
```typescript
PLACEHOLDER_REGEX = /^(未明确|未提及|未提到|未说明|未在本|未在证据|证据片段未|证据片段中未|证据中未|文中未|原文未|原文中未|材料未|未找到|未见|没有提到|证据不足|无明确|不涉及|暂未|无此信息|无相关|本章节未|条款未|不适用于本|N\/A|n\/a|无$)/
SOURCE_ONLY_PLACEHOLDER_REGEX = /^(?:详见来源文件|详见费率表|详见(?:原文|附件|附表|条款|附录)|参见来源文件|请参见来源文件)(?:[:：\s]|$)/i
WEAK_UNACTIONABLE_VALUE_REGEX = /^(?:需|需要|请|应)?(?:核对|查看|参见|参考|结合|确认).{0,24}(?:条款|合同|保险单|资料|约定|实际|具体)|^(?:以|具体以).{0,24}(?:条款|合同|保险单|资料|约定|实际|为准)$|^按(?:合同|条款|保险单)约定$/i
```

**字段值兼容性检查：**
- QA 字段：仅从明确问答类文件抽取
- 投保年龄：避免混入职业信息
- 保证续保：过滤纯数字期限

**标准化示例（交费方式）：**
```
"一次性交清" → "趸交"
"半年交一次" → "半年交"
"每季度交" → "季交"
"按月交费" → "月交"
"每年交" → "年交"
```

### 5.2 模块 → 字段桥接 (MODULE_TO_FIELD_BRIDGE)

解决问题：模块抽取了信息，但主产品表格字段仍为空。

桥接示例：
```typescript
{
  module: "保险责任",
  targetFields: ["保什么", "给付限额", "意外身故", "疾病身故", "全残保障"],
},
{
  module: "投保规则",
  targetFields: ["投保年龄", "投保职业", "犹豫期", "等待期", "宽限期"],
},
```

### 5.3 增量更新逻辑

**增量上传策略：**
1. 已有产品主文件存在时，增量上传只补空字段/新模块
2. 已有非空值不被自动覆盖
3. 字段冲突进入 Review 队列
4. 增量原文单独保存为 `增量原文-{sourceStem}.md`

**删除清理策略：**
1. 单个文件删除 → 只清理该文件独占支撑的字段值
2. 最后一个真实源文件删除 → 清理整套产品派生知识
3. `product_meta.json` 不算有效源资料

## 六、知识冲突与 Review 机制

### 6.1 冲突检测流程

```
新字段值到达
    ↓
检查 isMissingFieldValue()
    ├─ 是 → 跳过，不生成冲突
    └─ 否 → 继续
    ↓
检查 isLessSpecificThanExisting()
    ├─ 是 → 忽略，不覆盖旧值
    └─ 否 → 继续
    ↓
与已有值对比
    ├─ 完全相同 → 跳过
    └─ 不同 → 生成 Conflict
    ↓
Review 队列记录
    ├─ old_value, new_value
    ├─ source_file
    ├─ timestamp
    └─ status: pending
    ↓
人工审核
    ├─ 采用新值 → 同步更新模块+字段+主产品+Concept
    ├─ 保留旧值 → 标记 resolved
    └─ 编辑后保存 → 自定义值
    ↓
知识演化记录
    └─ 显示完整变更历史
```

### 6.2 Review 决策时的同步范围

当点击"采用新值"时，同步更新：

## 十、删除与更新机制详细解读

### 10.1 当前的处理逻辑总览

系统采用 **来源追踪 + 增量更新 + 级联清理** 的三层架构：

```
核心设计原则：
1. 来源可追溯：每个 Wiki 页面的 frontmatter 记录 sources: [来源1, 来源2]
2. 增量不覆盖：已有非空字段不会被自动覆盖，冲突进入 Review 队列
3. 删除不扩散：只删除当前来源独占支撑的内容，保留其他来源支撑的内容
```

---

### 10.2 手动删除或更新某个 Wiki 页面的处理

#### 场景 A：用户在 Wiki 编辑器中手动删除一个页面

**处理流程**：

1. **调用 `cascadeDeleteWikiPage()`**（`wiki-page-delete.ts`）
   - Step 1: 删除 Markdown 文件本身
   - Step 2: 删除 LanceDB 中的向量索引（通过 `removePageEmbedding()`）
   - Step 3: 级联清理（如果是来源摘要页 `wiki/sources/<slug>.md`）：
     - 删除对应的 `wiki/media/<slug>/` 图片目录
     - 删除该来源的抽取图片

2. **错误处理策略**
   - 文件删除失败：抛出异常，调用方处理
   - 向量删除失败：记录日志，不阻塞主流程
   - 媒体目录删除失败：最宽松处理，不存在或失败都不报错

#### 场景 B：用户在 Wiki 编辑器中手动修改并保存一个页面

**处理流程**：

1. **前端自动保存**（`preview-panel.tsx` / `wiki-editor.tsx`）
   - 编辑内容实时保存
   - 从编辑态切回预览前强制 flush，避免看到旧内容

2. **同步更新依赖**（针对产品字段页）
   - 更新主产品汇总表格
   - 刷新概念聚合页
   - 更新向量索引（后台异步）

3. **UI 刷新**
   - 知识树监听 `dataVersion` 实时重读
   - 右侧预览同步更新

---

### 10.3 上传同名产品文档（内容变更）的处理

#### 核心逻辑：增量更新，不覆盖已确认值

**处理流程**（`product-catalog-extractor.ts`）：

```
Step 1: 检查 Ingest Cache
    ├─ 相同文件内容（SHA256）→ 直接跳过
    └─ 内容变更 → 继续处理

Step 2: 读取现有产品文件
    ├─ 主产品文件已存在 → 增量模式
    ├─ 主产品文件不存在 → 全新模式

Step 3: 增量抽取策略
    ├─ 已有非空字段 → 跳过不覆盖
    ├─ 已有空字段 → 尝试填充
    ├─ 新模块 → 新增模块页
    └─ 字段冲突 → 进入 Review 队列，保留旧值

Step 4: 值质量检查
    ├─ 占位值过滤："未明确"/"详见来源文件" → 视为空
    ├─ 弱值检查："需核对具体条款" → 不生成冲突
    └─ 粗略值过滤：新值比旧值更粗略 → 忽略

Step 5: 保存增量原文
    └─ 单独保存为 "增量原文-{sourceStem}.md"，保留来源可追溯

Step 6: 级联更新
    ├─ 更新主产品汇总表格
    ├─ 刷新 Concept 聚合
    └─ 更新向量索引（后台异步）
```

#### 关键判断函数

**`isUsefulIncrementalFieldValue()`**：
```typescript
返回 true 的条件：
  1. 不是占位值（"未明确"/"详见来源文件" 等）
  2. 与字段类型兼容（如 QA 字段必须包含 Q&A 格式）
  3. 不比已有值更粗略（避免"1000万"覆盖"1000万保额"）
```

**`isLessSpecificThanExisting()`**：
```typescript
判断新值是否比旧值更粗略：
  旧值: "1000万保额，限至70岁"
  新值: "1000万"
  → 返回 true，忽略新值
```

---

### 10.4 删除源文件的完整处理链

#### 普通源文件删除

**调用入口**：`sources-view.tsx` → 删除按钮 → 二次确认

**处理流程**：

1. **删除原始源文件**（`raw/sources/...`）
2. **并发清理缓存**
   - 删除预处理缓存
   - 删除 Ingest Cache 中对应的条目
3. **查找关联 Wiki 页面**
   - 匹配策略：相对路径、文件名、Windows 中文路径变体
4. **逐个页面决策命运**（`decidePageFate()`，`source-delete-decision.ts`）
   ```typescript
   三种决策结果：
   1. DELETE：该来源是唯一来源 → 删除页面
   2. KEEP：还有其他来源 → 仅更新 sources 列表
   3. SKIP：sources 列表中本来就不包含该来源 → 不处理（防误杀）
   ```
5. **级联清理**
   - 删除 Wiki 页面（DELETE 决策）
   - 更新页面 frontmatter（KEEP 决策）
   - 清理 index.md 中的 wikilink
   - 刷新 Concept 聚合

#### 产品源文件删除（快路径优化）

**特殊逻辑**（针对 `raw/sources/产品/{险种}/{产品名}/`）：

```
场景 1: 删除单个产品源文件
  ├─ 识别产品上下文
  ├─ 扫描该产品的所有字段页
  ├─ 检查每个字段的 value_sources
  ├─ 只删除该文件独占支撑的字段值
  └─ 标记失去来源的字段为 needs_refinement

场景 2: 删除产品最后一个有效源文件
  ├─ 检测文件夹剩余内容
  ├─ 只保留 product_meta.json（不算有效源）
  ├─ 产品级清理：删除整个 wiki/product_catalog/{产品} 目录
  └─ 清理 wiki/source_text 中的相关原文

场景 3: 删除整个产品文件夹
  ├─ 递归删除源目录
  ├─ 批量清理缓存
  ├─ 产品级清派生 md
  └─ 统一跑一次 concept 聚合
```

#### UI 反馈优化

- **乐观更新**：删除成功后立即从 source tree 移除节点
- **清空预览**：右侧预览若选中已删除文件立即清空
- **进度状态**：删除按钮显示"删除中..."，不可重复点击
- **后台校准**：`loadSources()` 刷新仅作为校准，不阻塞用户操作

### 10.5 待完善的点

#### 高优先级

| 问题 | 现状 | 风险 |
|------|------|------|
| **缺少操作审计日志** | 删除/编辑操作没有记录 | 无法追溯谁在什么时候删了什么 |
| **缺少回收站机制** | 删除直接物理删除 | 误删无法恢复 |
| **向量索引一致性** | 删除页面后向量可能残留 | 搜索可能返回已删除页面的 phantom 结果 |
| **大批次删除性能** | 删除多个文件逐个处理 | 大量删除时可能卡顿 |

#### 中优先级

| 问题 | 现状 | 优化方向 |
|------|------|---------|
| **批量删除确认** | 每个文件需二次确认 | 支持批量删除的统一确认 |
| **删除预览** | 看不到影响范围 | 删除前预览"将删除 X 个页面，更新 Y 个页面" |
| **字段值来源粒度** | 只记录来源文件，不记录具体段落 | 无法精确知道某个值来自文档哪一部分 |
| **异步删除队列** | 删除同步执行 | 大批次删除改为后台队列 |

#### 低优先级

| 问题 | 现状 | 优化方向 |
|------|------|---------|
| **删除 undo** | 无 undo | 短期（5分钟内）支持撤销删除 |
| **自动归档** | 直接删除 | 旧版本自动归档到 .archive 目录 |
| **删除原因标签** | 无记录 | 支持选择删除原因（"误传"/"版本更新"/"不需要了"） |
