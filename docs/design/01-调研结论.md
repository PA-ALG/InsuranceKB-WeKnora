## 5. V5 抽取线（字段编译器迁入依据）

来源：`silvielala412-lab/InsuranceKB-WeKnora-ingest@codex/local-v5-preview`（自 B0 分叉，V5 代码约 1.7 万行在 `harness/src/insurance_harness/v5_preview/`）。

- **质量提升来源**：业务专家逐字段反馈（RESOLVED/PARTIAL/UNRESOLVED/NOT_SCORABLE）、字段组成要素检查、同产品多材料全页召回、Evidence 回原文、保守替换（不退化才替换）、执行完整性门禁。【B】
- **与主项目同源**：两边 Catalog 来自同一工作簿，154 个 field_key 与每类字段顺序完全一致。【A】
- **输入要求**：整页文本 + (文件, 页码)；回验先单页精确子串，再 NFKC 去空白。可由 WeKnora chunk 的 page_spans 按页重建，不能直接把重叠 chunk 当页。【A】
- **领域规则全部按 field_id 写死为 Python 常量**：关键词 55 字段、profile 9、组成要素 5、等待期 6 要素、字段指令 24；`value_constraints` 由 value_guidance 通用编译，可直接复用。【A】
- **引擎被试验编排缠住**：批次/分片/准入/替换在 `m158_run.run_m158` 闭包内，绑定基线文件与固定根目录；质量模块按 mission 命名逐层继承并跨模块引用私有函数。【A】
- **Provider 写死**：`qwen-plus`、`max_tokens=4096`（曾导致 1813 五个疾病字段整批截断）、model_family 仅 qwen/minimax。【A】
- **Evidence 松紧不一**：模糊匹配（锚点覆盖 ≥0.82）也记为 NORMALIZED_MATCH。【A】
- **语义冲突**：`absent_explicitly` 主项目要求 value 非空并带 Evidence（`knowledge_compiler/g3_field_tasks.py:218`），V5 要求 value=null。【A】
- **材料支持分母与召回用同一套关键词**，133/143 不是独立召回率；V5 文档自己也如此说明。【A】
- **同条件对比集**：596、594、1826、1824、1814、1816、1828 七款 PDF 与主项目 epoch9 语料字节一致；其中 596/1814/1816/1828 有专家反馈，1824 有回归集。【A】
- **可转 Golden 的资产**：30 条业务反馈（12 条可机器判定，18 条需专家补结构化期望）、31 项原文回归集。Golden 键须用 document_sha256 + 页码，避免换解析器后回归集静默失效。【A】

## 6. 私有化部署风险

1. 扫描件无本地带坐标 OCR；坐标证据只来自 MinerU Cloud（`internal/infrastructure/docparser/mineru_cloud_converter.go:34`），材料会出网。需自建 MinerU 或 PaddleOCR-VL 并解析 content_list。【A】
2. Office 格式缺原生 locator；若统一转 PDF 预览，soffice 转换的确定性未验证。【C】
3. LLM、VLM、embedding、rerank 均需内网部署；Harness 与 Go 中有硬编码外部端点与 Gemini 例外（`internal/types/concept_free_wiki_830_g3.go:1640` 等）。【A】
4. 签名 key ring 在私有环境需要 KMS/HSM 托管与轮换。【C】
