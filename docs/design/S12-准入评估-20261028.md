### 2.4 现有机器路由的门槛是否可靠

现有机器路由依据 DeepSeek 审核分数：所有有内容字段都 ≥ 门槛，才走机器通道。下表把 DeepSeek 审核分数与 GPT-6 评委结论逐字段对照。

- 共 232 个有内容的字段，数据来自 s5b4-first 的 `review/*/scores.json` 与 #384 的评委结论。
- 其中包括医疗险的 4 个补值点，它们不是整款评审的样本。
- 下表各行都是跨 pack 汇总，不是某一个 pack 自己的数字。例如重疾险 sc-8ff09af4ca 单独看，≥0.9 的字段为 15/26。

| DeepSeek 分数 | 字段数（覆盖比例） | 其中评委批准 |
|---|---|---|
| 全部 | 232（100%） | 145/232 = 0.625 |
| ≥ 0.5 | 223（96.1%） | 145/223 = 0.650 |
| ≥ 0.8 | 205（88.4%） | 136/205 = 0.663 |
| **≥ 0.9（原重疾门槛）** | 180（77.6%） | **122/180 = 0.678** |
| ≥ 0.95 | 140（60.3%） | 105/140 = 0.750 |

整体评委批准率是 0.625。在上述各个门槛下，评委批准率都**没有达到 95%**。这说明按现行 DeepSeek 审核分数设门槛，不足以支撑机器通道。这里不断言分数完全没有预测能力。

## 3. 提案

1. **目前没有完整的机器准入证据。** 有整款评委数据的 7 个 pack，有内容字段的评委批准率在 0.49–0.74 之间。这个结论只说明证据不足，不等于已经证明所有 pack 总体上都不合格：各 pack 的样本量都有限。
2. **重疾险的默认机器准入已经撤销**，见 #407，已合并。撤销的依据如下：
   - 1828 的段落召回在 5 款 Golden 中最低，v1 为 0.736，v2 为 0.727；
   - sc-8ff09af4ca 有内容字段的评委批准率为 0.53；
   - 原 0.9 门槛下，跨 pack 汇总的评委批准率为 0.678，见 §2.4。

   撤销之后，所有产品都走人工队列，由评委审核后经机器通道上线。这和本周的实际做法一致，线上行为不会退步。
3. **准入要求。** 逐 pack 判断，各项独立判断，互不推导。
   - **硬门槛，来自蓝图 §2.5，原样保留**。每个 pack 在 Golden 上用生产目标模型测得，必须同时满足：
     - 有材料字段 recall ≥ 90%；
     - present precision ≥ 95%；
     - 幻觉事实 = 0；
     - 已发布事实来源回跳 = 100%。

     本文**不修改**这些门槛。若要修改，需要另行做蓝图裁定。
   - **补充约束（本文提议）**。只在满足硬门槛的前提下额外要求，不能替代硬门槛：
     1. Golden 段落指标：S12a 规则下，段落召回 ≥ 0.85、精度 ≥ 0.90。段落选择指标与字段值指标不能互相替代。
     2. 整款评委：用当前编译器身份，至少评审 2 款产品，有内容字段的评委批准率 ≥ 0.90；unknown 中"材料其实有"的比例 ≤ 5%。
     3. 路由分数校准：机器通道使用的审核分数，在所选门槛下评委批准率 ≥ 0.95，且覆盖的字段 ≥ 50%。这一条只用于校准路由，不能替代 pack 的质量准入。

   可选的办法有两种，都需要用户决定阶段配置：
   - 换一个更强的审核模型，通过 OpenAI 兼容接口按阶段配置；
   - 继续由评委批量评审，再经机器通道上线。

   无论哪种，按硬边界 9，质量结论都只认生产目标模型。
4. **证据缺口**：
   - 医疗、意外医疗、定期寿险、年金、护理、专属商业养老这 6 个 pack 没有 Golden，无法对照 §2.5 的硬门槛评测；
   - 医疗险没有整款评委数据，594、596 只评过 4 个补值点。

   补齐办法：每个 pack 选 2 款在售产品，先做 GPT-6 整款评审，基本不需要 DeepSeek；再补评委标注的 Golden（参照 S4 / S12b 的文件交换流程），用来测 §2.5 的指标。
