## 3. 过程

沿用 S4h 的做法：每款产品一个独立评委会话，文件交换，Claude 审核。与 1828 时的差异：

- **分段**：用当前分段，也就是 `test_golden_data` 的读法：可信证据加上费率表表头段落（S4i/S4j）。
- **字段**：按所属 pack 的全部"原文抽取"字段，与编译器一致。字段卡使用 draft-2026-10-18a 的规则，不带样例。
- **提示词**：S4h 提示词改了两处：
  - 费率表表头只能作 `trust_policy.json` 所列字段（`premium_payment_term`）的证据；
  - 只说明"材料未提及"的值不算 present（2026-10-27 裁定）。
- **隔离**：
  - 会话可写范围只有本会话目录，`/tmp` 与 `$TMPDIR` 都不可写；
  - 可信请求副本及其摘要存放在会话目录以外；
  - 合并时要求会话里的请求与可信副本逐字节相同；
  - 引文一律从仓库分段复制，不取自会话；
  - 模型、推理强度、会话 ID 和沙箱策略从 Codex 会话记录读取，评委写不到这份记录。
- **确定性校验**：
  - 编号存在，区间顺序正确；
  - 状态与证据数、值一致；
  - 表头段落只用于允许的字段；
  - 值中的数字能在所选段落中找到；
  - present 值不能只是在说"未提及"。

  数字核对标出的都是假阳性：中文数字换成了阿拉伯数字（"十二次"→"12次"），或评委引用了值中自己的分项编号。

## 4. 审核结果

**审核修改**：全部集中在 `claim_application_deadline_and_documents` 一个字段，记录在运行目录的 `logs/edits.log`。

- 11 款里有 10 款，评委在这个字段的值里加了"客户申请保险金或诉讼时效：材料未载明"这样的分项。这类分项不陈述任何事实，按 2026-10-27 裁定删去，其余分项重新编号。
- 1815、1855 是附加险，其中一个分项写"适用主险合同条款"，后面还附带一段"本批材料未载明……"，只删去附带的这段。

**抽查**：Claude 抽查了 1830、594、2648 的交费期间、投保年龄、等待期、absent 与 unknown 字段，未发现错误；594 的"院外特药"absent 已与材料核对，材料中确实没有特药或药店责任。

**暂不入库：L3223（意外医疗）**

- 原因：来源仓库的错误。来源仓库中 L3223《平安意外（A款）医疗保险》目录下的 `产品说明书.pdf`，与 L3233《平安附加学生门诊急诊医疗保险》的说明书逐字节相同，是另一款产品的说明书。来源仓库里找不到 L3223 自己的说明书。
- 处理：Owner 裁定不随数据集发布这份说明书，以免对 L3223 的编译或评测把别的产品的说明书当作证据。但数据集要求每个产品都有条款和说明书（`test_material_roles`），这条约束不放宽。因此这次 L3223 整体不入库。
- 已有成果：L3223 的 Golden 已标好，只引用了条款，评委没有用这份说明书。Golden 与 manifest 条目保存在运行目录的 `out-of-repo/`。
- 线上影响：线上 sc-a27860e39d 的产品归属已把这份说明书隔离（原因：材料中找不到本产品的标识），它目前在待确认队列中，已发布的事实没有一条引用它。本次不动线上。

**暂不入库：2647（专属商业养老）、1855（护理附加险）**

- 原因：这两款的费率表（2647 是"转换标准表"）无法离线推断材料角色，返回 `MATERIAL_ROLE_UNRESOLVED`。线上编译靠 S5b-6 记录的角色解决这个问题。但数据集受 `test_material_roles` 约束，每个产品必须有且只有一个可识别的费率表，而这两款去掉费率表后就不满足。
- 目前做法：Golden 已按"条款 + 说明书"标好，与 manifest 条目一起保存在运行目录的 `out-of-repo/`。
- 其他候选：专属商业养老在售只有 2647，没有第二款可选；护理的另一候选 5011 同样有这个问题。

**下一切片（Owner 已定）**：数据集 manifest 记录已确认的材料角色，与 S5b-6 让线上编译以记录的角色为准一致。每个产品只有一个费率表的约束不放宽。之后补入：
