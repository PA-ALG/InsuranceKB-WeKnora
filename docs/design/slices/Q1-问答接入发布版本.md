# Q1 · 问答接入发布版本：原文检索与已发布知识两种来源，由选择的知识库决定

> 状态：用户 2026-10-19 批准（"同意方案B"；原文检索"更像一个开关……可选的"；"同意当前发布版本绑定的原始材料，明确区分「已发布知识（审核过）」和「原文检索（未经编译审核）」两类来源"）｜ 作者：Claude Code

> - Q1b 已发布知识的查询服务与 Agent 工具；

## 1. 背景与目标

**问题**：WeKnora 的问答（快问快答、Agent、IM、嵌入、MCP）都读不到企业 Space 的内容。

- S1b 后，快问快答对受管知识库返回 `RELEASE_MANAGED_KB`。
- Agent 会排除 Space 的原始材料库；对 Space 的 Wiki 库，只认识旧的 830 发布格式，选中时整轮报错。
- 发布只写 Release 成员，不写 chunk，原生检索也搜不到它们。

**用户决定（2026-10-19）**：

- 保留原来的 chunk 问答能力，做成可选的开关；
- 原文只检索当前发布版本固定的那批材料；
- 每个来源标明「已发布知识（审核过）」或「原文检索（未经编译审核）」。

**开关**：就是在问答里选了 Space 的哪个知识库。不新增配置项，API 调用方传不同的知识库 ID 即可。

| 选中 | 模式 | 本片之后 |
|---|---|---|
| 原始材料库 | 原文检索：与 WeKnora 原来的问答相同，只是范围限定在固定材料 | Q1a 提供 |
| Wiki 库 | 已发布知识：字段、概念及其出处 | Q1b 提供 |
| 两个都选 | 混合 | Q1b 之后可用 |

**硬边界修订**（随本 Spec 提交，记入 `AGENTS.md` 硬边界 5 与蓝图 §14）：

- 原始材料可以在问答中被检索并用于回答；
- 只限当前发布版本固定的材料，并标注"原文检索（未经编译审核）"；
- 不进入发布版本，不改变"已发布知识只来自 Release"的规则。

## 2. Q1a 设计

### 2.1 解析器（新包 `internal/enterprise/chatsource`，项目自有）

每轮问答开始时，把选中的检索目标解析一次，得到本轮的检索范围与固定的发布版本。接口冻结如下，验收测试依据它编写：

```go
type Role string // "raw" | "wiki"

type Spaces interface { // 由 releasestore 的 ENTERPRISE_SPACES 配置实现：知识库 → Space 与角色
	SpaceOf(tenantID uint64, kbID string) (spaceID string, role Role, ok bool)
}
type Heads interface { // 当前 Active；没有 Active 时返回空字符串、nil
	ActiveRelease(ctx context.Context, tenantID uint64, spaceID string) (string, error)
}
type Pin struct{ KnowledgeID string; ParseAttempt int64 }
type Pins interface { // 该版本在 enterprise_release_sources 中固定的材料
	ReleaseSources(ctx context.Context, tenantID uint64, spaceID, releaseID string) ([]Pin, error)
}
type Attempts interface { // 材料当前的解析轮次（knowledge.current_parse_attempt）
	CurrentAttempts(ctx context.Context, tenantID uint64, knowledgeIDs []string) (map[string]int64, error)
}

func NewResolver(spaces Spaces, heads Heads, pins Pins, attempts Attempts) *Resolver

type Turn struct {
	Targets      types.SearchTargets // 本轮实际检索的目标
	Releases     map[string]string   // spaceID → 本轮固定的 release_id
	WikiSpaces   []string            // 选中了 Wiki 库的 Space（Q1b 使用），按首次出现排序
	RawKnowledge map[string]string   // 可检索的固定材料 knowledgeID → spaceID，用于标注
}

func (r *Resolver) Resolve(ctx context.Context, tenantID uint64, targets types.SearchTargets) (Turn, error)
func (t Turn) Label(results []*types.SearchResult)
```

**规则**：

1. **不属于任何 Space 的目标**：原样保留，顺序不变。
2. **Space 的原始材料库目标**：替换为一个 `SearchTargetTypeKnowledge` 目标。
   - `KnowledgeIDs` 是本版本固定、且当前解析轮次等于固定轮次的材料。
   - 原目标本身是 knowledge 级时，再与原 `KnowledgeIDs` 求交集。
   - `TenantID`、`TagIDs`、`ScopeTagIDs`、`DisableRecallThresholds` 沿用原目标。
   - `KnowledgeIDs` 按字典序排序。
3. **当前解析轮次与固定轮次不同的材料**：不检索。这类材料的 chunk 已经不是固定的那一轮。
   - 一份可检索的材料都没有时，返回 `*release.Error{Code: "RELEASE_SOURCES_UNAVAILABLE"}`。
4. **Space 的 Wiki 库目标**：从 `Targets` 中去掉，Space 记入 `WikiSpaces`。
5. **固定版本**：
   - 选中原始材料库或 Wiki 库的 Space，都在 `Releases` 中固定当前 Active；
   - 同一个 Space 在一轮中只读一次 Active，两个库都选时共用同一个 release_id。
   - Space 没有 Active 时，返回 `*release.Error{Code: "RELEASE_NOT_FOUND"}`。
6. **失败关闭**：`Heads`、`Pins`、`Attempts` 任一出错，原样返回错误，不降级为全库检索。
7. **`Label`**：只标注本轮可检索的固定材料的结果。
   - `KnowledgeID` 在 `RawKnowledge` 中的结果，`Metadata` 写入 `source_tier = "raw_text"` 与 `release_id`；
   - `Metadata` 为 nil 时新建；
   - 其他结果不改。

### 2.2 接入（实现方的测试覆盖）

- **快问快答**（`session_knowledge_qa.go` 现有接缝 :73、:853）：
  - 原来对受管库一律拒绝，改为：Space 原始材料库经 `Resolver` 改写目标后照常检索，检索结果经 `Label` 标注。
  - 只选了 Wiki 库：Q1b 之前仍返回 `RELEASE_MANAGED_KB`，提示"已发布知识问答即将提供，请先选择原始材料库"。
  - 未受管的知识库，行为完全不变。
- **Agent**（`agent_service.go` 现有接缝）：
  - Space 原始材料库按改写后的目标参与 `search_knowledge`，计入 `hasVectorKB`，结果同样标注。
  - Space 的 Wiki 库不再交给 830 投影，避免整轮失败。Q1b 之前不注册它的工具，并在系统提示中说明"已发布知识尚不可用"。
- **固定版本**：同一轮内所有检索都用 `Turn.Releases` 中的版本。多轮之间是否沿用，按用户 2026-10-19 的意见暂不处理。
- **MCP**：本片不改，Q1c 处理。
- **新增读取接口**：在 `releasestore` 增加按版本列出固定材料的读取函数，以及按知识库反查 Space 与角色。

### 2.4 实现口径（2026-10-19 按 #244 计划 1–6 确认）

1. **注入**：
   - 允许最小修改 `internal/application/service/session.go`：在 `sessionService` 的字段与构造器中注入 `Resolver`，并测试调用点；
   - Agent 在 `agent_service.go` 内注入；
   - 不用全局变量，不每轮新建连接。
2. **范围与授权**：
   - `Resolver` 只改写**已识别的企业 Space** 目标，并且在原有授权（`buildSearchTargets` 的 ACL、共享、tag 解析）之后执行，不替代 ACL；
   - 其他受管库仍走原 `managed` 检查，失败关闭；
   - 企业目标只支持当前执行租户，目标的 `TenantID` 不是本租户时返回 `RELEASE_ACCESS_DENIED`；普通共享 KB 行为不变；
   - 只选原始材料库时，不要求用户另有 Wiki 库权限：读取 Active 是平台内部行为；
   - 配置歧义（同一知识库出现在多个 Space 或多个角色）在加载 `ENTERPRISE_SPACES` 时报错，不能在运行时因 `ok=false` 被当作普通库放行；
   - 明确选中的企业目标解析不完整时，整轮失败，不静默少搜。
3. **解析轮次的保证强度**：每次检索结果交付前，都按 chunk 的 `parse_attempt` 过滤，剔除与本轮固定轮次不一致的结果。
   - 适用于快问快答，以及 Agent 每次调用 `search_knowledge`；
   - `Turn` 可以增加只读字段 `RawAttempts map[knowledgeID]int64`，供过滤使用（RED 不受影响）；
   - 查询 chunk 的轮次复用现有 chunk 仓储；
   - 不加迁移，不开长事务，不改来源的写入生命周期；
   - 同一轮中 Head 前进时，仍读本轮固定的旧 `release_id`。
4. **Agent 工具**：
   - 企业原始材料库在 Q1a 只开放 `search_knowledge`（含 keyword 模式），结果经轮次过滤与标注；
   - `read_document`、`list_documents`、`query_knowledge_graph`、`database_query`、`data_analysis` 对企业目标不开放；普通目标保持原工具；
   - 标注在项目包的**每轮工具结果包装器**中完成，不改 `internal/agent/tools/search_knowledge.go`；
   - 允许修改 `frontend/src/components/AgentStreamDisplay.vue`（上游），让工具结果重建引用时保留 `metadata`。
5. **浮层**：
   - 允许最小修改 `frontend/src/composables/useCitationPopover.ts` 与 `frontend/src/components/ChatCitationFloat.vue`，增加来源标签位；嵌入页行为不变；
   - 来源只取服务端引用的 `metadata`，不信任模型在引用标记中的自报内容；
   - 分组时保留 tier 与 release，不把不同来源合并为同一来源。
6. **错误语义**：
   - 任一明确选中的企业原始材料库收窄后为空，整轮返回 `RELEASE_SOURCES_UNAVAILABLE`，不去掉该目标只答其他库，不生成空 `KnowledgeIDs` 的整库目标；
   - 同一版本中同一材料出现冲突轮次时，该材料不可检索；
   - 检索时发现固定版本已退役或材料已改轮次：由第 3 条的过滤剔除结果，不报错；
   - 无 Active：`RELEASE_NOT_FOUND`；依赖出错原样传播；
   - 只选 Wiki 库的快问快答：仍返回 `RELEASE_MANAGED_KB`，在入口提供提示"已发布知识问答即将提供，请先选择原始材料库"，可以在 `session_knowledge_qa.go` 的入口适配，不改公共错误映射；
   - 原始材料库 + Wiki 库：只查原始材料库。Agent 在提示中说明"已发布知识尚不可用"，不因 830 失败整轮报错。
7. **PostgreSQL 测试**：`releasestore` 新读取函数的 PostgreSQL 测试接入现有 Enterprise PostgreSQL CI，以 CI 结果为证据；本地没有测试库时如实写"未在本地运行"。

## 6. Q1b、Q1c 概要（各自另写 Spec）

- **Q1b**：
  - `internal/enterprise/knowledge` 查询服务，提供四项能力：按名称、别名或编号找产品；取字段值及出处；搜字段内容（规则同 S3h-1）；取概念说明。
  - 作为 Agent 工具注册，按 `Turn.Releases` 固定版本。
  - 快问快答增加一个检索插件，把命中的字段作为"已发布知识（审核过）"的引用；点开时按版本打开出处。
- **Q1c**：同一组能力的 MCP 工具，供外部 Agent 使用。
