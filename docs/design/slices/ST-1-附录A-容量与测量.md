## 2. r2统一情景与分块预算（M1/M2）

本节**从空集引导到P款**，用于同夹具新旧机制比较，不是从#547已存在29款增量外推；
旧r1逐成员引用表公式/数值废止，不沿用其512–1024 B/引用预算。
真实历史唯一内容 `U0`、历史块布局/根数和其他业务增量另计，当前未知。

| 符号 | 冻结情景/计量口径 |
|---|---|
| P、K、N | P=60/150/300；每款K=125成员；最终N=125P；普通slug分组，不按业务ID切块 |
| 激活 | 引导每款一次；后续每轮恰10%产品各一次，全部125成员改成新完整身份；无额外无变化激活 |
| 内容宽度C | 每个新完整对象逻辑列合计5120 B=5 KiB，含七字段与对象元数据；统一合成尺寸，不读私有正文 |
| 块长 | 最小32、最大128；仅全局末块可不足32；自然hash概率1/64，均匀假设下修尾前期望81.1083项 |
| 块条目/块头 | 每项32 B二进制digest；块头及该行其他逻辑列预算128 B，不含refs；无逐成员行 |
| 根 | 根头及该行其他逻辑列128 B；块列表每项36 B（count4+digest32） |
| 映射/控制 | 每次激活两个映射及其元数据合计512 B；每scope控制元数据4096 B；scope不在每项重复 |
| 余量F | 统一1.25，分别乘内容和结构；不是实测索引/TOAST/WAL放大率 |

这些列预算须由未来真实schema/固定宽度合成身份逐列计数验证，超预算即失败/修订，不能漏算
digest、ID、版本、四段scope映射列。PG元组头/页、索引、TOAST/WAL不含在逻辑预算中，单列实测。
平均81.11只说明目标64–128的选择；表格采用最小块长的**保守上界**，不假设实际输入随机。

主Spec局部窗口算法，单段增量K的保守界为：

```text
B(n) = floor(n/32)+1                         # 根的块数上界，包含短尾余量
Wa = K+4×128 = 637；Qa = floor(Wa/32)+1 = 20
Da = Wa×32 + Qa×128 = 22944 B               # 每款添加的新块字节上界
Wm = K+2×(128−1) = 379；Qm = ceil(K/32)+2 = 6
Dm = Wm×32 + Qm×128 = 12896 B               # 连续125键换值的新块字节上界
R(n) = 128+512+36×B(n)                      # 根+两个映射，每次激活一份
```

Wa包含相交块/左右完整邻块及修尾余量；Wm只换值、保留边界。全部按新写计，实际可因共享更少。
多个分离修改区间J另用主Spec `K+4J×128` / `K+2J×127`，不套单段成本；散布K个换值键最多
K个块、K×128条目。无自然切点/最小最大强制边界也只局部重切，不向全表移位。
不同历史的同逻辑集合允许不同内部布局，根不充当业务身份；每个根自足，读时无父链依赖。

## 3. 60/150/300款与多轮增长复算（M2）

设q=0.1P（本表各P均整除），k为后续轮数；每轮q次激活，10%产品/10%成员产生新身份。
这里不是“每款都激活但只改10%成员”；额外逐点批次、页面变化、无变化激活均须另加真实根/映射。

```text
Content(P,k)   = (P+kq)×K×C
Structure(P,k) = 4096 + Σ(i=1..P)[Da+R(Ki)] + kq×[Dm+R(KP)]
OldProxy(P,k)  = 2×K×C×P(P+1)/2 + kq×2×KP×C
表中GiB        = F×对应逻辑字节 / 2^30
```

以上新合计只计本片内容对象和集合结构，**不是整个新数据库**。按原合同保留的完整 manifest、
候选 raw_bundle、决定、receipt、Source pin 等共同项另记 `Audit(P,k)`；其中 manifest 的逐成员清单
仍随历史成员出现次数增长，不因为新块共享就消失。新旧全库逻辑比较分别加上同一 Audit 项，
再单列各自索引/元组/TOAST/WAL及备份物理开销。该共同项及线上物理大小尚未测，列入§5迁移前测量；
不能拿表中新合计或结构占比直接预测全库/VM释放空间。合成PG的实际资源采样包含这些保留项。

OldProxy近似每次完整成员+完整准备两份；不是旧真实JSON转义/数组/列宽或物理实测。
未来同夹具计数器需按旧原序列化逐对象长度、数组标点/转义和行列元数据加权，报告真实旧逻辑
字节对照；无需为对照实际存数百GiB旧重复DB。F同乘，不能只给新格式加/减不同余量。

| P | k | 总激活数 | 新内容GiB | 集合结构上界GiB | 新成员存储合计GiB | 旧两份近似GiB | 结构/内容 |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 60 | 0 | 60 | 0.0447 | 0.0020 | 0.0467 | 2.7269 | 4.37% |
| 150 | 0 | 150 | 0.1118 | 0.0060 | 0.1177 | 16.8756 | 5.35% |
| 300 | 0 | 300 | 0.2235 | 0.0156 | 0.2392 | 67.2787 | 7.00% |
| 300 | 3 | 390 | 0.2906 | 0.0215 | 0.3121 | 107.5119 | 7.39% |
| 300 | 10 | 600 | 0.4470 | 0.0351 | 0.4821 | 201.3892 | 7.85% |

例如P=300,k=10：内容384,000,000 B；结构上界30,152,452 B，未乘F之比7.8522%，低于10%。
这是算术上界，不是已通过codec/PG实测的RED。小对象、散布变化或更多激活可能超过10%；
不能外推为任意负载保证。总结构仍含每个根的完整块列表，即 `O(集合数×N/块长)`，并非完全O(delta)。

## 4. 未来RED的定量失败标准（本轮只描述）

1. **固定改动、隔离远处规模**：N≈3600/37500，独立同宽合成scope；大集合通过正常追加在编辑
   邻域外增长，保留同一修改邻域与外侧完整保护块，不伪造特定hash切点。同改连续125键、同七字段，
   新内容对象数125且内容/被重写块字节必须相等；根列表差额≤36×B(37500)=**42192 B**。
   根头/映射宽度一致；不允许把N个引用重复制成块blob。该对照不等价任意散布125键；另锁散布上界。
2. **长历史结构预算**：按§3的300款+10轮600次激活，所有唯一块/根、scope及两映射的**全部逻辑
   列字节**≤内容对象10%；原始计数与F分开记录。每次prepare/Release只共享一个根。旧格式同夹具
   计数器给出现次数/实际字节；不以近似OldProxy替代正式对照，不以物理压缩掩盖结构超标。
3. **历史冷读**：全部600个Release以及历史准备异序/空kind控制，冷应用缓存还原完整七字段和
   原顺序，逐字节对旧格式真值；缺块/缺对象/错scope/hash失败。流式逐版本核，不靠全历史热缓存。
4. **Active全读基准**：隔离合成PG、相同硬件/schema/连接池，N≈3600/37500，冻结旧适配器和新
   生产Read链交替ABBA共30次；每次清应用/对象缓存，两侧DB预热状态一致，记录SQL数/读取字节及
   wall-clock p50/p95。查询数、p50和p95均≤旧2倍；任一超过即失败，不推迟到上线后豁免。

主Spec另有完整性、插删/32/128/短尾、迁移/回滚、并发/CAS和受管读取保护矩阵；新性能标准不
覆盖或放宽它们。本轮只复核公式和文档，不写chunker/测试、不跑产品测试或基准。
