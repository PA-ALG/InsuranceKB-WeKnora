# S6a-2 · 候选窗口溢出拆分：候选列表超出输出上限时，把该窗口对半拆开重读

> 状态：Claude 2026-10-20 提出（S6c 试点中 2650 条款两次处理失败，#253）｜ 作者：Claude Code
> 依据：S6a（#230）分窗机制、蓝图硬边界 3（上游补丁登记）、AGENTS 首要原则与核心工程原则 5
> 实现方：Codex（Go，已登记的上游文件）｜ 审核方：Claude ｜ 实现阶段真实模型调用：0

## 1. 问题（S6c 试点，日志核对，未额外调用模型）

- 2650（平安e生保（悦享版）医疗保险）条款约 6.2 万字。S6a 把它分成两个窗口：32,596 字与 29,485 字，约 2.0 万 token 输入。
- 详尽粒度下，候选列表的输出约为输入的 1.2～1.6 倍：
  - 说明书 13,878 → 17,024；
  - 条款第二窗 20,330 → 26,576（第一次），第二次到 32,768 被截断；
  - 条款第一窗两次都到 32,768 被截断。
- 两轮都按 S6a 的规则在候选阶段失败，条款没有进入原生 Wiki；1828、1824 没有触发。
- 不是模型循环：同一窗口两次输出量接近，说明书的比例与条款一致。根因是窗口只按**输入**字数装箱，而候选输出量随内容密度增长，密集材料在 2 万 token 输入下就会超过 32,768 的输出上限。

## 2. 设计（通用机制，不按文档或产品特判）

1. **溢出才拆**：
   - 候选调用返回 `errWikiOutputTruncated`（S6a 的截断失败，已发送、结果已知），且该窗口不止一个 chunk 时，把这个窗口按 chunk 顺序拆成前后两半，两半各自重新调用候选。
   - 两半按重建后字符数尽量平分，每半至少一个 chunk；内容用 S6a 窗口的同一套重建与富化逻辑生成（富化信息仍只读一次）。
   - 拆开的一半仍被截断，就再拆一次。**拆分深度上限为 2**：一个窗口最多变成 4 份，最多 1 + 2 + 4 = 7 次候选调用。
   - 到上限仍截断，或者只有一个 chunk 的窗口被截断，按 S6a 规则让候选阶段失败（FAILED，包装 `errWikiOutputTruncated`）。
2. **只对已知的截断拆分**：
   - 发送结果未知（UNKNOWN）、未发送（NOT_RUN）、空答案、解析失败，都不拆，也不重发，沿用现有分类。
   - 拆分产生的调用由候选阶段自己负责，传输层不重试；日志写明原窗口序号、深度与两半的 chunk 数，不含模型正文。
3. **拆分后的窗口贯穿后续步骤**：
   - 拆开的两半替换原窗口，保持文档顺序；后续引用批次、`<candidate_slugs>` 的按窗口归属都用拆分后的窗口。
   - 每份窗口只列出自己找到的候选（S6a C3/C4 规则不变）。
   - 合并顺序按拆分后的窗口顺序，"同一 slug 首次出现为准"的规则不变。
4. **并发**：拆开的两半在原窗口的任务里依次处理，每文档最多 4 并发的规则不变，并发数不随拆分增加；不在池内等待池中的其他任务（避免死锁）。一份失败不取消已发出的其他调用，全部收齐后再判定。
5. **不改的东西**：窗口初始大小、粒度、提示词、输出 token 上限、引用批次大小、页面改写续写、摘要与撤回用第一个原始窗口。

**为什么不直接把窗口改小**：所有长文档的候选调用都会变多，而只有密集材料才需要。溢出才拆只对溢出的窗口多付一次被截断的调用（约 3.3 万输出 token）。

**为什么不续写 JSON**：上游注释已说明候选 JSON 续写不可靠；拆分得到的是两份完整答案。

## 4. 验收（RED：`internal/application/service/wiki_ingest_window_split_test.go`，Claude 编写，受保护）

测试沿用 S6a 的 90 个 chunk、约 5.4 万字文档（初始两个窗口，约 54 与 36 个 chunk）。模型替身：窗口超过给定 chunk 数时返回 `finish_reason=length`。

1. 每份最多 30 个 chunk：两个窗口各溢出一次，拆成 4 份都得到答案；每个 chunk 恰好被一份答到，且每份是文档中连续的一段；候选阶段不失败。
2. 引用批次只列出读到它那些 chunk 的那一份的候选，每个 chunk 都进入某个引用批次。
3. 每次都溢出：候选阶段以 FAILED + `errWikiOutputTruncated` 失败，候选调用 2～14 次（深度上限 2），之后没有引用调用。
4. 只有一个 chunk 的窗口溢出：只调用 1 次，以截断失败。
5. 发送结果未知：每个窗口只发 1 次，不拆不重发，候选阶段为 UNKNOWN。
6. 实现方另补：S6a 的 `wiki_ingest_longdoc_test.go` 与现有窗口测试全部保持通过；拆分日志字段；不平分的 chunk 长度下两半的字符数尽量接近。
