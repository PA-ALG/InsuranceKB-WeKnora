## 1. 目标

第二步（写值）改成 #390 的 B1 协议：
- 先判断每个段落里有没有本字段的内容；
- 同一段落里属于其他字段的内容不写进 value；
- 给定段落里根本没有本字段的内容时，答 `unknown`，不再用"材料未提及"之类的句子充当值。

字段卡、Golden、评分口径都不改。

## 2. 第二步的回答格式

每个值行：

| 键 | 说明 |
|---|---|
| `ordinal`、`field_key` | 与原格式相同 |
| `state` | `present` 或 `unknown`；省略时按 `present` 处理，旧的录制回答照常能解析 |
| `value` | `present` 时必须是非空字符串；`unknown` 时不得出现 |
| `used_segments` | 可选，字符串数组，只供模型自查。平台不把它当证据，也不检查内容 |

`parse_values` 返回 field_key → 值；字段答 unknown 时，值为 `None`。

解析仍然严格：键重复、多出未知的键、状态与 value 不一致、行号或字段对不上，都会让整批作废。漏掉某个字段的行，只是这个字段没有值（与原来相同）。

## 3. 引擎

- 第二步答 `unknown` 的字段，输出为 `FieldResult(field_key, state="unknown")`，与第一步答 unknown 的结果完全相同：没有值、没有证据、没有段落编号。它不算作丢弃的字段。
- `present` 字段的证据和段落编号仍是第一步的选段；`normalize_field_value` 只作用于 `present` 的值。
- 两步的调用次数与预算都不变。

## 4. 版本与复用

- 在 `prompt.py` 中定义 `VALUE_PROTOCOL_VERSION = "2026-10-27.1"`。
- `CompileOutput` 新增 `value_protocol: str | None`，编译时写入当前版本；旧输出读进来是 `None`。
- 新增 `engine.reusable(output, materials) -> bool`：材料、`cards_version`、`value_protocol` 三者都与当前一致时才返回真。`eval/compile_run.py` 和 `ingest/publication.py` 原来各写了一份复用条件，都改为调用这个函数。旧协议的输出因此会重新编译。

## 5. 回归集

PR #366 中 Codex 给出的反例（"材料未提及收费且明确免费提供健康咨询。""条款未约定的事项按保险法执行。"等），也就是原文里本来就混着事实的句子，作为 `present` 值原样保留。新协议不对文字做确定性删除；只有模型自己答 `unknown` 时，字段才是 unknown。

## 7. 验收（RED，Claude 编写）

1. `tests/compilers/schema_fields/test_value_protocol.py`，全部使用离线假回答：
   - 第二步答 unknown 时，结果与第一步 unknown 的形状相同；同批其他字段的值和第一步证据都不受影响；
   - 格式校验：unknown 带了 value、present 没有 value、未知的键、重复的行，都会作废整批；省略 `state` 的旧格式照常解析；`used_segments` 不会进入证据；
   - 回归集（§5）原样保留为 `present`；
   - 输出记录当前协议版本；没有该键的旧输出读进来为 `None`；
   - `reusable` 三项条件各自生效；
   - 第二步请求的说明里允许 unknown 并规定了它的格式（通过 `build_value_request` 检查）。
