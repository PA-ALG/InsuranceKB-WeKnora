# S12c-12c RV7 两次独立评审

冻结；Refs #552 第3部分。实现 Codex、审核 Claude。仅离线工程，不消费本 Issue 模型预算。
基于已合并 S12c-12a 的同源字段卡；不依赖第2部分、不解除所有 pack 暂停。

## 1. 输入与两轮

新 prepare 标记 `review_protocol=dual-v1`；第一轮保留原题/判定标准。只有第一轮
通过严格 ingest 的 approve 点可进入 `second` 子目录。`second` 命令仅做本地计划，
不调用模型/平台；按原会话分组取通过子集，空组不创建。第二轮只给待发布值及证据、
字段定义/卡片/规则、同源角色及完整材料；不提供第一轮答复、理由、线上旧值。
沿用原 system/AGENTS 判定文本（不降低标准、不另写提示词）；第一轮承担新旧比较，
第二轮对所给候选事实独立核全文。变化类型仅留父计划，不成为第二轮输入。

第二轮题目由第一轮冻结题目投影产生，使用原始完整全文副本；父 plan/manifest、
全部变化点与第一轮请求/成功回答/会话身份摘要构成 parent_binding。二轮只投影已批准
字段，内容/字段/来源不能重新选取。已有 second 仅在全部绑定一致时幂等返回，否则拒绝。
两轮严格全覆盖/顺序/type/枚举校验；部分或无效第二结果不能上线。

## 2. 会话执行与可信回执

run.sh 调用受管执行器，不直接把用户填的 session 名当独立性证明。每次执行创建新的
attempt 工作目录，只拷冻结题目/全文/AGENTS/run，不拷旧回答。调用必须是全新
`codex exec --json`，不 resume/fork；模型与 xhigh 固定来自计划。执行前以完全相同
sandbox 参数实测自身可写、run/data/sessions/attempts 控制目录不可写；失败零模型。
去除附加 writable roots、TMPDIR、/tmp 默认写根的既有边界保留。

受信控制目录保存：先 durable pending（attempt/输入摘要/model）→实际发送→退出码及
JSON 事件→完成回执。一次启动算一次预算，不根据HTTP/token猜成本；默认预算为首轮
会话数的两倍，可在 prepare 明确给更大已授权上限（不产生预算授权）。两轮共享账本
与排他锁。失败重试也计数，只有已知失败才能显式 retry，使用新目录和新会话；结果
未知先从原事件/退出记录对账，无法证明终态则保持 pending 并拒绝补发。成功再次执行
零发送；不中途覆盖原答案/事件。

成功必须有恰一个真实 thread.started 的 thread_id、成功 turn.completed 和零退出码，
输入文件与根 manifest 一致、回答覆盖与摘要完整。回执绑定 root plan/manifest、session、
request bytes/hash、response bytes SHA、model、thread id；ingest 及任何 publish/close
之前重验，不能只检查存在。两轮所有有效 session thread_id 必须互异，第二轮不接受
同线程下一轮或手工生成 UUID。实现测试用合成事件/假子进程，绝不执行真实评委。
信任执行器本地控制目录/操作者；不是把可手工改写的本地文件宣称远程密码学证明。

## 3. 合成与发布

只有两轮 approve 交集进入 publish；任一 reject 留原 Active，记录本地机器拒绝改进
清单，标明来源轮次。没有第二结果的 approve 是 blocked，不能冒充 reject 或 approve。
最终清单/summary 作为一套带输入与文件摘要的完成回执；读取时验证，部分写入不成立。
publish 恢复、完成重跑、close 同样先核双评绑定，不以旧 publish receipt 绕过。
保持原来源/卡片/内容/当前 Active 复核、逐产品幂等发布记录与确定性检查。

保留原激活后10%平台抽检任务，由第三个独立会话处理；本片不把第二评算成上线后抽检，
也不启动第三评。pack 暂停与运维授权保持独立，合并不授权上线。两轮评委约原预算两倍，
失败尝试另计，不能因通过双评宣称模型整体质量或 pack 准入。

## 4. 兼容、写域与验收

旧无 dual-v1/无可信执行回执的单评目录可保留只读历史，但不能经新 publish/close 当成
双评目录。需要重新 prepare/两轮执行，不能补造回执或复用无法验证的旧会话。代码不
自动迁移/补调用。新增 second/execute/reconcile CLI 只在操作者明确调用才执行相应步骤。

写域仅 ingest/judge_batch（执行/两轮绑定模块、sessions/verdicts/publishing/closing/cli/
launch/manifest 的接线）及相应合成测试。prompt.json、字段卡、编译协议、平台/合同、
准入策略、抽检策略与守卫基线均不改。单文件≤500，不增加依赖。

Spec 独立提交→RED独立提交推送（证明单评可发布旧漏洞、同线程/缺第二/篡改等拒绝缺失）
