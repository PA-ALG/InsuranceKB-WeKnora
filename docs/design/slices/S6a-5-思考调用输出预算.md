# S6a-5 · 思考调用的输出预算：候选与引用调用按模型能力用 65,536，拆分多一层，记录传输错误类别

> 依据：#266 条款重跑与思考模式消融（评论 6300447580、6310201304）
> 实现方：Codex（Go，已登记的上游文件）｜ 审核方：Claude ｜ 实现阶段真实模型调用：0

## 1. 问题（日志核对）

- 本机 `deepseek-v4-flash` 模型行带有旧设置 `thinking_control: none`，Wiki 的 `Thinking=false` 发不出去，DeepSeek 默认开启思考。思考 token 计入 `max_tokens`。
- 2650 条款：候选调用的输入为 6–11k token，输出却有 16k–32,768 token。12 次调用中 7 次在 32,768 被截断；拆到第 2 层（约 30 个 chunk）仍然截断，条款没有页面。
- 消融（594 条款）：关掉思考后，引用明显变少（308 页中 22 页没有任何引用），等待期、犹豫期等核心页面按常识写错。**用户决定保持开思考**，这一行设置不改。
- 因此要给开思考的候选/引用调用足够的输出空间。DeepSeek 文档写明思考模式的默认输出上限是 64K（`internal/models/providers/deepseek.go` 注释），目录记录该模型最大输出为 384K。
- 596 条款：引用阶段 5 次失败，类别都是 `transport error`（结果未知），日志里没有具体原因，无法判断是超时、HTTP 错误还是连接断开。

## 2. 设计

### 2.1 输出预算按模型能力取值

- `internal/models/chat` 提供可选接口 `OutputLimited { MaxOutputTokens() int }` 与函数 `MaxOutputTokens(c Chat) int`：
  - 函数返回模型已知的最大输出 token 数（远程模型取目录解析结果 `Spec.MaxOutputTokens`）；
  - 模型没实现该接口或不知道时返回 0；
  - 必须穿过 `NewChat` 的三层包装（debug、langfuse、并发），各层转发内层的值。
- Wiki 的 `wiki_candidate_slug` 与 `wiki_chunk_citation` 两类调用：
  - 模型已知最大输出 ≥ 65,536 时，`MaxTokens = 65536`；
  - 否则仍为 32,768。
- 其他 Wiki 调用（摘要、去重、页面修改、分类等）不变，仍为 32,768。
- 不改模型行、不改思考设置，也不加按 KB 的配置项。

### 2.2 拆分多一层

- `maxCandidateSplitDepth` 与 `maxCitationSplitDepth` 从 2 改为 3：一个窗口或批次最多 8 份，最多 1 + 2 + 4 + 8 = 15 次调用。
- 其余规则不变：
  - 只在已知截断（FAILED + `errWikiOutputTruncated`）时拆；
  - 结果未知、未发送、解析失败都不拆也不重发；
  - 单 chunk 不拆。

### 2.3 传输错误写明类别

- 新增 `wikiTransportDetail(err error) string`，只返回固定类别，不带任何错误正文：
  - `http <状态码>`：错误链中有 `*api.HTTPError`；**不写 Body**，因为 Body 可能回显请求内容；
  - `timeout`：错误链中有 `net.Error` 且 `Timeout()` 为真；
  - `connection closed`：错误链中有 `io.EOF`、`io.ErrUnexpectedEOF`、`syscall.ECONNRESET` 或 `syscall.EPIPE`；
  - `other`：其他情况。
- `runWikiRequest` 的失败警告在类别为 `transport error` 时追加 `detail=<类别>`，其他类别的日志格式不变。

## 4. 验收（RED，Claude 编写，受保护）

`internal/application/service/wiki_ingest_budget_test.go`（新）：

1. 模型报告最大输出 384,000：候选与引用调用的 `MaxTokens` 都是 65,536；文档摘要等其他调用仍是 32,768。
2. 模型报告 0、报告 40,000，或根本不报告：所有 Wiki 调用都是 32,768。
3. 拆到第 3 层才能装下（每次最多 4 个 chunk）：引用批次全部得到答案，每个 chunk 恰好在一份中，引用阶段不失败。
4. 拆到第 3 层才能装下（每次最多 8 个 chunk）：候选窗口全部得到答案，每个 chunk 恰好读一次。
5. `wikiTransportDetail`：
   - HTTP 503（Body 带标记文本）→ `http 503`，结果里不含标记文本；
   - 超时的 `net.Error` → `timeout`；
   - `io.ErrUnexpectedEOF`、`ECONNRESET` → `connection closed`；
   - 其他 → `other`；
   - 以上各类被 `fmt.Errorf("%w")` 包一层后结果不变。

`internal/models/chat/max_output_test.go`（新）：

6. `NewChat` 构造的远程 `deepseek` / `deepseek-v4-flash` 模型（带 `thinking_control: none`，与本机一致）：`MaxOutputTokens` ≥ 65,536。
7. 未在目录中的 generic 模型：`MaxOutputTokens` 为 0。
