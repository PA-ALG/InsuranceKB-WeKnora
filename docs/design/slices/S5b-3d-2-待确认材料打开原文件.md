## 1. 目标

管理员在待确认页上点"打开原文件"，就能在新标签页里看到这份材料的原始文件，并且平台保证打开的正是提问时那一版文件。

平台不解析 Harness 的 `subject`（例如 `material:<id>`）。待确认项改为由提交方显式附带一个**通用的来源引用**，平台只认这个引用。

## 2. 平台（Go）

### 2.1 待确认项增加可选的 `source_ref`

- `confirm.ItemInput` 与 `confirm.Item` 增加 `SourceRef string`，JSON 字段为 `source_ref`，没有时省略（`omitempty`）。
- 提交接口 `POST /confirmations` 的严格解码键加上 `source_ref`。值为空表示没有来源；非空时必须能被 `release.ParseSourceRef` 解析，否则整批返回 400 `CONFIRMATION_INVALID`，什么也不写。
- **内容指纹**：`contentDigest` 的规范 JSON 增加 `"source_ref,omitempty"`。不带来源的项，指纹与现在逐字节相同，已有记录的身份不变；带来源的项是新的内容，所以同一 subject 与 revision 下会另存一条（Harness 按 S5b-3d-1 的做法把旧项关为 obsolete 后重提）。
- **存储**：迁移 000012 给 `enterprise_confirmations` 增加 `source_ref TEXT NOT NULL DEFAULT ''`。`InsertItems`、`ListItems`、`ItemByID` 都要读写这一列。down 迁移删除这一列；`packagedEnterpriseMigrationHead` 改为 12。

### 2.2 会话路由：打开待确认项的原文件

`GET /api/v1/enterprise/spaces/:space_id/view/confirmations/:confirmation_id/file`

- **挂载位置**：挂在 `MountSessionConfirmations` 中，与提交答复共用管理员守卫。处理函数内再次检查调用者角色是否为管理员（同 `answerConfirmation`），检查先于任何存储读取。服务密钥与非管理员返回 403 `RELEASE_ACCESS_DENIED`；其他租户或不存在的 Space 返回 404，规则同现有会话路由。
- **处理步骤**：
  1. 在本租户、本 Space 中按 id 读取待确认项，读不到返回 404 `CONFIRMATION_NOT_FOUND`。已关闭的项也可以打开。
  2. 项上没有 `source_ref` 时返回 404 `SOURCE_NOT_FOUND`。
  3. 请求头 `If-None-Match` 等于 `"<file_sha256>"` 时直接返回 304，不打开文件。
  4. 用 `SourceFiles(ctx, {tenant, space}, knowledge_id)` 打开文件。文件不存在、不在本 Space 的 RAW KB 中、或已删除，都返回 404 `SOURCE_NOT_FOUND`。`Files` 未配置时返回 503 `SOURCE_UNAVAILABLE`。
  5. 最多读取 `maxSourceFile` 字节，并计算 sha256。超长或指纹与引用不一致时返回 409 `SOURCE_INTEGRITY`，不输出内容。请求被取消时立即关闭文件，与 `citedFile` 相同。
- **成功响应**：
  - 状态 200，响应体是文件原样字节；
  - `ETag: "<file_sha256>"`；
  - `Cache-Control: private, no-cache`：每次都必须回到服务器做权限检查，再靠 304 复用，不允许浏览器在不请求服务器的情况下直接使用缓存；
  - 内容以 `%PDF-` 开头时，`Content-Type: application/pdf`，`Content-Disposition: inline`；否则为 `application/octet-stream`，`Content-Disposition: attachment`；
  - 文件名用 `filename*=UTF-8''<转义后的名字>`。
- **代码复用**：读取、校验、取消这一段与 `citedFile` 相同，请提取成一个共用函数。`citedFile` 的对外行为（包括它现有的缓存头）保持不变。

## 3. 页面（`ConfirmationCard.vue`）

- **按钮**：项有 `source_ref` 时，显示"打开原文件"按钮（`data-confirm-file`），待确认与已关闭两种状态都显示；没有 `source_ref` 时不显示。
- **接口**：新增 `readConfirmationFile(spaceId, itemId): Promise<Blob>`，用 `get(url, { responseType: 'blob', signal })` 带认证读取。路径为 `/api/v1/enterprise/spaces/<编码后的 space>/view/confirmations/<编码后的 id>/file`。
- **点击之后**：
  1. 在点击处理函数里**同步**执行 `window.open('', '_blank')`，避免读取完成后再开窗被浏览器拦截；
  2. 读取期间按钮不可用，并显示"正在打开…"（`role="status"`）；
  3. 读取成功后，用 `URL.createObjectURL(blob)` 生成地址，赋给新窗口的 `location.href`，60 秒后撤销这个地址；
  4. 读取失败时关闭新窗口，在卡片上显示错误（`data-confirm-file-error`，`role="alert"`）：
     - `SOURCE_NOT_FOUND`："原文件已不存在"；
     - `SOURCE_INTEGRITY`："原文件与提问时的版本不一致"；
     - 其他错误："打开失败，请重试"；
  5. `window.open` 返回 null 时，提示"浏览器拦截了新窗口，请允许弹出窗口后重试"，并且不发起读取。
- **范围**：所有文案五种语言齐全。不改卡片的其他行为，也不改 `EnterpriseConfirmations.vue` 的列表逻辑。
