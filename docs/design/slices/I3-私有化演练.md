# I3 私有化演练

> 状态：Spec 草稿（2026-10-30，Claude）。实现方 Claude，审核方 Codex。蓝图 §11 I3：上线前用内网 LLM、VLM、embedding、
> rerank、MinerU 做材料不出内网的端到端演练；§12 风险「私有化后 OCR 与模型能力不足」。
> 分两步：**I3a 从制品全新安装**（可现在做，依赖 I1）；**I3b 内网模型演练**（阻塞于用户的内网资源）。

## 1. I3a 从制品全新安装演练

目的：证明只凭“CI 镜像 digest + 仓库里的部署文件 + 一份运维手册”，就能在一台干净的机器上装出可用环境；顺带验证 I2 的
compose 与恢复流程。第一次演练用本机**独立的 colima profile**（如 `i3-rehearsal`，单独磁盘），不碰线上 profile 与数据。

步骤（写成可重复执行的 runbook 与脚本 `scripts/rehearsal/`）：
1. 新建 profile → 按 `deploy/cloud-test/images.lock` 拉取 digest（I1 产物）。
2. 起 pg/redis/docreader → app：官方迁移推进到当前头、企业迁移账本推进到当前头（以账本状态证明，不以日志）。
3. 初始化数据，二选一：
   - **恢复**：用 I2 的备份格式恢复一份线上库与原文件 → 核对 Active；
   - **最小新装**：空库 + 建租户、Space、API key + Harness 对 1 款公开产品（数据集材料）编译发布（≤ 10 次 DeepSeek）。
4. 冒烟：健康 200；API key 读 Active；1 次快问快答；原文回跳（PDF）打开；Harness `publish_navigation --dry-run`。
5. 拆除 profile，记录耗时与每一步的人工操作。

通过标准：全程无手工改镜像、无从源码构建；每一步有命令和预期输出；冒烟全过；总耗时与人工步骤写进手册。

## 2. I3b 内网模型演练（阻塞于用户资源）

目的：模型与解析全部换成内网服务，验证“只改配置即可切换”（蓝图 §7.6）与材料不出内网。

- 模型通过 OpenAI 兼容接口按阶段配置：问答 LLM、编译 LLM（Harness `HARNESS_LLM_*`）、VLM、embedding、rerank；代码不出现模型家族特判。
- 解析：自建 MinerU（S10 相关），docreader 指向内网服务。
- 网络：演练机禁止访问公网（出网白名单为空），用 `tcpdump`/防火墙日志证明没有外发。
- 质量：在 2 个 pack 的 Golden 产品上跑一次编译 + 评测，与 DeepSeek 结果对比，写明差距（质量结论按蓝图只认生产目标模型，演练只给差距与风险）。

**需要用户提供**：内网 LLM / VLM / embedding / rerank 服务的地址与模型名（OpenAI 兼容），MinerU 部署位置，一台内网演练机（规格同 I2），
演练用的材料范围许可，以及内网镜像仓库（或允许把 I1 的镜像导入内网）。

## 3. 改动范围

`scripts/rehearsal/`（新，shell/Python 小脚本）、`docs/` 运维手册（安装、恢复、换模型配置）、本 Spec。I3a 不改产品代码；
若演练暴露“配置不能切换”的硬编码，按普通切片另开 Issue 修复。

## 4. 验收

- **I3a**：§1 通过标准全部满足；runbook 由另一个人（或 Codex 审核时）按文档逐步可复现；DeepSeek ≤ 10 次。
- **I3b**：内网服务全部生效、零外发证据、Golden 对比报告；所需配置改动只在配置层。
