## 1. 目标

段落评分要反映编译器的真实差距。本片把裁定 1–3 写成**版本化的评分规则**，只改评分：
- 不改编译器、卡片、Golden；
- 旧口径保留，用于对照。

## 2. 规则（`harness/src/insurance_harness/eval/segment_scoring_rules.json`，版本 2026-10-26.1）

记某个字段的 Golden 段落为 G，选中的段落为 C，中性段落为 N：
- 召回 = G 中去掉 N 后，被选中（或其副本被选中）的比例；
- 精确 = C 中去掉 N 后，属于 Golden（或是 Golden 的副本）的比例；
- 分母为 0 时这一项记为空（`None`），不计入平均，与现状相同；
- 判断"被选中"时用全部 C，中性段落也可以通过副本为 Golden 段落记功。

1. **近似副本**（裁定 1）：
   - 比较两段是否为副本时，在现有的标准化之外（去空白、统一全半角、去掉开头一个条款号或项目符号），再做两件事：
     - 按 `copy_replacements` 替换（"本附加合同"→"合同"、"本合同"→"合同"、"本条款"→"条款"）；
     - 去掉夹在汉字之间的 1–2 位脚注编号（`copy_footnote_pattern`）。只认紧贴在两个汉字之间的独立数字，后面是计量单位（日、天、年、月、岁、元、万、倍、种、次、个、项、级、类、期、份、条、款、号等）或前面是"第"的不算：
       - "合同1后"去掉 1；
       - "有15日""第3条"保持不变，避免把"15日"和"30日"当成同一段；
   - 仍要求较短的一段至少 20 字，并且完整包含在另一段中，不做相似度判断；
   - 同一文件内的重复不算副本，与 S4e 相同。
2. **中性：标题与阅读指引**（裁定 2），只用于条款与说明书。费率表的表头单元格（如"10年交"）也很短、也没有句末标点，但它们是交费字段的证据（S4j），不能当作标题：
   - 标准化后不超过 `heading_max_chars`（14）字，并且不含句末标点；
   - 或者含有 `guide_markers`（"阅读指引""这部分讲的是"）。
3. **中性：脚注与释义**（裁定 3）：
   - **脚注块**：从一页中第一个"脚注开头"段落起，到该页末尾。脚注开头指：以 1–2 位数字加空格开头（后面不是数字、"级"或"%"），并在前 40 字内出现"指""是指""是由"或冒号；块内再出现条款号的，这一页不算脚注块；
   - **释义部分**：从标题含"释义"的段落起，到下一个章节标题或文件末尾，包括标题本身；
   - 字段卡片 `includes` 提到"释义"或"脚注"的字段，这两类段落照常计分（目前 6 个字段：意外定义、疾病定义，以及几个疾病名单）；其余字段中性。
4. **中性：说明书的重述**（裁定 3）：
   - 某字段的 Golden 至少引用了一段条款时，说明书里的段落对这个字段中性；
   - Golden 只引用说明书的字段（说明书独有的内容）照常计分；
   - 文件角色按文件名判断：`document_roles` 中 "条款" → 条款，"说明书" → 说明书。

## 3. 接口与输出

- `score_selection(source, golden, predicted, *, rules=None)`：
  - `rules=None` 时用旧口径，结果与现在逐项相同（受保护的 S4d–S4j 测试不变）；
  - 传入 `load_scoring_rules()` 时用新口径；
- 新模块 `harness/src/insurance_harness/eval/segment_rules.py`：
  - `ScoringRules`（规则数据，带版本）与 `load_scoring_rules()`；
  - `neutral_segments(source, field_key, gold, rules) -> set[str]`；
  - 新口径的副本判断；
- 命令行 `segment_score`：
  - 每个产品与合计各输出一行新口径，行首带规则版本；
  - 另起一行 `legacy`，输出旧口径，便于对照。

## 4. 验收（RED，受保护）

`harness/tests/eval/test_segment_rules.py`（合成页面，不依赖真实材料）：
1. 只差"本"字或夹了脚注编号的条款与说明书段落互为副本；不到 20 字的不算；
2. 标题行与阅读指引行：漏选不扣召回，多选不扣精确；
3. 脚注块与释义部分：对普通字段中性；对卡片要求选释义的字段照常计分；
4. Golden 引用了条款的字段，说明书段落中性；Golden 只引用说明书的字段，照常计分；
5. 不传 `rules` 时与旧口径完全一致；
6. 规则文件带版本，读取失败时报错，不静默退回旧口径。

**门禁**：`uv run pytest`、`uv run ruff check .`、`uv run mypy src tests`、架构守卫。

## 5. 证据（PR 中报告，不进仓库）

用 2026-10-26 的编译结果（`~/insurancekb-runs/s5b4-first/compile`）对 5 款产品重新评分。分别列出旧口径、新口径，以及每条规则单独去掉时的召回与精确（消融），看每条规则各贡献多少。

错误分析的估计：前三条规则合起来大约召回 0.86、精确 0.88；剩余差距主要是 S4i 拆段片段（S12b）和跨字段归属（编译器）。
