## 1. 问题

S12c-3 的盲评显示，"属于其他字段"集中在 9 个字段上，而且现有字段卡大多已经把这些内容列入 excludes。模型照样写入，原因是边界写得不够具体，或者与 includes 的说法互相打架：

| 字段 | 评委指出的混入内容 | 原卡的问题 |
|---|---|---|
| `coverage_responsibilities` / `coverage_summary` | 写在保险责任条文里的"生效前已患疾病再次发生不赔"、某类疾病程度不保、等待期内出险退费 | excludes 只写"不承担保险责任的情形"；includes 的"主要限制"没有说明不含不保情形 |
| `target_customer_profile` | 照抄投保年龄、出生天数等承保条件，展开给付条件，复述投保举例 | includes 允许"依据年龄归纳"，没有说明只写概括的人群描述 |
| `premium_payment_frequency` | 抄入"保险费约定支付日"释义和"无对应日取月末"的日期规则 | excludes 只写"名词定义"；该释义同时是月、季、半年、年交费频率的出处 |
| `income_loss_benefit_payment_rules` | "每年给付以一次为限"、给付后合同终止、投保举例金额 | 次数上限没有写明归上限规则 |
| `disability_recovery_and_benefit_termination_rules` | 具体给付年数、身故时一次性补足的金额公式 | 金额公式没有写明归金额规则 |
| `disability_status_verification_and_reassessment_rules` | 核验后不再符合失能状态即中止给付、合同继续有效 | includes 的"未按时提交材料的处理"与"恢复后停止给付"界线不清 |
| `non_guaranteed_benefit_rules` | 死差益、利差益等红利来源的定义；"基本保险金额不含红利"一类计算口径 | includes 的"影响因素"容易被展开成盈余来源定义 |
| `sum_assured_growth_rate` | 各部分保额的增长基数与计算公式 | 没有说明只写比例、不写各部分保额的计算公式 |

## 2. 改动

只改 `harness/src/insurance_harness/compilers/schema_fields/field_cards.json`，版本 `draft-2026-10-18a` → `draft-2026-10-28a`。不改提示词、引擎、目录或其他卡。

- **最终合入**：上表除 `coverage_responsibilities`、`coverage_summary` 以外的 7 张卡的 `includes`、`excludes`、`bad`，以及适用人群卡的 4 个示例。
- **已撤回**：两张 `coverage_*` 卡的改动在第三轮后撤回（§7 第 5 条），这两张卡保持 `draft-2026-10-18a` 时的文字。
- **下文**：下面各轮的描述保留当时的改法，作为消融记录。

措辞规则（AGENTS.md 首要原则）：只写寿险领域的通用说法，不写产品编号、产品名称、样例材料原句或预期答案；需要举例时用占位（如"出生满X日至Y周岁"）。

**改法：边界写在"内容"上，不让第一步把混合段落整段丢掉。** 第一步把 excludes 理解为"这类段落不选"。第一轮消融中，把"约定支付日释义""投保年龄条件"写成整段排除，第一步就丢掉了这些段落：缴费方式变成 unknown（评委判 wrong，3 款），适用人群也不再选用投保年龄条款作依据。第二轮改为：

- 依据段落照常选。例如投保年龄条款可以作为归纳年龄段的依据；约定支付日释义中列出的月、季、半年、年交费频率仍属本字段。
- excludes 只写不得写入取值的那部分内容，例如对应日规则、不保情形。
- `coverage_*` 的不保限定后注明"同一段落中的给付内容照常选入"。

**第三轮（按 §7 裁定 R1、R2）**

- **适用人群**：字段范围不变，仍是"客群画像，不是承保条件"。
  - 第一步选入所有说明产品为谁而设的段落：投保年龄条款，说明保障目的或保障需求的产品特色、保障概述段落（如为少儿提供的额外保障、产品满足的保障需求），以及保险期间条款；
  - 取值压缩为简短画像（年龄段 + 保障需求）。年龄段用概括的人群描述（如"少儿""中青年家庭经济支柱"），不写投保年龄的具体周岁数字或出生天数规则，也不写给付细节。第三轮只写"年龄段"时，模型把它读成"0-55周岁"，6 款全部照抄了投保年龄上下限，所以补上这句；
  - 说明书中以具体人物为例的投保案例不入本字段；
  - 同卡的 4 个正确示例原先逐项写出投保年龄上下限与出生天数，与本规则冲突，按本规则改写为"年龄段 + 保障需求"。两个示例的 pitfalls 同步改写，终身寿示例写明"漏选保障需求的产品特色段落"。这些示例原由独立评委复核，改写后标注依据为本裁定。
- **保险责任 / 保什么 与失能核验**：归属按段落内容判断，不按所在小节标题。
  - 决定每期是否给付、能否继续给付的实质条件属于保险责任的给付条件，照常选入（如相邻两次给付之间被保险人仍须满足失能或状态认定标准）；
  - 核验或复评由谁进行、需提交的资料、有异议时的鉴定等纯手续，以及因无法核验而暂停或停止给付的手续后果，归 `disability_status_verification_and_reassessment_rules`；
  - 经核验确认已恢复而减少、中止或停止给付，归 `disability_recovery_and_benefit_termination_rules`；
  - 失能核验卡的 includes 同步写明：它收的是"因无法核验而暂停或停止给付"的手续后果，不收因已恢复而停止给付。

## 4. 升级影响与回滚

- **升级影响**：字段卡版本变化后，旧编译输出不能再按 `engine.reusable` 复用；编译器身份（cards + 值协议）随之改变。下一次重编时，每个 claim 仍按 `changes/decision.py` 的顺序判定，**不是一律 UPGRADE**：
  1. 新旧取值等价（状态相同，且取值相同或证据摘要相同）：UNCHANGED，材料已撤回时 REFRESH；
  2. 专家锁定且不等价：CONFLICT；
  3. 旧值为 unknown：FILL；
  4. 材料已撤回：SUPERSEDE；
  5. 材料未变、编译器身份不同：UPGRADE；
  6. 依据新增材料的变化：仍按原规则 KEEP 或 CONFLICT。

  UPGRADE 到 unknown 的在普通路由下强制进人工队列。当前默认准入策略为空（`review_policy.json` v3），本切片不改，所以 UPGRADE 不会自动上线。S12c-4 carry 照常复用已审证据段。
- **回滚**：revert 本切片的字段卡提交，只影响此后的编译所用规则，**不改写已生成的候选，也不改写已发布的 Release**。线上数据要回退，需另行重编、比较、审核和发布，这些都是独立的动作。

- 不处理责任免除内容混入保险责任 / 保什么，例如写在保险责任条文里的既往症不赔、某类疾病程度不保、等待期内出险退费。本切片的 `coverage_*` 改动已撤回。后续切片只改取值层措辞，即 includes 与 bad 示例，**不新增 excludes**，并用多次重复的消融验证。

## 7. Owner 裁定（2026-10-28，#425 审核 R1–R4）

1. **R1 适用人群不收窄为年龄画像。** 字段范围保持"客群画像，不是承保条件"。通用规则如下：
   - 第一步选入所有说明产品为谁而设的段落：投保年龄条款，产品特色、保障目的段落（如为少儿提供的额外保障、产品满足的保障需求），以及保险期间依据；
   - 取值压缩为简短画像（年龄段 + 保障需求），不照抄年龄上下限、出生天数规则或给付细节；
   - 说明书中以具体人物为例的销售案例不入本字段；
   - 与本规则冲突的已有正确示例（逐项写出投保年龄上下限的）按通用规则改写，终身寿示例的 pitfall 与本规则一致。
2. **R2 保险责任 / 保什么 与失能核验的边界。** 归属由内容决定，小节标题不决定归属：
   - 决定每期是否给付、能否继续给付的实质条件（如相邻两次给付之间仍须满足失能标准）是保险责任的给付条件，照常选入；
   - 纯手续（谁来核验、提交什么资料、有异议时的鉴定），以及它们的手续后果（因无法核验而暂停或停止给付），归失能核验与复评字段；
   - 因已恢复而停止给付，归失能恢复字段；
