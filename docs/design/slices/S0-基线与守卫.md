## 1. 目标

1. 在干净环境中对 Go、Harness、前端各跑一次完整门禁，记录失败清单，作为后续切片"不新增失败"的比对基准。
2. 让 Claude 已提供的架构守卫（G1–G6、G10、G11）在新环境中通过，并接入 CI。
3. 精简 CI 工作流，使新私有仓库可以启用 Actions；把 Dependabot 配置缩到实际维护的组件。

本切片**不改产品代码**（`harness/src`、`internal/`、`cmd/`、`frontend/src`、`docreader/`、`migrations/`）。

## 3. 基线门禁

### 3.1 环境

- Harness：在 `harness/` 下 `uv sync --locked`（Python 3.12），不复用旧工作树的 venv；记录 uv 与 Python 版本。
- Go：使用 `go.mod` 指定版本；记录 `go version`。
- 前端：`frontend/` 下 `npm ci`；记录 node 与 npm 版本。
- 如遇本机代理导致的 DNS 或下载问题，在 PR 中如实记录现象，不为跑通修改产品代码或测试。

### 3.2 命令

| 组件 | 命令 | 分组与超时 |
|---|---|---|
| Harness | `uv run pytest -m "not live and not integration_postgres" -q`、`uv run ruff check .`、`uv run mypy src tests` | pytest 按测试目录分组，每组超时 20 分钟 |
| Go | `go test ./...`（仓库根）、`go vet ./...` | 按包运行，单包超时 10 分钟；外网依赖导致的失败如实记录 |
| 前端 | `npm test`、`npm run type-check`、`npm run build` | — |
| 守卫 | `python -m pytest -q tests/architecture` | — |

某组卡住时，先按文件或包二分定位，时间盒 0.5 人日；仍未定位就记为"已知阻塞"，写明现象与已排除范围，继续推进。

### 3.3 产出

`tests/baseline/` 下：

- `harness-nonlive-failures.txt`：每行一个 pytest nodeid 加一句失败摘要；
- `go-test-failures.txt`：每行 `包路径 测试名` 加一句失败摘要；
- `frontend-failures.txt`：每行一个测试标识加一句失败摘要；
- `README.md`：生成日期、commit、环境版本，以及 ruff、mypy、type-check、build、go vet 的结果计数。

这些文件只作比对基准：不 deselect、不加 xfail/skip、不修改任何测试。

## 4. CI 精简

新私有仓库的 Actions 目前关闭。目标：PR 只跑与改动相关的检查；需要旧仓库密钥或会向外发布的工作流改为手动触发。
Codex 先逐个读工作流确认其实际行为，在 PR 中附上下表的最终版本；与下表不同的地方写明理由。

| 工作流 | 现状 | 目标 |
|---|---|---|
| `harness-ci.yml` | push/PR，含 PG 集成 | 保留 |
| `frontend.yml` | push main / PR | 保留 |
| `app.yml` | Go 构建与测试 | 保留 |
| `go-lint.yml`、`go-lint-cache.yml` | PR / push main | 保留 |
| `docreader.yml`、`anydoc.yml`、`cli.yml` | 按路径触发 | 保留 |
| `cli-e2e.yml` | 需 `WEKNORA_E*` 密钥 | 改为只手动触发 |
| `harness-live.yml` | 手动 | 保留 |
| `docker-image.yml` | push main 推 Docker Hub（需密钥） | 改为只手动触发 |
| `dsh-plugin.yml`、`mcp-server.yml` | 构建并发布 npm/包 | 发布步骤只在手动触发时执行；PR 上只构建 |
| `release-lite.yml`、`weknora-app-local-live-image.yml` | 手动 | 保留 |
| 新增 `architecture-guards.yml` | — | PR 与 push main；`actions/checkout` 用 `fetch-depth: 0`；Python 3.12；运行 `python -m pytest -q tests/architecture` |

Actions 由 Claude 在本 PR 推送精简后的工作流后启用（仓库设置变更，不归实现者）。

## 5. Dependabot

`.github/dependabot.yml` 改为：

- 删除 `/cli` 的例行版本更新（新仓库已关闭过一次由它产生的 PR）；
- 根 gomod、`/frontend` npm、`/docreader` pip、github-actions 保持"只安全更新"；
- 新增 Harness（`/harness`）"只安全更新"。生态名称以 Dependabot 当前文档为准（`uv` 或 `pip`），在 PR 中注明查证来源；
- `/client`、`/miniprogram` 不是本项目维护的组件，删除对应条目。

## 6. 验收

- `python -m pytest -q tests/architecture` 在新环境全部通过，含各检测器自测。
- `tests/baseline/` 四个文件齐全；PR 描述含各组耗时、峰值内存（如可得）、失败总数与按目录分布、阻塞项。
- 工作流按 §4 精简；`architecture-guards` 在本 PR 上运行通过。
- Dependabot 按 §5 修改。
- 未修改产品代码与受保护路径。
