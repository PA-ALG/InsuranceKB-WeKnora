## 1. 问题

S12 准入评估需要每类险种至少 2 款 Golden（`docs/design/S12-准入评估-20261028.md` §3.4）。#422 补了 8 款，另有 3 款标好了 Golden，却进不了数据集（`docs/design/S12-Golden六类险种-20261028.md` §4）：

- **2647（专属商业养老，在售唯一一款）、1855（护理附加险）**：费率表离线认不出角色。
  - 2647 的 `费率表.pdf` 是一份"转换标准表"，开头没有"费率表/金额表"；
  - 1855 的 `费率表.pdf`，PDF 文字层从表格正文开始，标题不在开头；
  - S4i 要求文件名与开头两处信号都命中，所以都报 `MATERIAL_ROLE_UNRESOLVED`。
  - 线上 2647 已由用户在待确认页确认为费率表，编译按 S5b-6 用登记表记录的角色。数据集没有对应的记录办法。
- **L3223（意外医疗）**：来源仓库里它目录下的 `产品说明书.pdf` 是另一款产品（L3233）的说明书，Owner 裁定不随数据集发布。去掉后，这个目录没有说明书，不满足数据集"每款都有条款和说明书"的约束。

## 2. 规则

**数据集目录可以带一份 `material_roles.json`，逐个文件记录已确认的材料角色，并绑定文件的 SHA-256。有这份记录时，按记录的角色读材料；没有时，行为与现在完全相同（S4i 推断）。** 这与 S5b-6"登记表记录的角色在编译时为准"一致，只是记录放在数据集目录里。

### 2.1 记录文件

```json
{
  "basis": "为什么需要记录（必填，非空）",
  "roles": {
    "保险条款.pdf": {"role": "terms", "sha256": "<64 位小写十六进制>"},
    "费率表.pdf": {"role": "rate_table", "sha256": "<…>"}
  }
}
```

- **必须完整**：`roles` 的键与目录中的 PDF 文件名一一对应，不多不少。部分记录没有意义（没记的文件仍要推断），而且"缺一份说明书"只有在完整记录里才是明确的决定，而不是漏放了文件。
- **绑定文件身份**：每项的 `sha256` 必须等于该文件字节的 SHA-256。文件被替换后记录自动失效，不会把旧决定套到新文件上。
- 角色必须是材料角色目录（`identity/material_roles.json`）中的角色；未知角色沿用 S5b-6 的 `MATERIAL_ROLE_UNKNOWN`。
- 失败一律关闭，整款停下，报调用方安全的代码（`MaterialRoleError`，是 `ValueError`）：
  - 记录文件不是合法 JSON、字段缺失或多余、`basis` 为空、覆盖的文件与目录中的 PDF 不一致：`RECORDED_ROLES_INVALID`；
  - SHA 不符：`MATERIAL_IDENTITY_MISMATCH`（与 S5b-6 同名）。

### 2.2 读取

数据集的三个读取入口都用同一份记录：

- `eval.product_sources.source_pages`（评委标注读取的证据页）；
- `eval.product_sources.trusted_source_pages`（编译、段落评分、Golden 校验读取的证据页与表头输入；`TrustedPages.roles` 带出生效角色，S5b-6 已把它计入编译产物的输入身份）；
- `eval.golden_remap`（重映射读取的材料与排除集合）。

角色确定之后的用法不变：能否作为证据由角色的 `evidence` 决定；表头输入按信任策略的 `header_rules` 取。

### 2.3 数据集约束（受保护测试）

`tests/identity/test_material_roles.py::test_every_dataset_material_is_recognised_and_each_product_drops_one_rate_table` 现在要求每个目录：所有材料都能认出、恰好一个费率表、条款与说明书都有。改为：

- **没有记录文件的目录**：约束原样不变；
- **有记录文件的目录**：
  - 每份材料的生效角色都不为空；
  - 恰好一份条款，至多一份费率表，说明书可以没有（记录本身就是"本款不带说明书"的决定）；
  - 推断能认出角色的材料，记录必须与推断一致。线上 S5b-6 在两者不一致时以记录为准；数据集是我们自己整理的，不一致只可能是记错了，所以在数据集上直接拒绝。

这是对受保护断言的有意修改，单独提交并在 PR 中说明。

## 3. 数据

本切片同时补入 3 款（Golden 来自 #422 运行目录的 `out-of-repo/`，manifest 条目由同一生成方式写出）：

| 产品 | 目录材料 | 记录的角色 | Golden 处理 |
|---|---|---|---|
| 2647 | 条款、说明书、费率表（转换标准表） | 三份全记；费率表 = `rate_table`（与线上用户确认一致） | 不变。原标注未见表头段；转换标准表表头不列交费期间，`premium_payment_term` 原取自说明书，不受影响 |
| 1855 | 条款、说明书、费率表 | 三份全记；费率表 = `rate_table` | `premium_payment_term` 由 unknown 改为 present，见下 |
| L3223 | 条款、费率表（不带说明书） | 两份全记 | 只改文件序号：条款由 D2 变为 D1，页与句位不变，逐条核对文本 |

- **1855 的交费期间**：原标注时费率表认不出角色，评委看不到表头段，所以标了 unknown。加上记录后，费率表表头（"交费期间：趸交、3 年交 …… 20 年交"）成为该字段的表头输入。按 S4j（用户 2026-10-18 裁定：交费期间引用费率表表头），该字段应为 present，引用各页表头段。这是 Owner 依规则所做的确定性修订，不调用模型，在 manifest 该产品条目的 `owner_edits` 中写明依据。
- **L3223 重编号**：评委只引用了条款（D2），没有引用那份说明书。去掉说明书后，条款的段落切分不变，只是文件序号前移。实际执行、也可验证的约束是：**同一文件 SHA，页与原句位保持，只改文件序号（D2→D1）；每条引文在新编号处重新核对文本**（文件、指纹、页、去空白文本全部相同），任何一条不符即停止。
  - 这不是"按（文件、页、引文）找唯一段落"。同一页上可以有文本相同的两个句子：`claim_application_deadline_and_documents` 的 `D2P6S7` 与 `D2P6S14` 各在第 6 页有一个文本相同的候选（医疗申请与急性病身故申请两节各列一遍同样的材料）。按句位保留后分别是 `D1P6S7`、`D1P6S14`，各自对应评委原来引用的那一节，引用正确，不删。
  - 规则由 `eval.golden_reindex.reindex_documents` 实现（§6），对 #422 原标注重新执行的结果与入库的 `L3223.json` 逐字节相同。
- manifest 不新增 `revisions` 条目：这些是新入库产品的入库处理，不是对已有 Golden 的修订；依据写在各产品条目的 `basis` 与 `owner_edits` 中。

## 6. 第 2 轮补充（#424 Codex R1–R4，Owner 裁定）

1. **记录必须无歧义（R1）**：`material_roles.json` 在模型校验之前拒绝任何层级的重复 JSON 键（重复的文件名、`role`、`sha256`、`basis` 等），报 `RECORDED_ROLES_INVALID`。三个读取入口共用同一个读取函数 `eval.product_sources.read_materials`，不各自解析记录。
2. **完整性按真实文件清单核对（R2）**：
   - 有记录的目录，按目录中真实存在的 PDF 文件核对：扩展名不分大小写（`.pdf`、`.PDF` 都算），多出未记录的 PDF 或记录了不存在的文件，报 `RECORDED_ROLES_INVALID`；
   - 有记录的目录只接受普通文件：PDF 是符号链接、目录等其他形态，报 `RECORDED_ROLES_INVALID`；
   - 区分"没有记录"和"有记录但读不了"：`material_roles.json` 是悬空符号链接、目录、不可读或不是 UTF-8 时，报 `RECORDED_ROLES_INVALID`，不当作没有记录；
   - 没有任何记录的目录保持原行为（只读 `*.pdf`）。
3. **先核身份，再解析，失败给安全代码（R3）**：
   - 有记录的目录，每份 PDF 只读一次字节，先用这份字节核对记录的 SHA（不符报 `MATERIAL_IDENTITY_MISMATCH`），再解析同一份字节。所以把同名文件换成任何其他字节，包括非 PDF 字节，都报身份不符；
   - 读取或解析失败（文件不可读、字节不是 PDF）报 `MATERIAL_UNREADABLE`，不外泄 pdfium 异常或文件内容。没有记录的目录也一样：正常读取不变，只是坏文件的错误由原始异常变为这个代码；
   - `eval.pdf_text` 增加按字节解析的 `pdf_pages(document, content)`，`read_pdf` 改为读字节后调用它；解析失败抛 `PdfReadError`（`ValueError`），由 `product_sources` 转为上面的代码。`golden_remap` 的命令行入口因此输出 `{"stopped": "MATERIAL_UNREADABLE"}` 等代码，不出现 traceback。
4. **L3223 重编号的依据（R4）**：见 §3。新增 `eval/golden_reindex.py`：`reindex_documents(golden, source)` 把每条引文移到其文件当前的序号，页与句位不变，并要求新编号处的段落文件名、指纹、页、去空白文本与引文完全相同，否则报 `RemapError("REINDEX_MISMATCH")`。它只用于"切分不变、只是文件增减"的情形，不替代 `golden_remap` 的按位置重映射。

**补充的改动范围**：`harness/src/insurance_harness/eval/pdf_text.py`、新文件 `harness/src/insurance_harness/eval/golden_reindex.py`；`docs/design/S12-Golden六类险种-20261028.md` 记录两处同页同文。
