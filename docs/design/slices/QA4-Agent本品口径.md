# QA4 Agent 方式的本品口径

> 状态：Spec 冻结（2026-10-29，Claude）。实现方 Codex，审核方 Claude。Issue #426。
> 真实调用：实现阶段为 0；上线后复核见 §5。

## 1. 问题

2026-10-29 C/D（Agent）方式复测：q23-D 把行业通行的“自本合同成立之日起超过 2 年的，我们不得解除合同”写成 2650 的条款，并放进结论；回答自己也承认检索到的条款片段里没有这一句。

根因（#426，只读核对代码与线上数据）：

- 2650 的 8.5 条完整在检索结果里（同一 chunk 含 8.5 全文，随后是 8.6），只有“30 日”与“订立时已知不得解除”两条时限，没有“2 年”。不是断段（QA2c 的 N2 补后段帮不上），也不是检索漏召回，是模型用常识补了一条产品规则。
- 快问快答的规则里有第 4 条“不用常识回答具体产品事实”（`chatsource/answer_context.go` `AnswerRules`），只作用于快问快答。Agent 的系统提示改用 `KnowledgeNotice`（`chatsource/knowledge.go`），要求每条产品事实带来源句柄、找不到来源就不写，但没有“不用常识/行业通行做法补产品规则”，也没有“句柄必须支撑这一行事实”。q23-D 正好违反这两点：补了行业通行条款，并把相邻条款的句柄挂在它上面。

## 2. 改动

只在 `KnowledgeNotice` 中补一条规则，与快问快答第 4 条对齐。以下三句原样写入（验收测试按原文检查），位置在“回答中的每一条产品事实都必须……”之前或之后均可：

1. `不用常识、行业通行做法或其他产品的规定回答具体产品的事实。`
2. `材料没有写的内容，说明材料未载明，不写进结论，也不给它挂来源句柄。`
3. `来源句柄必须能支撑同一行的事实，不能借用相邻条款的句柄。`

规则对“只有已发布知识”与“已发布知识 + 原文检索”两种 Agent 轮次都生效；没有 wiki KB 的轮次仍返回空串（不变）。

## 3. 不做

- 不改 Agent 工具、检索与过滤。QA2/QA2b/QA2c 的按点名产品检索、合并前排除他品、N2 补后段目前只接在快问快答（`chatsource/retrieval.go` `RetrievalScope`），Agent 的原文检索工具只做固定材料过滤与产品标注。这一差距不是 q23-D 的原因，本片不处理；若后续 Agent 复测出现借用或断段，再按证据另立切片。
- 不改快问快答规则，不改模型、温度或迭代次数。
