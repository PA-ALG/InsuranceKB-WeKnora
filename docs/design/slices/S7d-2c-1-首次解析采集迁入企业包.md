## 1. 目标与现状

企业知识的来源回跳依赖"首次解析采集"。解析 PDF 时，系统把原文 Markdown、原生坐标结构与分块范围签封后写到本地存储，之后的出处与页面接口按（知识、解析次数）精确读回，不再重新解析。

这套内核现在住在 830/G3 旧代码里：

- `service/g3_first_parse.go`；
- 签封与存储借用 `concept_source_reuse_830_g3.go`；
- 原生结构校验借用 `concept_source_authority_830_g2.go`。

S7d-2c-3 要删除这些旧家族，所以必须先把内核搬到项目自有的企业包，并保证已经写在磁盘上的采集照常能读。

## 2. 设计

### 2.1 新包 `internal/enterprise/capture`

各文件不超过 500 行，文件名不带旧版本标记。

| 内容 | 说明 |
|---|---|
| `Identity`、`Range`、`Record` | 与现有 `g3FirstParseIdentity`、`g3FirstParseRange`、`g3FirstParseRecord` 的字段、顺序、JSON 标签完全一致 |
| `Contract = "g3-first-parse.830.v1"`、`Key(Identity)` | 键的推导不变：`"first-" + sha256(contract + "\x00" + canonical(identity))` |
| `Keys`、`NewKeys(activeKeyID, privateKeys)` | 用现有引用令牌签名环的私钥签封；环中任一公钥都可验证，轮换不受影响 |
| `Store`、`NewStore(root, keys)`、`DefaultRoot()` | 根目录不变：`$LOCAL_STORAGE_BASE_DIR`（默认 `/data/files`）下的 `.concept-source-reuse-v1`；文件 `<key>.json` |
| `Store.Save(id, result, chunks, origin)` | 规则不变：校验原生结构与分块后写入；同一键已存在时只接受完全相同的记录；用硬链接发布，不覆盖 |
| `Store.Read(id)` | 文件不存在返回 `os.ErrNotExist` 语义，**先于**密钥检查；签名、键、内容或原生结构不符返回 `ErrUnavailable` |
| 签封 | 格式 `{key_id, key, payload, signature}`，域 `"weknora.concept-source-reuse.830.g3.v1"`，签名对象 `domain\nkey\npayload`，载荷按原样规范化 |
| 原生结构校验 | 与现有 `prepareConceptNativeQuoteIndex830G2` 等价：契约与指纹、规范字节、页码与页文本摘要、坐标框与覆盖规则；只用于校验，不做引用定位 |
| `ExactChunks`、`SplitParentChild` | 与现有 `g3ExactSourceChunks`、`g3FirstParseSplitParentChild` 等价 |
| `ReadSourceArtifact(ctx, store, knowledge, scope, knowledgeID, attempt)` | 与现有 `G3FirstParseStore.ReadSourceArtifact` 等价：先核对知识归属与修订，再读采集；错误分类沿用 `source` 包 |
| `ErrUnavailable` | 消息与现有 `ErrConceptSourceAuthorityUnavailable830G2` 相同；旧变量改为指向它，`errors.Is` 两边都成立 |

### 2.2 旧服务侧

只做薄适配，不新增文件。新增非测试文件会触发 G11：

- `G3FirstParseStore` 的构造、`ReadSourceArtifact`、`save` 签名不变，内部委托 `capture`。受保护测试读写 `store.reuse.root` 与 `store.reuse.codec`，所以这两个字段保留，适配在每次调用时由它们构造 `capture.Store`。
- `g3FirstParseIdentity`、`g3FirstParseRange`、`g3FirstParseRecord` 改为 `capture` 类型的别名。旧家族仍在使用的 `readFirstParse`、`g3ExactSourceChunks`、`g3FirstParseSplitParentChild` 等改为一行委托。
- `knowledge_process.go` 不改。

旧家族自用的原生引用定位（`resolveConceptNativeQuote830G2` 等）暂时保留自己的副本，随 S7d-2c-3 删除。

## 4. 验收（RED，Claude 编写，受保护）

**`internal/enterprise/capture/testdata/`**：一份由**迁移前的现有代码**写出的签封采集，以及它的输入。

- 生成方式：固定的 ed25519 种子（32 字节 0x72，键 ID `citation-key`），固定身份，两页原生结构；
- ed25519 签名是确定的，所以同样的输入必须写出同样的字节。

**`internal/enterprise/capture/capture_acceptance_test.go`**：

1. **格式不变**：用同样的输入 `Save`，写出的文件与 testdata 中的签封采集逐字节相同；`Key` 与当时记下的键相同。
2. **旧采集可读**：把 testdata 的签封采集放入根目录，`Read` 得到原来的 Markdown、原生结构摘要与分块范围。
3. **失败关闭**：
   - 文件不存在时返回"不存在"，没有密钥时也一样；
   - 换身份（解析次数、租户）后读不到；
   - 改动载荷、换一套不含该键的密钥，都返回 `ErrUnavailable`。
4. **写入不覆盖**：同一记录重复保存成功；同一键换内容保存失败；根目录不可写时失败。
5. **出处读取**：`ReadSourceArtifact` 返回文件名、文件指纹、解析器身份、Markdown 与原生 JSON；未采集返回 `source.ErrNotCaptured`；知识不在该 RAW 库或修订不存在返回 `source.ErrNotFound`。

现有企业与服务测试照常通过，作为行为回归：`enterprise_capture*_test.go`、`source_pages_test.go`、`g3_first_parse_test.go`、`router/enterprise_space_sources_test.go`、releasestore 的 MCP 与生产测试。
