> 回验 quote → 渲染；失败返回 typed error"）、硬边界 4、6、7；S4c-2a Spec §3.2；S4c-2c Spec；2026-10-16 调研
> 分支：`slice/s4c2b2` ｜ 工作目录：`.worktrees/s4c2b2` ｜ 实现方：Claude ｜ 审核方：Codex（发布合同、证据口径、REST 与安全）

S4c-2b 拆为两片：2b-1 固定与退役（Codex 实现，并行）、**2b-2 本片**。

## 1. 目标

1. **提交时逐字回验**：候选包里每条 Evidence 必须与平台捕获的原文逐码点一致（页、码点区间、引文、文件指纹）；对不上的整包拒绝。
2. **有来源的内容必须带证据，模型生成的内容必须标注**（用户 2026-10-16）：自称有原文依据（`SOURCE_SUPPORTED`、`MIXED` 等）且有值或
   明确不适用的成员必须带至少一条通过回验的证据；LLM 自由知识发现允许模型做必要的生成，这类成员标为 `MODEL_GENERATED`，可以没有
   原文证据，标注随成员原样发布、读回与回跳接口都给出，供前端与 Agent 显示"大模型生成"。
3. **按 Release 回跳**：给定 Release、成员与证据序号，平台重新核对原文并返回文档、页、引文与页内高亮框；另提供该引用所指原始 PDF
   的精确字节（按指纹核对后才返回）。

## 2. 现状（`main@27e3d5daa`）

- 提交校验（`release/validate.go:101-113`）只把成员的 `evidence_refs` 交给 `EvidenceResolver`；`releasestore.Evidence.Resolve`
  （`evidence.go`）只核对 `source:v1:<knowledge_id>:<parse_attempt>:<file_sha256>` 的归属与修订指纹，不看引文与定位。
- Evidence 对象只在成员 payload 内（`payload.evidence[]`，claim、relation、qa_item 合同都有）；平台不校验它。合同：
  `contracts/evidence.schema.json`（`additionalProperties: false`；必填 source_ref、file_sha256、locator、quote、access_scope；可选
  `quote_sha256`、`match` 默认 EXACT）、`locator.schema.json`（`PDF_TEXT_SPAN` 的 page 从 1 起、start/end 为页内码点半开区间）。
  claim 的 `origin` 取 `SourceClass`：SOURCE_SUPPORTED、MIXED、MODEL_GENERATED、EXPERT_REVISION、STRUCTURED_IMPORT。
- `quote_sha256` 的 Harness 定义（`harness/.../contracts/knowledge.py:111-114`）：`sha256(utf8("".join(NFKC(quote).split())))`，
  即 NFKC 后去掉 Python `str.split()` 认定的全部空白。
- 捕获产物（S4c-2c）：`source.Service.Pages` 校验签名产物后按页返回文本（页文本连续拼成全文，偏移为码点）；原生 JSON 每页有
  `width_points`、`height_points`、`bboxes[]`（每个非空白码点一个 `{bbox:[x0,y0,x1,y1], global_codepoint_start, global_codepoint_end}`，
  `normalized_0_1e6_top_left`）、可选 `unavailable_ranges[]`（旋转页、字符映射失败、无效框）。现有 G3 的框查找按文本搜索、只给一个
  外接框，不复用。
- 原始文件：每个 knowledge 一个资源，所有 attempt 共用；没有按 attempt 取字节的接口。`interfaces.KnowledgeService.GetKnowledgeFile`
  返回当前文件。
- 路由：`router.registerEnterpriseRoutes`（`router.go:418`）构造 `source.Service` 并交给 `enterprise.Mount`；`*release.Service` 由
  `releasestore.Register` 经 DI 提供，构造时拿不到捕获产物读取器。

## 3. 设计

### 3.1 合同镜像与提交校验（`internal/enterprise/release`）

- 新文件 `evidence.go`：

  ```go
  // Evidence mirrors contracts/evidence.schema.json; Locator keeps only the fields this slice verifies.
  type Evidence struct {
      SourceRef   string  `json:"source_ref"`
      FileSHA256  string  `json:"file_sha256"`
      Locator     Locator `json:"locator"`
      Quote       string  `json:"quote"`
      QuoteSHA256 string  `json:"quote_sha256,omitempty"`
      Match       string  `json:"match,omitempty"`
      AccessScope string  `json:"access_scope"`
  }

  type Locator struct {
      Kind  string `json:"kind"`
      Page  *int   `json:"page,omitempty"`
      Start *int   `json:"start,omitempty"`
      End   *int   `json:"end,omitempty"`
  }

  // EvidenceCheck is one evidence object with its JSON pointer inside the bundle.
  type EvidenceCheck struct {
      Path     string // e.g. /members/0/payload/evidence/1
      Evidence Evidence
  }

  // EvidenceVerifier checks evidence against the captured sources of the request scope
  // (release.ScopeFromContext). It returns nil or a *Error with ErrorEvidenceMismatch,
  // ErrorEvidenceUnsupported or ErrorEvidenceUnverifiable whose Detail starts with the
  // failing Path; any other error is a storage failure and rejects the bundle.
  type EvidenceVerifier interface {
      VerifyEvidence(ctx context.Context, checks []EvidenceCheck) error
  }

  func WithEvidenceVerifier(v EvidenceVerifier) Option
  ```

- 新错误码：`EVIDENCE_MISMATCH`、`EVIDENCE_UNSUPPORTED`、`EVIDENCE_UNVERIFIABLE`、`MEMBER_NOT_FOUND`、`EVIDENCE_NOT_FOUND`。
- `NewService` 的 schemas 可另带 `"evidence"`（`contracts/evidence.schema.json`，其 `$defs` 自带 Locator）；`CheckSchemas` 同时校验它。
- `Receive` 在现有校验（含 `EvidenceResolver`）之后，对每个成员的 payload（JSON 对象）：
  1. 有 `evidence` 键时它必须是数组，每个元素按 evidence 合同校验，不通过 → `CANDIDATE_INVALID`（Detail 为 JSON 指针）；
  2. 有 `evidence` 键时，引文的 `source_ref` 集合必须与成员 `evidence_refs` 集合相等，否则 `CANDIDATE_INVALID`
     （没有 `evidence` 键的成员保持 S4c-2a 规则不变）；
  3. 来源规则（只看 payload 顶层的 `origin` 与 `state`，二者都是通用合同字段）：`origin` 为 `SOURCE_SUPPORTED`、`MIXED`、
     `EXPERT_REVISION`、`STRUCTURED_IMPORT` 且 `state` 不是 `unknown` → 至少一条 evidence，否则 `CANDIDATE_INVALID`；
     `origin` 为 `MODEL_GENERATED` → 不要求 evidence（有则照样回验）；没有 `origin` 键的成员不加此规则；
  4. 收集全部 evidence，若非空：未配置 `EvidenceVerifier` 或未配置 evidence 合同 → `EVIDENCE_UNVERIFIABLE`（失败关闭）；否则一次调用
     `VerifyEvidence`，错误原样返回（`*Error` 不改码）。
- 只在提交时回验一次（捕获产物按 attempt 只写一次并签名，激活时不重复）。

### 3.2 回验规则（`internal/enterprise/releasestore`，新文件）

- `NewEvidenceVerifier(spaces Spaces, pages PageReader) *EvidenceVerifier`，`PageReader` 是
  `Pages(ctx, source.Scope, knowledgeID string, attempt int64) (*source.PageSet, error)`（`*source.Service` 满足）。
- 每条 evidence 依次：
  1. `source_ref` 按 S4c-2a 格式解析；`file_sha256`（不区分大小写）等于引用里的指纹，否则 `EVIDENCE_MISMATCH`；
  2. `locator.kind` 必须是 `PDF_TEXT_SPAN`、`match` 为空或 `EXACT`，否则 `EVIDENCE_UNSUPPORTED`（OCR 在 S10、Office 在 S11、
     专家修订与结构化导入另开切片）；
  3. 读 `(knowledge, attempt)` 的页（同一次调用内按 `(knowledge, attempt)` 只读一次）；`SOURCE_NOT_FOUND`、
     `PARSE_ARTIFACT_NOT_CAPTURED`、`PARSE_ARTIFACT_INTEGRITY` 与 Space 外的知识 → `EVIDENCE_UNVERIFIABLE`；
     `SOURCE_UNAVAILABLE` 与其他错误 → 存储错误；页集的 `document_sha256` 必须等于引用指纹，否则 `EVIDENCE_MISMATCH`；
  4. `page`、`start`、`end` 都有，`1 ≤ page ≤ 页数`、`0 ≤ start < end ≤ 该页码点数`，且 `quote` 与页文本 `[start, end)` 逐码点相等，
     否则 `EVIDENCE_MISMATCH`；
  5. 有 `quote_sha256` 时，按 Harness 定义计算并比对（小写十六进制，不等 → `EVIDENCE_MISMATCH`）。空白集合 = Go
     `unicode.IsSpace` 加 U+001C–U+001F（与 Python `str.split()` 一致）；NFKC 用 `golang.org/x/text/unicode/norm`（已在
     go.mod 依赖图中，转为直接依赖）。实现为合同层函数 `release.QuoteDigest(quote string) string`；Go 与 Python 共用测试向量
     `internal/enterprise/release/testdata/quote_digest_vectors.json`（由 Harness `quote_digest` 生成），两端各有测试核对。
- Detail 只含 JSON 指针与原因类别，不回显引文或页文本。

### 3.3 页内区间与高亮框（`internal/enterprise/source`）

- 新方法与类型：

  ```go
  // Rect is one highlight rectangle in normalized_0_1e6_top_left coordinates.
  type Rect struct{ X0, Y0, X1, Y1 int }

  // SpanView is a verified quote location on one captured page.
  type SpanView struct {
      KnowledgeID, Document, DocumentSHA256 string
      ParseAttempt                          int64
      Page                                  int
      WidthPoints, HeightPoints             string
      Start, End                            int // page-local code points, half-open
      Quote                                 string
      Rects                                 []Rect
      Complete                              bool
  }

  func (s *Service) Span(ctx context.Context, scope Scope, knowledgeID string, attempt int64,
      page, start, end int) (*SpanView, error)
  ```

- 与 `Pages` 同样先完整校验产物（同一校验代码，不复制）；`page`、`start`、`end` 越界或 `start >= end` → 新错误码
  `SPAN_OUT_OF_RANGE`。
- 框：取全局码点落在 `[页起点+start, 页起点+end)` 的 bboxes，按码点顺序合并成行：下一个框与当前矩形在纵向不重叠
  （`y0 >= 当前.y1` 或 `y1 <= 当前.y0`）或 `x0 < 当前.x0`（换行回到左侧）时另起一个矩形，否则取并集。坐标越界、`x0>=x1`、
  `y0>=y1` 的框 → `PARSE_ARTIFACT_INTEGRITY`。
- `Complete`：区间内每个非空白码点都有框且没有 `unavailable_ranges` 与区间相交时为 true；否则 false，`Rects` 仍给出已有的框
  （可能为空），引文与页照常返回——查看器至少能打开正确页。

### 3.4 回跳接口（`internal/enterprise/mount.go` 与 `release.Service`）

- `release.Service.Evidence(ctx, p, spaceID, releaseID, slug string, index int) (EvidenceAt, error)`：
  `EvidenceAt{ReleaseID, Slug string; Index int; Origin string; Evidence Evidence}`。Release 必须显式给出 ID（不接受空串或
  `active`，查看器总是知道自己显示的版本）；Release 不存在 → `RELEASE_NOT_FOUND`；成员 → `MEMBER_NOT_FOUND`；payload 没有
  `evidence` 或序号越界 → `EVIDENCE_NOT_FOUND`。`Origin` 取 payload 顶层 `origin`（没有则空）。
- 路由（策略同其他企业路由：全权限且不限 KB 的服务密钥；成员 slug 可含 `/`，因此用查询参数）：
  - `GET /api/v1/enterprise/spaces/:space_id/releases/:release_id/citation?member=<slug>&evidence=<index>` → 200：

    ```json
    {"data": {"release_id": "…", "member": "1828/waiting_period", "evidence_index": 0, "origin": "SOURCE_SUPPORTED",
      "source": {"knowledge_id": "…", "parse_attempt": 1, "document": "保险条款.pdf", "file_sha256": "…"},
      "page": {"number": 5, "width_points": "595.28", "height_points": "841.89"},
      "start": 120, "end": 168, "quote": "…",
      "highlight": {"coordinate_space": "normalized_0_1e6_top_left", "complete": true, "rects": [[x0, y0, x1, y1]]},
      "file": "/api/v1/enterprise/spaces/<sid>/releases/<rid>/sources/<kid>/attempts/<n>/file"}}
    ```

    处理：取 `EvidenceAt` → 非 `PDF_TEXT_SPAN` → `EVIDENCE_UNSUPPORTED` → `Sources.Span` → 页集指纹与引文必须分别等于 evidence 的
    `file_sha256` 与 `quote`，否则 `EVIDENCE_MISMATCH`（不打开相似文本、不跳第 1 页）。
  - `GET /api/v1/enterprise/spaces/:space_id/releases/:release_id/sources/:knowledge_id/attempts/:attempt/file` → 200
    `application/pdf`：该 `(knowledge, attempt)` 必须被该 Release 某个成员的 `evidence_refs` 引用（取其中的指纹），否则 404
    `SOURCE_NOT_FOUND`，且不读取文件；经新依赖 `Deps.Files` 打开文件：

    ```go
    // SourceFiles opens the original file of a knowledge in the request Space's RAW KB and returns
    // its file name. A knowledge outside that KB, deleted, or unknown returns source.ErrNotFound.
    type SourceFiles func(ctx context.Context, scope source.Scope, knowledgeID string) (io.ReadCloser, string, error)
    ```

    最多读 `256 MiB`（超出即 409 `SOURCE_INTEGRITY`），sha256 必须等于引用指纹，否则 409 `SOURCE_INTEGRITY`；核对通过后才写响应：
    `Content-Type: application/pdf`、`Content-Disposition: inline` 带 RFC 5987 UTF-8 文件名、`ETag` 为带引号的指纹、
    `Cache-Control: private, max-age=3600`。`source.ErrNotFound` → 404 `SOURCE_NOT_FOUND`；其他错误 → 503 `SOURCE_UNAVAILABLE`。
- 请求参数：`member` 缺失、`evidence` 不是非负整数、`attempt` 不是正整数 → 400 `INVALID_REQUEST`。
- 错误映射：`MEMBER_NOT_FOUND`、`EVIDENCE_NOT_FOUND`、`SOURCE_NOT_FOUND` → 404；`EVIDENCE_MISMATCH`、`SOURCE_INTEGRITY`、
  `PARSE_ARTIFACT_NOT_CAPTURED` → 409；`EVIDENCE_UNSUPPORTED`、`EVIDENCE_UNVERIFIABLE`（提交时）→ 422；`SPAN_OUT_OF_RANGE` → 409；
  其余沿用现有映射。响应不含 RAW KB ID、存储路径或后端诊断。

### 3.5 装配

- `releasestore.Production(db, knowledge, rawSpaces, contractsDir string, pages PageReader, reserved ...)`：另读
  `evidence.schema.json`；`pages` 非空时 `release.WithEvidenceVerifier(NewEvidenceVerifier(spaces, pages))`。
- `releasestore.Register`：用 DI 中的 `*service.G3FirstParseStore` 与 `interfaces.KnowledgeRepository` 构造只认企业 Space 的
  `source.ArtifactStoreFunc`（与 `router.registerEnterpriseRoutes` 的企业分支相同，不含 G3 回落），再 `source.NewService` 作为
  `pages`。
- `router.registerEnterpriseRoutes`：`Deps.Files` 为闭包——`params.EnterpriseSpaces.Scope` 取该 Space 的 RAW KB，`KnowledgeRepository.GetKnowledgeByID` 核对知识属于该 KB 且未删除（否则 `source.ErrNotFound`），再调用 `params.KnowledgeService.GetKnowledgeFile`。未配置企业 Space 时一律 `source.ErrNotFound`。

### 3.6 不在本片

证据、来源固定（2b-1）、Agent 引用。
