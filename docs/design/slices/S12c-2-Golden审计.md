# S12c-2 · Golden v2 证据审计（独立评委）

> 依据：#390 的诊断——编译器"漏选"的 257 个 Golden 段落中，评委判定 156 个（61%）根本不含该字段的内容；1828 的覆盖类字段得 0 分，原因是 Golden 只引了说明书和列表引导句，而编译器正确选中的条款原文不在 Golden 里。Golden 不准，段落召回与精度就衡量不了编译质量。

## 1. 目标

让 Golden v2（1814、1816、1824、1826、1828 五款）的证据段落只包含真正写有该字段内容的原文，并补上漏掉的条款原文。字段的 state 与 value 本次不改。

## 2. 两类判定

对每个 state 为 present 或 absent_explicitly 的字段，同一会话内逐段判定：

1. **删除审计（keep / drop）**：该字段现有的每个证据段落。只有在段落没有写本字段内容时才 drop，包括：只有标题或编号、文件抬头、目录、"详见"导航句、字段卡 excludes 的内容、其他字段的内容、残缺碎片。absent_explicitly 字段据以判定"不适用"的原文保留。
2. **补充审计（add / skip）**：#390 基线重跑（A0r）中编译器为该字段选中、而 Golden 没有的段落。只有在段落写有本字段 includes 范围的内容、且不属于 excludes 时才 add。

以下段落固定不判、原样保留：
- S4i 的 widened 段落（受保护测试要求保留）；
- 费率表表头证据（只有交费期间可以引用，见用户 2026-10-18 裁定）。

补充审计不考虑以下段落：
- 费率表；
- 与已有证据近乎重复的段落（评分时已经按副本计分）；
- S12b 已判出 Golden 的同一字段段落。

评委规则全文与请求哈希都留在仓库外的运行目录，PR 中写明位置。

## 3. 写入规则

- 只删除判为 drop 的段落、只加入判为 add 的段落，其余证据顺序不变，新增段落按阅读顺序排在后面。
- 字段删空且没有新增时，该字段整体保留原证据，列入待裁决清单。
- 所有文件一起写入，或一个都不写。manifest 更新文件哈希，并追加一条修订：
  - `method: judge-golden-audit`；
  - 卡片版本；
  - 每款产品的审计段数、候选段数、drop 与 add 清单、待裁决字段、评委对 state/value 的疑问（只记录，不改）；
  - 模型、推理强度、各会话 ID。

## 4. 验收

`harness/tests/eval/test_golden_audit.py`（受保护，在数据提交之前单独提交）：
- 修订恰好一条、覆盖五款产品，记录完整；
- 记录为 drop 的段落已不在 Golden，记录为 add 的段落都在 Golden；
- 没有删掉任何 widened 段落；
- 没有加回任何 S12b 已删的段落；

现有的 Golden 数据测试（文件哈希、段落编号与原文一致、state 计数）照常通过。
