# S4c-2b-1 · 发布固定来源：只固定已发布版本引用的原文，旧版本手动退役后解锁

> 状态：用户已定方向（2026-10-16：方案一"激活时固定原文"；旧版本由管理员手动退役） ｜ 作者：Claude Code
> 依据：蓝图 §5.4、§7.4（"打开指定 SourceRevision → 核对 hash"）、§7.5（来源撤回；"历史 Release 中被清除的来源不可服务"）、
> 硬边界 5、7；S4c-2a Spec §3.2；2026-10-16 调研（结论摘入 §2）
> 分支：`slice/s4c2b1` ｜ 工作目录：`.worktrees/s4c2b1` ｜ 实现方：Codex（Go 平台、持久化、并发） ｜ 审核方：Claude

S4c-2b 拆为两片：**2b-1 本片（固定与退役）**、2b-2 证据逐字回验与回跳接口（Claude 实现，并行）。

## 1. 目标

已发布知识的每条引用都必须能打开原文，回滚到旧版本也一样（蓝图：已发布事实来源回跳 100%）。用户决定：

1. 激活一个 Release 时，把它（含继承成员）引用的每个来源修订（knowledge + parse attempt）**固定**：固定期间该文档不能删除、
   不能重新解析、所在 KB 不能删除、源文件绑定不能解除；
2. 旧版本默认一直可回滚、引用一直有效；管理员把不再需要的旧版本（非 Active）**退役**后，它引用的来源若不再被任何未退役版本
   引用，自动解锁；
3. 删除被拒时能查到是哪些版本在引用（来源固定查询接口）。

同时纠正现状缺陷（§2）：今天每个 PDF 修订一提交就被永久固定，导致没有被任何版本引用的文档也删不掉、不能重新解析（S4c-2c 的存量回填
方式因此失效），非 PDF 文档提交直接失败。

## 3. 设计

### 3.1 提交只登记、不固定（`repository/knowledge.go`）

- `pinRevisionSourceLocked` 改为只登记（建议改名 `recordRevisionSourceLocked`）：对 `resource://` 且 `application/pdf` 的持久资源，
  现有完整性检查全部保留（绑定唯一、租户、大小、摘要回填与漂移），写入的行 `retention_state='released'`、`released_at` 为提交时间；
  其他文件（非 PDF、非 `resource://`）**不写来源行、提交照常成功**（非 PDF 的来源修订在 S11）。
- 封存即固定：`SealRevisionSourcePageCount`、`SealRevisionSourceBinding` 与管理回填写入封存字段时同一条更新把行设为 pinned、
  `released_at=NULL`；已封存行只由 G3 使用，S7 前保持现状。
- 导出的固定原语（供 releasestore 在自己的事务里调用；不得自行开启事务）：

  ```go
  // RevisionRef names one committed parse attempt of a knowledge.
  type RevisionRef struct {
      KnowledgeID  string
      ParseAttempt int64
  }

  // ErrRevisionSourceUnavailable: a cited knowledge is missing, soft-deleted or deleting,
  // belongs to another tenant, or its attempt has no source row.
  var ErrRevisionSourceUnavailable = errors.New("revision source unavailable")

  // PinRevisionSources locks the cited knowledge rows FOR UPDATE in ascending id order
  // (the lock order of every delete/reparse guard), then their knowledge base rows FOR SHARE
  // in ascending id order, validates every ref (a soft-deleted knowledge base makes its
  // knowledge unavailable), then sets retention_state='pinned', released_at=NULL. All-or-nothing.
  func PinRevisionSources(tx *gorm.DB, tenantID uint64, refs []RevisionRef) error

  // ReleaseRevisionSources sets retention_state='released', released_at=now for the given
  // unsealed rows of the tenant (binding_digest=''). Sealed rows and missing rows are left as is.
  func ReleaseRevisionSources(tx *gorm.DB, tenantID uint64, refs []RevisionRef) error
  ```

- 新查询（KB 删除守卫用）：`func (r *knowledgeRepository) HasPinnedRevisionSourceInKnowledgeBase(ctx, tenantID uint64,
  knowledgeBaseID string) (bool, error)`。
- 新的 KB 删除准入（2026-10-16 修订，见 §3.4）：`func (r *knowledgeRepository) DeleteKnowledgeBaseUnlessPinned(ctx,
  tenantID uint64, knowledgeBaseID string) error`，加入 `interfaces.KnowledgeRepository`。一个事务内：`FOR UPDATE` 锁该 KB 行
  （未软删、属于该 tenant，否则返回 KB 不存在的既有错误）→ 统计该 KB 下知识的 pinned 来源行，非零返回 `ErrResourcePinned` →
  按与现有 KB 软删完全相同的方式软删该 KB 行。全局加锁顺序：知识行 → KB 行 → 来源行 → Head；本方法只取 KB 行锁、
  其后只读来源行，因此与固定不会成环。

### 3.2 激活时固定（`internal/enterprise/releasestore`）

- `Store.Activate` 在**同一个数据库事务**内：先从 `w.Members` 的 `EvidenceRefs` 收集去重的 `(knowledge, attempt)`（只认
  `source:v1:` 格式，S4c-2a 提交时已校验归属与指纹），调 `repository.PinRevisionSources`；再写 Release（复用
  `WikiReleaseRepository.Activate`，可用嵌套事务/保存点或给 `WikiReleaseActivationWrite` 增加事务内钩子，二选一并说明）；再写
  `enterprise_release_sources`。任一步失败整体回滚，Head 不变。
- 引用的文档已删除、正在删除、或该 attempt 没有来源行 → 新错误码 `SOURCE_UNAVAILABLE`（HTTP 409），什么都不写。
- 同一 Nonce 重放仍按 S4c-2a 提前返回已提交的 Release，不重复固定。
- 引用为空的 Release 不写固定行。

### 3.3 退役与固定查询

- `internal/enterprise/release` 新增可选端口（不改 `Publisher`，S4c-2a 的验收与夹具不变）：

  ```go
  // Retirement records that a non-active release is no longer a rollback target.
  type Retirement struct {
      ReleaseID string    `json:"release_id"`
      Reason    string    `json:"reason"`
      Subject   string    `json:"subject"`
      RetiredAt time.Time `json:"retired_at"`
  }

  // SourcePin names a non-retired release that cites a knowledge of the Space.
  type SourcePin struct {
      ReleaseID    string `json:"release_id"`
      ParseAttempt int64  `json:"parse_attempt"`
      Active       bool   `json:"active"`
  }

  // RetirementWrite is what Service.Retire hands to the Retirer.
  type RetirementWrite struct {
      TenantID  uint64
      SpaceID   string
      ReleaseID string
      Reason    string
      Subject   string
  }

  // Retirer retires releases and lists source pins. Retire is idempotent: retiring an
  // already retired release returns the original Retirement. It must refuse the
  // Space's active release with ErrorReleaseActive inside its own transaction.
  type Retirer interface {
      Retire(ctx context.Context, w RetirementWrite) (Retirement, error)
      SourcePins(ctx context.Context, tenantID uint64, spaceID, knowledgeID string) ([]SourcePin, error)
  }

  func WithRetirer(r Retirer) Option

  func (s *Service) Retire(ctx context.Context, p Principal, spaceID, releaseID, reason string) (Retirement, error)
  func (s *Service) SourcePins(ctx context.Context, p Principal, spaceID, knowledgeID string) ([]SourcePin, error)
  ```

  - 校验顺序：权限同发布（`checkAccess`，再要求 Store、Publisher 与 Retirer 都已配置，否则 `SERVICE_UNAVAILABLE`）；`releaseID`
    空白 → `RELEASE_NOT_FOUND`；`knowledgeID` 空白 → `INVALID_REQUEST`；`reason` 去掉首尾空白后为空或超过 500 个字符（按 Unicode
    码点计）→ `RETIREMENT_INVALID`。交给 Retirer 的是去掉首尾空白后的理由，Subject 取 `p.Subject`；以上失败都不调用 Retirer；
  - 服务层先读 Head：`releaseID` 等于当前 Active → `RELEASE_ACTIVE`（409），不调用 Retirer；Store 在事务内再核对一次（并发激活）；
    Retirer 返回的 `*release.Error` 原样返回，不改码；
  - 新错误码（与现有常量同在 `publish.go` 的常量块）：`ErrorReleaseActive = "RELEASE_ACTIVE"`、
    `ErrorRetirementInvalid = "RETIREMENT_INVALID"`、`ErrorSourceUnavailable = "SOURCE_UNAVAILABLE"`（§3.2）、
    `ErrorInvalidRequest = "INVALID_REQUEST"`，都加入 Mount 的错误映射。
- `Store` 实现 `Retirer`：
  - `Retire` 事务：锁该 Release 引用的知识行（升序）→ 确认 Release 属于该 tenant/Space 且不是 Head（否则 `RELEASE_NOT_FOUND` /
    `RELEASE_ACTIVE`）→ 写 `enterprise_release_retirements`（`release_id` 唯一；已存在则原样返回）→ 删除它的 `enterprise_release_sources`
    → 对其中不再出现在任何 `enterprise_release_sources` 行里的 `(knowledge, attempt)` 调 `repository.ReleaseRevisionSources`；
  - `SourcePins`：该 Space 中引用该 knowledge 的未退役 Release（含 Active 标记），按 release_id 排序。
- `release.Release`（`publish.go`）增加 `RetiredAt *time.Time`（json `retired_at,omitempty`）：读回已退役 Release 时给出退役时间；成员照常可读
  （历史读取），其引用的原文不再受固定保护。
- 路由（`internal/enterprise/mount.go`，策略同 candidates：全权限且不限 KB 的服务密钥）：
  - `POST /api/v1/enterprise/spaces/:space_id/releases/:release_id/retirement`，body `{"reason": "..."}` → 200 `Retirement`；
  - `GET /api/v1/enterprise/spaces/:space_id/sources/:knowledge_id/pins` → 200 `{"pins": [SourcePin...]}`。
- 装配：`releasestore.Register`/`Production` 让同一个 `*Store` 同时作为 Publisher 与 Retirer（`release.WithRetirer`）。

### 3.4 删除守卫补全

- `DeleteKnowledgeBase`：用 `DeleteKnowledgeBaseUnlessPinned` 替换原来的 KB 软删，并作为第一个副作用；它返回
  `ErrResourcePinned` 时映射为 `ErrKnowledgeRevisionSourcePinned`，KB 与其余状态都不变；清任务、组织共享、异步删除只在它成功后执行。
  **并发**（2026-10-16 修订）：两个只读预检无法阻止"检查为假 → 激活固定 → 删除"的交错。KB 行锁使"确认无固定 + 软删"与固定互斥：
  先提交的一方生效，另一方被拒（删除得到 409，或激活得到 `SOURCE_UNAVAILABLE`）；KB 软删后，其知识不能再被固定，异步清理不会
  遇到新固定。若现有 KB 软删除了置 `deleted_at` 还有其他效果，实现方在 Issue 中报告，不自行取舍。
- `internal/handler/knowledgebase.go` 的 KB 删除错误分支：识别 `ErrKnowledgeRevisionSourcePinned` 返回 409 Conflict（2026-10-16 修订；
  原来所有错误都被包成 500，无法兑现上一条）；其余 Handler 不动。
- `ProcessKBDelete`：在删除向量、chunk、图谱、文件之前同样检查，为真则不做任何删除并以不可重试的方式结束该任务（记录原因），避免
  "先删向量再被挡住"的部分删除。
- `DeleteBinding`：解除 `relation='source_file'` 且该知识存在 pinned 来源行的绑定 → `ErrResourcePinned`。
- 其余入口（单个/批量删除、重新解析、文件删除）沿用现有守卫，行为随 §3.1 自动变为"只挡被固定的"。

### 3.5 迁移 `migrations/enterprise/versioned/000007_release_source_pins`

- up：
  - `enterprise_release_sources(tenant_id BIGINT, space_id TEXT, release_id TEXT, knowledge_id VARCHAR(36), parse_attempt BIGINT,
    created_at TIMESTAMPTZ, PRIMARY KEY (release_id, knowledge_id, parse_attempt))`，索引 `(tenant_id, knowledge_id)`；
  - `enterprise_release_retirements(release_id TEXT PRIMARY KEY, tenant_id BIGINT, space_id TEXT, reason TEXT, subject TEXT,
    retired_at TIMESTAMPTZ)`；
  - 纠正存量：`UPDATE knowledge_revision_sources SET retention_state='released', released_at=now(), updated_at=now()
    WHERE retention_state='pinned' AND binding_digest=''`（未封存的提交期固定全部解锁；已封存的 G3 行保持 pinned）。
- down：删两表；`UPDATE ... SET retention_state='pinned', released_at=NULL WHERE retention_state='released' AND binding_digest=''`
  （回到"提交即固定"，偏保守）。
- `packagedEnterpriseMigrationHead` 6 → 7。
- 迁移之前激活的企业 Release（只存在于测试库与即将进行的本机演示）没有固定行；对它们，下一次激活会按完整成员集重新固定。
