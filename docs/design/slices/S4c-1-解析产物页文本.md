S4c 拆为两片：本片（S4c-1）只让 Harness 从 WeKnora 读到与本地 pdfium 完全一致的逐页原文；S4c-2 再做受管范围的解析产物
必存、新 CandidateBundle 的发布桥接与引用回跳。

## 1. 目标

S4d 的指针抽取需要逐页原文：分段编号、证据切片与将来的字符框回跳都以"页内 Unicode 码点偏移"为准。现在 Harness 自己用
pypdfium2 读本地 PDF；蓝图要求页文本来自 WeKnora 的解析产物（唯一的 SourceRevision/ParseArtifact 权威）。本片提供：

1. WeKnora 只读接口：按 `knowledge_id + parse_attempt` 返回该修订的逐页原文与身份（文件指纹、解析器身份、产物指纹）；
2. Harness 读取端：把接口结果转成编译器使用的 `PageText`，逐页回验 hash；
3. 两端码点一致：同一份 PDF，接口返回的页文本与 Harness 本地 `read_pdf` 逐字相同，S4d 的段落编号不变。

## 2. 现状（调研结论，路径为 `main@22ba260bc`）

- docreader 在 native capture 分支用 pypdfium2 `get_text_range()` 取整页原文（不 strip、不改换行），页间以 `\n\n` 拼成全文；
  `NativeStructure.SanitizedJSON.pages[]` 记录 1 起页号、`global_codepoint_start/end`（不含分隔符）与 `page_text_sha256 = sha256(页文本 UTF-8)`。
  依据：`docreader/parser/pdf_parser.py:1650–1704`、`internal/infrastructure/docparser/grpc_parser.go:53–65`。
- 解析结果（全文 + NativeStructure）存于 `g3FirstParseRecord`（本地签名 sidecar），读取函数为私有 `readFirstParse`；仅 G3 platform
  processing 范围内的 PDF 会保存。依据：`internal/application/service/g3_first_parse.go:36`、`:60`、`:103`。
- 没有通用的按修订读取逐页文本的 REST 接口；旧 G3 snapshot 是 POST、仅当前修订、隔离权限链。新 enterprise 模块已有 `Mount`
  与全权限服务密钥策略，但未接入生产路由。依据：`internal/router/routes_g3_platform_snapshots.go:68`、`internal/enterprise/mount.go:24`。

## 3. 设计

### 3.1 Go：`internal/enterprise/source`（新包）

- `ArtifactStore` 接口：`Load(ctx, Scope, knowledgeID, attempt) (*Artifact, error)`；`Artifact` 含 `KnowledgeID`、`ParseAttempt`、
  `FileName`、`FileSHA256`、`ParserIdentitySHA256`、`Markdown`（全文）与 `NativeJSON`（SanitizedJSON 原字节）；找不到返回 `ErrNotFound`，
  该修订未保存解析产物返回 `ErrNotCaptured`。**读取时不得补解析**。
- `Service.Pages(ctx, Scope, knowledgeID, attempt) (*PageSet, error)`：
  - 输入校验（空 knowledge_id、attempt ≤ 0 → `INVALID_REQUEST`，不访问 store）；
  - 从 `NativeJSON.pages[]` 读页号与码点区间，以 **rune（码点）** 切 `Markdown` 得到页文本，原样返回（不改换行、不 strip）；
  - 页号从 1 连续递增、区间单调不重叠且不越界、`sha256(页文本 UTF-8) == page_text_sha256`，任一不满足 → `PARSE_ARTIFACT_INTEGRITY`；
  - `PageSet` 带 `knowledge_id`、`parse_attempt`、`document`（文件名）、`document_sha256`、`parser_identity_sha256`、`native_sha256`
    （`sha256(NativeJSON)`）与 `pages[{page_number, text, page_text_sha256}]`。
- 错误为 typed `*source.Error{Code, Detail}`：`INVALID_REQUEST`、`SOURCE_NOT_FOUND`、`PARSE_ARTIFACT_NOT_CAPTURED`、`PARSE_ARTIFACT_INTEGRITY`、
  `SOURCE_UNAVAILABLE`（store 其他错误；Detail 不含路径与内部信息）。
- 生产 `ArtifactStore`：在 `internal/application/service` 增加导出的只读方法，复用 `readFirstParse` 与 `validateG3FirstParse`，并核对
  Knowledge 属于 Scope 的 tenant；不复制、不改动签名封装与写路径。
- 路由：`enterprise.Mount` 增加 `GET /sources/:knowledge_id/attempts/:attempt/pages`，策略同 candidates（全权限服务密钥）；
  在生产路由注册 enterprise 分组 `/api/v1/enterprise/spaces/:space_id`（candidates 路由随之上线，行为不变）。HTTP 映射：
  400 / 404 / 409 / 500 / 503，错误体 `{success:false, code, error}`。

### 3.2 Harness：`evidence/weknora_pages.py`（新模块；旧的 `sources/` 包属 OpenSpec 017，S7 清理，不再扩展）

- `WeKnoraSourcePages(base_url, api_key, transport=None)`：`pages(space_id, knowledge_id, attempt) -> list[PageText]`，
  请求 `GET {base_url}/api/v1/enterprise/spaces/{space_id}/sources/{knowledge_id}/attempts/{attempt}/pages`，头 `X-API-Key`，响应体为 `PageSet` JSON
  （`eval/pdf_text.PageText`：`document`、`document_sha256`、`page`、`text`）；逐页重算 sha256 并与 `page_text_sha256` 比对，不符或缺页抛
  `SourcePagesError`；HTTP 错误按 code 抛同一异常类（消息只含 code，不含响应正文）；只在边界做一次显式转换。
- `eval/pdf_text.read_pdf` 改为**原样**保留 `get_text_range()` 的文本（删除 `\r\n`→`\n` 替换），使本地页文本与 WeKnora 页文本逐码点一致；
  `SegmentedSource` 的分段与编号不受影响（`splitlines` 把 `\r\n` 视为一个换行）。

### 3.3 不在本片

受管范围的解析产物必存与回填、Source lifecycle event、Evidence locator 写入码点区间、CandidateBundle 发布桥接与引用回跳（S4c-2）。
