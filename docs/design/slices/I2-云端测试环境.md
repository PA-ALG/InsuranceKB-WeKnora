# I2 云端测试环境

> 状态：Spec 草稿（2026-10-30，Claude）。**阻塞于用户资源**（见 §5）。实现方 Claude，审核方 Codex。
> 蓝图 §9「构建与部署」：开发阶段沿用现有阿里云配置；§11 I2：云上环境按 digest 拉取部署，附回滚步骤；Mac 不再作为唯一运行环境。
> 依赖：I1（CI 镜像，按 digest 拉取）。真实调用：环境冒烟 ≤ 5 次 DeepSeek。

## 1. 为什么现在做

2026-10-28～30 本机运行环境出了四类故障，每次都让线上中断或阻塞：Docker 数据盘写满（带密钥请求 401）、
DeepSeek 余额耗尽（问答失败）、colima 非正常停止后磁盘锁残留（线上停机约数小时）、外置盘句柄丢失（10-27）。
线上环境只有一台 Mac 是最大的单点。

## 2. 现状（本机线上环境，只读盘点）

| 组件 | 现在 |
|---|---|
| 运行 | colima（外置 SSD 上的 192G 数据盘）；容器 `…-live-{pg,redis,docreader,app,ui}`，无重启策略，停机后需手动按序拉起 |
| 数据库 | ParadeDB（pg17 + pg_search）；App 库约 3.5 GB；官方迁移账本 110（U-1 后 134）、企业迁移账本 12 |
| 卷 | pg 数据、redis 数据、原文件（`/data/files`）、docreader 临时目录、c5 运行目录 |
| 配置 | `config.yaml` 与 `contracts/` 绑定挂载；数据库、Redis、JWT、AES 等密钥以环境变量注入（**模型密钥在库内以 `SYSTEM_AES_KEY` 加密保存**） |
| 模型 | 问答 DeepSeek 官方 API；embedding、rerank、VLM 走阿里云 DashScope（百炼）；另有一个自建 VLM/问答端点 |
| 入口 | UI 容器 80 → 本机 18295；API 经 UI 反代 |
| Harness | 本机 Python CLI（uv venv），读 `HARNESS_WEKNORA_*`、`HARNESS_LLM_*` 等环境变量；登记表、运行目录在本机 |
| 评委 | GPT-6 Astra 经本机 `codex exec`（需要用户的 Codex 登录），**不随环境上云** |

## 3. 目标拓扑

- **一台阿里云 ECS**（与 DashScope 同地域，降低延迟与出网费用），Docker + compose。
- `deploy/cloud-test/docker-compose.yml`（新，我们自有）：`pg`（ParadeDB 固定 digest）、`redis`、`docreader`、`app`、`ui`、`harness`（CLI 容器，按需 `docker compose run`），**镜像全部按 digest 引用**（来自 I1）；`restart: unless-stopped`（解决本机"停机后手动拉起"）。
- 数据卷放云盘；pg 用独立云盘便于快照。
- 入口：只对白名单 IP / 堡垒机开放 UI 端口；不开放数据库与 Redis 端口。需要域名与 TLS 时用 nginx/caddy 在 UI 前终止 TLS（成熟方案，可选）。

## 4. 数据、密钥与运维

1. **数据初始化（推荐：从本机线上恢复）**：`pg_dump -Fc` App 库 + 原文件卷打包 → 云上 `pg_restore` + 解包 → 启动 App
   （迁移按账本自动推进）→ 核对 Active epoch、成员数、成员摘要与本机一致。备选：空库 + Harness 重编发布（要 DeepSeek 与评委预算，不推荐首批）。
2. **密钥**：云上 `.env`（root 600）由用户在 VM 上放置，不进仓库、不进镜像、不进日志。**恢复库内加密的模型密钥需要与本机相同的
   `SYSTEM_AES_KEY`**；若用户不愿迁移该密钥，就在云上用新密钥并在 UI 重新录入模型密钥（推荐，云上用独立的 DeepSeek / DashScope 密钥与额度）。
3. **部署与回滚**：`deploy/cloud-test/images.lock`（digest 清单）是唯一版本来源；换版本 = 改 lock + `docker compose up -d <svc>`；
   回滚 = 改回上一版 lock。迁移前先 `pg_dump`；企业迁移有 down SQL 时才允许回滚迁移。
4. **备份**：每日 `pg_dump` + 原文件卷增量到对象存储（OSS），保留 7 天；每周云盘快照。
5. **监控**：容器健康检查 + 磁盘使用率告警（≥ 85%）+ 模型余额/401 探测（每小时一次只读健康检查，不调模型）。
6. **与本机关系**：云上成为测试主环境；本机保留开发与评委（`codex exec`）。Harness 线上写入改为对云上 base URL。

## 5. 需要用户提供（阻塞项）

1. **云账号与机器**：确认“现有阿里云配置”指的账号/资源；批准开一台 ECS（建议 8 vCPU / 32 GB / 系统盘 100 GB + 数据云盘 200 GB ESSD，
   x86_64；或倚天 arm64 同规格——I1 两种架构都出镜像），与 DashScope 同地域。粗估月费用约 ¥1,500–2,500（按量/包月不同，以阿里云报价为准）。
2. **访问方式**：哪些 IP / VPN 可访问 UI；是否需要域名与 TLS 证书。
3. **模型密钥**：云上用的 DeepSeek API key（建议独立账户与额度）、DashScope key；是否迁移 `SYSTEM_AES_KEY`（见 §4.2）。
4. **镜像拉取**：GHCR 包设为 public，或提供只读 PAT 给 VM。
5. **数据外发确认**：同意把本机线上库与原文件（当前为公开产品材料与评测数据；不含 S11 私有样本）复制到云上。
6. **出网**：VM 可访问 `api.deepseek.com`、`dashscope.aliyuncs.com`、`ghcr.io`（以及备份用的 OSS）。

## 6. 验收

1. compose 按 digest 起全部服务；`restart: unless-stopped` 下重启 VM 后服务自动恢复。
2. 从本机恢复的数据：Active epoch / 成员数 / 成员摘要与本机一致；官方与企业迁移账本正确。
3. 冒烟：健康 200；API key 读 Active；1 次快问快答（DeepSeek）；Harness `publish_navigation --dry-run`；≤ 5 次模型调用。
4. 回滚演示：换一个旧 digest 再换回，服务与数据不变。
5. 备份恢复演示：从最近一次备份恢复到临时库并核对 Active。
