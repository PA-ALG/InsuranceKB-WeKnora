冻结；Refs #552 第2部分；实现 Codex、审核 Claude。

## 1. 允许范围

TrustPolicy `2026-11-05.1` 分别保存 header_rules、note_rules、scoped_rules。
rate_table 表头仍只服务 premium_payment_term；新增 note_rules 仅服务
premium_payment_term、premium_payment_frequency。note 起始标记是版本化数据
“注”“注释”“说明”，必须有冒号（含全角），可带注编号。其他角色、字段与
数值正文不因本片得到授权。旧策略缺 note_rules 视为空；重复/无效规则拒绝。

## 2. 页内范围与失败关闭

保持原 header_block 算法与数字行标准（至少两个数值 token）。新解析按每物理页
原始文本偏移扫描，只允许数字表最后一行后**紧接**的标记行开始注释，空行、正文
或标题隔开则不能起始。只处理该页第一张数字表之后的注释，不从第二张表再次开启。

连续范围：标记行、紧接的编号注释项、缩进续行；无缩进折行仅在上行没有句末终止
标点且本行不是新标题/数字行时继续。上行已经结束后出现无标记/无编号/无缩进正文
即停止。空段、新章节/产品或表格标题、下一数字行终止，不跨页、不跨 Office block，
不拼接零散段。版式无法证明连续时不信任。标题识别仅用通用版式及版本化标题词尾，
没有产品号、产品名或固定样本特判。仅标记而无正文不构成注释。

保留 PDF/Office 原位置、字符和 SHA；header/note 各自独立分段。相邻 segment ID
并不表示原文连续：证据合并不能跨 header→note 间的数字行或两个原文范围。
carry/旧引文定位若跨未信任间隙不得仅凭与合法段部分重叠而采用。

## 3. 全链路信任

SegmentedSource 对每段记内部信任范围（不改公开 Segment/合同），统一公开逐段
permission 判定供选段主抽/后抽、carry、reviewed、claims_from 和评分使用。
frequency 能用 note，不能用 header；term 可用两者；其他字段两者均拒绝。既有
scoped 角色保持整文且限字段。发布重新验证保存段号/引文及逐段许可，不能通过伪造
output 或把表头和注释拼成一条 Evidence 引入数字正文。

评分仅接受该字段合法段；carry/recall 仍不计第一步选段分母。Golden remap 不得将
新增 note 当作 header 自动恢复或把历史表头引用扩到注释；只修该范围判定，不写
Golden 文件、不重评或重编任何真实材料。

## 4. 身份与写域

注释改变生产可见证据与段号范围。VALUE_PROTOCOL_VERSION 升至 `2026-11-05.1`
作为管线身份（提示词文本不变）；旧 output 不能复用，Claim compiler_version 由
既有协议字段区分，仍经原 UNCHANGED/FILL/CONFLICT/UPGRADE 等条件分支，不一律升级。
replay 的现有 trust_policy 上下文也包含 note_rules；旧请求不能冒充新请求。

写域：catalog/trust_policy.py/json；evidence/segments.py 与新 rate_notes.py；
schema_fields/engine.py、claims.py、prompt.py（仅版本常量/注释）；
eval/segment_score.py、golden_remap.py；本片新增测试及单独披露的旧保护适配。
无材料角色数据、字段卡、平台、合同、守卫基线或 Golden 数据变更，无新增依赖。

需要的保护适配独立提交：原 restricted_fields(rate_table) 集合增加 frequency，
header_fields 断言原样；旧协议版本期望更新。不得为注释测试改弱原表头/数字正文、
角色冲突、评分或来源身份断言。新 RED 冻结后不在实现提交修改。
