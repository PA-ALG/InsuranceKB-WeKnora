# RV6a · 只写"材料未提及"的值按未知处理

> 状态：Claude 2026-10-27 提出 ｜ 作者：Claude Code
> 依据：
> - 用户 2026-10-27 在线上审核页看到，594 的"直付与垫付"字段值是"材料未提及医疗费用直付、住院费用垫付或理赔款预付服务。"，状态却是"有值"，变更类型是补充（FILL），进入了人工审核。用户决定：值只说明材料没有提到的，按未知处理，不送审；
> - 调研（2026-10-27，s5b4-first 的 20 个产品、566 个有值字段，不调用模型）：
>   - 44 个值含"材料未载明/材料未提及…"一类说法，其中 43 个同时写了原文事实（如"1. 通知时限：10 日内通知。2. 诉讼时效：材料未载明。"），这些必须保持有值；
>   - 整个值只说"材料没有提到"的只有 1 个，即上面 594 那一个；
>   - 有一个条款原文"未约定定点医院的，则指……"没有主语，是条款内容，必须保持有值；
> - 根因：第一步选段时选了"有值"，第二步只看选中的段落写值，提示词要求"value 始终是一个非空字符串"（`prompt.py`），不能回答"未知"，于是写成"材料未提及……"；
> - 蓝图 §5.1：未知（unknown）表示材料没有说明，不带值。
>
> 实现方：Claude ｜ 审核方：**Codex** ｜ 真实模型调用：0

## 1. 目标

编译组装字段结果时，如果某个"有值"字段的值，每一句都只是在说"材料没有写明某事"，就把它改为"未知"（不带值、证据和段落），与第一步直接选"未知"的结果完全相同。

只在一处生效：`SchemaFieldsCompiler.compile` 组装结果时，在规范化值之前判断。这样 `output.json`、评测、审核打分和发布看到的是同一个结果。

## 2. 规则（版本化数据）

新增 `harness/src/insurance_harness/catalog/non_mention_policy.json`（版本 `2026-10-27.1`）与严格加载器 `catalog/non_mention_policy.py`，写法同 `trust_policy`：

| 键 | 内容 |
|---|---|
| `subjects` | 主语：材料、本批材料、给定材料、所给材料、现有材料、原文、条款、段落 |
| `connectors` | 主语后可选的连接字：中、内、均（可连用） |
| `negations` | 否定：未、没有、并未 |
| `verbs` | 动词：提及、载明、约定、说明、明确、列明、列示、涉及、写明、规定 |
| `continuations` | 出现即说明后面还有内容的词：仅、但、依据、只 |
| `label_max_chars` | 句首标签的最大长度：20 |

判断"只说明未提及"（`NonMentionPolicy.only_non_mention(value)`）：

1. 先做 NFKC 规范化（全角标点变半角）；
2. 按"。"、";"、换行切成句子，去掉空句；没有句子时不算；
3. 每句先去掉句首编号（如 `1.`、`2.1`、`(1)`、`1、`），再去掉不超过 `label_max_chars` 字、不含逗号、以":"结尾的标签（如"诉讼时效："）；
4. 每句都必须以"主语 + 连接字（可无）+ 否定 + 动词"开头；动词后面是"没有写明的对象"，其中不能再有逗号、冒号或 `continuations` 中的词（有就说明还有别的内容）；
5. 全部句子都满足才算。只要有一句写了原文内容，整个值保持有值。

规则宁可漏判：漏判的值维持现状（进入审核，由人拒绝），不会误删原文事实。

加载器拒绝：缺版本或空版本、任一列表为空、列表含空串或重复项、词语不是 NFKC 规范形式或含句子分隔符、`label_max_chars` 不是 1–40 的整数、多余的键、不是 JSON。错误只报稳定的错误码 `NON_MENTION_POLICY_INVALID`。

## 3. 记录版本

`CompileOutput` 新增 `non_mention_version: str | None = None`，编译时写入规则版本。之前写的输出读出来是 None，照常可以加载。这不改 `contracts/`：`CompileOutput` 是 Harness 内部的编译结果，不是对外合同。

输出复用的条件（`ingest/publication.py`、`eval/compile_run.py` 按材料与卡片版本判断）不变。规则只会删掉没有内容的值，为它重新编译要真实调用模型，不划算。因此 RV6a 之前写的输出保持原样，直到下次重新编译。

## 4. 不在本切片

- **根因不在这里修**：要让第二步也能回答"未知"，需要改提示词和输出格式，并用真实调用验证。这类值出现的频率是 1/566，现在不做。卡片里"（原因：材料未提及）"一类的写法也留着。
- **已经提交的 594/596 两个字段**：在 RV6b 的逐字段审核里由人拒绝，不在这里处理。
- **混在有内容的值里的"某项材料未载明"**（如"诉讼时效：材料未载明"）：保留。这是 `extraction_profiles.json` 有意要求的写法。
