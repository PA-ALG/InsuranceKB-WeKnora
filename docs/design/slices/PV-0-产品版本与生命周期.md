## 0. 背景与裁定

批次一接入与 Office 端到端时暴露出：我们的产品登记没有“版本、年份、销售期、在售/停售”的概念，而业务材料
（尤其销售与培训材料）通常只写“产品品牌 + 年份”。已定方向（本 Spec 不再重新请求确认）：

1. **培训材料与产品严格按年份/版本对应**（用户）："这个是严格对应的年份的"。例：一份 2024 年的税优护理险培训材料，
   只能对应 2024 年在售的那个版本（2635-1 平安智盈倍护终身护理保险），不能挂到 2648-1 平安智盈倍护（2026）终身护理保险。
2. **方案 A**（用户）：培训材料按“品牌 + 年份/日期”只匹配到**唯一**一个已登记版本、日期信号明确且一致、类型词不冲突时，
   **自动归属**，记为机器结论；否则交人并附候选与依据。修订 S11c §2.5 第 4 条“即使只有一个候选也不自动归属”。
3. **版本唯一但角色识别不出时只问角色**；PV-3 同时补培训材料的角色信号（数据）（Owner）。
4. **Office 端到端等 PV-3**：PV-3 之前只登记 2635-1 的条款、说明书、费率表；培训材料由 PV-3 按方案 A 挂接，同时验收方案 A；
   不再让用户为它手选（Owner）。
5. **PV-4 全量重发布**：接受，零模型调用，单独 Issue、前后核对 Active、不与编译轮次重叠（Owner）。
6. 既有底线：**内容锚点优先**——条款编号、首页标题与文件夹或清单冲突时以内容为准。仓库确有放错的文件（L3223 文件夹里
   放的是另一款附加门诊急诊医疗险的产品说明书）。“按下载来源清单归属”是提案 #497（S5b-8），不是已合入行为。

## 3. 模型

### 3.1 产品版本（事实与材料的挂载单位）

一个报备版本 = 一个登记条目 = 一个发布实体（`entity_type` 仍为 `product`，见附录 A §1.2）。登记表 v2 字段：

| 字段 | 来源 | 说明 |
|---|---|---|
| `product_id` | 不变 | 内部 ID：种子条目为 planCode，新建条目为 `sc-` + 条款号摘要（确定性），Release slug 依赖它，永不改写 |
| `version_key` | 仓库 `planCode-versionNo` | 外部标识，可空；非空时在登记表内唯一（去重，附录 A §1.3） |
| `plan_code`、`version_no` | 仓库 | 可空 |
| `names`、`clause_codes`、`schema_pack_id` | 不变 | 内容确认的值，同步不覆盖（附录 A §3） |
| `sale_start`、`sale_end` | 仓库 `startDate` / `endDate` | 半开区间日历日，可空；空不等于在售 |
| `year_tag` | 名称解析（数据规则） | 可空 |
| `channel`、`plan_type` | 仓库 | 类型词匹配与展示 |
| `predecessor` | 唯一前驱规则 | 可空（附录 A §1.4） |
| `family_key` | 名称派生（§3.3） | 只用于分组与候选；发布为 Entity 的 `product_family`（附录 A §1.2） |
| `metadata_basis` | 固定的仓库提交、文件路径、同步时间 | 当前元数据的来源；历史判断依据另存于决定记录（§4.4） |

销售状态不存储，读取时按评价日由销售期与来源状态推出：`on_sale`、`discontinued`、`not_yet_on_sale`、`unknown`
（附录 A §3.2）。**销售期不是 Claim 的业务有效期**：蓝图 §5.1 的 `effective_from/to` 指条款对保单的适用期；停售只影响新单
销售，在保客户仍按原版本服务。`sale_end` 永不写入 Claim `effective_to`，停售也不视为来源撤回。

### 3.2 产品编码链

同一 `plan_code` 的版本按附录 A §1.4 的唯一前驱规则串链，发布为 `supersedes` Relation（新 → 旧）。链只表达“谁接替谁”，
不撤回旧版本的知识。前驱不唯一（同名、共用条款号、同起售日的并行版本）时不建链，只报告。

### 3.3 品牌系列（派生，只作分组与候选）

`family_key` 由名称按数据规则派生：沿用 S11c 的品牌核心（去公司名与“附加”“创”等前缀、去全部括号限定、去最长险种后缀，
NFKC 折叠）。它永远不是归属锚点，只用于生成培训材料候选与产品库分组。规则写在归属策略数据中，不写产品编号特判。

## 4. 归属规则

### 4.1 内容锚点优先（不变）

条款编号、首页标题（S5b-1、S5b-5、S5b-7）仍先于一切：材料有自有条款编号或首页标题命中已登记版本时按现有规则判定，
冲突照旧隔离，方案 A 不参与。方案 A 是**仅限培训材料的、已批准的兜底规则**：只在强内容锚点缺失时启用，不适用于条款、
说明书、费率表。文件夹、清单、下载来源只能作辅助证据，不能单独决定归属。

### 4.2 新版本不再替换旧版本（修订 S5b-1）

同名、新自有条款号的条款到达时，新建版本条目（内部 ID 按现规则由条款号确定；外部 `version_key` 从固定提交的清单按条款号
查得，0 个或多个匹配时留空），按唯一前驱规则建 `predecessor`；原条目的材料与已发布知识保留不动；后续说明书、费率表按
内容锚点归属到对应版本。是否“已登记”按附录 A §1.3 的组合匹配表判定：外部键与条款号必须指向同一条目，共用条款号或两者
指向不同条目时失败关闭（隔离并报告），从不合并条目。

### 4.3 培训材料按“品牌 + 年份/日期”归属（方案 A，修订 S11c §2.5 第 4 条）

适用：`brand_roles` 中的角色（销售/培训类）与无法识别角色的 Office 文件，且 §4.1 的强内容锚点缺失。

1. **信号**（只读材料本身，规则为数据）：品牌（文件名或开头窗口含 `family_key` 前缀，S11c 规则不变）；日期信号，每个记
   （值、精度 = 年 / 月 / 日、来源 = 封面或开头窗口 / 落款日期行 / 文件名）；类型词（分红型、万能型、附加、税优、险种词……，
   与版本名称、`plan_type`、`channel` 的矛盾表为数据）。
2. **日期一致性**：所有日期信号必须相互包含（年 2024 包含 2024-05，2024-05 包含 2024-05-27）；任一不包含（如文件名 2023、
   封面 2024）→ 不自动归属，交人并显示各信号。一致时取最精确信号的区间作材料区间 `M`（年 → 整年，月 → 整月，日 → 当日）。
3. **候选全集**（在全部已登记版本上计算，任何展示上限之前）：同一品牌系列中满足下列任一的版本——
   (a) `year_tag` = 材料年份；(b) `M` 与 `[sale_start, sale_end)` 有交集。再去掉与材料类型词矛盾的版本。
4. **一致性校验**：候选 `v` 只有在材料的月或日精度信号全部落在 `v` 的销售期内时才算“一致”（`year_tag` 命中而精确日期落在
   销售期外 = 材料信号冲突，不是合法错位）；合法的“标签年 = 起售年 + 1”由 (b) 销售期覆盖或 (a) 年份标签命中处理，二者不互相
   否定。销售期未知的版本可以是候选，但不能是“一致”的唯一候选。
5. **判定**：全集里恰好一个候选、它是一致的、且没有被月份跨越换版（`M` 只与它一个版本的销售期有交集）→ 自动归属，
   `reason = matched_by_version_period`，机器结论（§4.4 记录依据）。其余情况（零个、多个、不一致、`M` 跨越换版、信号冲突）
   → 交人，页面按依据排序显示候选（展示上限只截断显示，写明“共 N 个”）；零候选时附固定提交清单中唯一匹配的未登记版本
   建议（“可先登记 `planCode-versionNo`”），登记仍走正常接入。
6. **严格对应**：材料从不归属到日期信号与年份标签都对不上的版本，即使同系列只有那一个已登记版本。
7. **角色**：自动归属要求角色已确定在 `brand_roles` 内；PV-3 补“培训/销售”角色信号（封面或标题中的“培训”“学习课程”
   “销售方法”“话术”等，词表为数据）；版本已唯一一致但角色仍识别不出 → 只问角色（§4.4）。

### 4.4 人工入口、依据与回退的闭环

- **展示的候选与可选的选项分开**：页面展示 §4.3 的候选全集作为依据，并逐个标出一致性结论（一致 / 日期冲突 / 类型矛盾 /
  销售期未知）；**可选的选项只包括“一致”的候选**（外加“忽略”）。机器因已知日期冲突或类型矛盾排除的版本只作展示，不能被
  选中；不再提供“任选已登记产品”。人工的作用是在多个一致候选之间做选择，不能用一次选择放开严格的版本约束。
- **日期信号冲突**（材料自身矛盾，如文件名 2023、封面 2024）：不定义材料区间，也不先挑一个日期计算候选——可选选项为空，只能
  “忽略”，页面列出冲突的信号。严格按年份对应不允许违背材料自身（Owner 裁定 2026-11-01）。
- **材料没有任何日期信号**：机器不自动归属。可选选项 = 同一品牌系列中与材料类型词**不矛盾**的全部已登记版本（外加“忽略”），
  每个都标注“材料无日期依据”，并显示其年份标签与销售期；人选择后记为**人工版本决定**（`version_decided_by = person`），依据写明
  “材料无日期信号，由人补充”。理由：严格对应禁止违背材料，但人的业务知识可以补上材料缺失的日期（Owner 裁定 2026-11-01）。
- **应用时重验一致性**：应用答复时（`identity/confirmation.conclude`）以同一材料三元组（knowledge_id、parse_attempt、sha256）、
  当时的策略版本与登记元数据重算：有日期信号的材料，所选版本必须仍是“一致”的候选，而不只是仍在候选全集内；无日期信号的
  材料，所选版本必须仍在上述可选集合内且与类型词不矛盾（材料一旦出现日期信号，按有日期的规则重算）。不满足则问题作废并重新
  提问。正确版本未登记时，人只能忽略或等待登记，不能改选别的版本。
- **只问角色**：问题携带机器已定的版本与依据；答复只设角色；应用时同样重验该版本仍唯一一致。
- **来源分开记录**：决定记录增加不可变依据——策略版本、日期信号（值、精度、来源）、每个候选的一致性结论、命中条件、所用
  元数据提交与候选销售期——以及 `version_decided_by`（machine / person）与 `role_decided_by`（machine / person）。机器定版本、
  人定角色时两者分别标注，不把整条记录标成人工或机器。
- **问题摘要与对账**：问题的 revision 摘要覆盖材料三元组、策略版本、日期信号、每个候选的一致性结论与元数据依据；候选 ID 不变
  而依据变化也会产生新 revision，旧问题作废。已持久化的 Settlement 按 S5b-3c-2 的原协议对账，重算从不改写已保存的意图：
  `applied` 的结论原样完成，`obsolete` 保持作废，只有新问题产生新的 Settlement。
- **解除归属**：PV-3 提供受控入口（`uploads detach --knowledge-id … --reason …`，持上传文件锁，写决定记录
  `detached`）。效果按现有变化判定处理：下一轮编译中，Evidence 只来自该材料的 Claim 按“来源撤回”撤回；仍有其他来源支持
  的 Claim 保留；`expert_lock` 的 Claim 不被自动撤回（保留旧值并按冲突处理）。评委与“销售材料只作 4 个销售字段证据”的
  限制不替代归属校验。

## 5. 生命周期

### 5.1 主数据同步（PV-2）

固定提交的清单 → 差异报告；哪些字段自动更新、哪些只报告，以及评价日、时区与未知状态的规则见附录 A §3。要点：销售期与
来源状态自动更新（机器、留记录），不触发重编，随下一次元数据发布（附录 A §2）进入 Release；名称、条款号、险种这类由正文
确认的值**只报告**，待内容回验，不被清单覆盖；新版本只生成“待接入建议”。

### 5.2 停售不删知识

停售版本的知识继续留在 Release 中，页面与问答标注销售状态与日期。

### 5.3 问答（PV-4）

- **销售候选类**问题（推荐、对比、能不能买）默认排除 `discontinued` 与 `not_yet_on_sale`，`unknown` 保留并标注“销售状态
  未知”，避免未匹配的已登记产品从回答中消失；
- **点名产品**：按名称解析；同名多版本时列出各版本与销售期消歧，不默认选最新；
- **在保服务**（保全、理赔）：给出投保日期时选销售期包含该日期的版本；投保日期不是 Release 日期，读取仍固定在 Active
  或 pinned Release，权限边界不变；无法判断时追问产品全称或投保时间；
- 回答引用的产品标注版本名称、销售期与销售状态。

### 5.4 页面（PV-4）

产品库按 Release 实体上的 `product_family` 分组（前端不读登记表、不另写品牌规则；缺失时归入“未分组”），组内列版本（名称、
年份标签、销售期、销售状态），默认隐藏 `discontinued`，可切换“含停售”；`unknown` 显示并标注；版本页显示前驱与后继的链接。

## 6. 迁移现有 27 条（PV-1）

细则见附录 A §4：只读入口保持纯读（v1 文件按 v2 模型读入、版本字段为空，不写回）；迁移是单独、持锁、有备份的命令，原子替换为提交点，
替换前写操作日志，未确认的结果在同一把锁下按日志摘要恢复；全部既有内容与 ID 保留；条款号 0 个或多个匹配时不猜；`retired` 非空在迁移前检查并报告，格式继续支持。

## 7. 数据与代码的边界

- **数据**（版本化策略文件）：品牌前缀、险种后缀、年份标签模式、日期信号模式与精度、类型词与矛盾表、角色信号词、同步来源
  （仓库与提交）配置、问答默认过滤。
- **代码**：登记表 v2 与迁移命令；同步命令；候选全集、一致性校验与判定；人工入口约束与决定依据；元数据发布路径；合同与
  Go 读取；页面与问答过滤。
- **守卫**：不按产品编号、品牌名或样例文件写特判；文件夹/清单只作辅助证据；品牌永不单独作锚点；机器与人工结论分开记录。

## 8. 风险

| 风险 | 应对 |
|---|---|
| 年份标签与起售年错位（73 例） | 候选同时看 `year_tag` 与销售期；精确日期与销售期冲突时不自动归属 |
| 月份精度跨越换版 | `M` 与两个版本销售期都有交集 → 交人 |
| 同系列并行变体多（65 个系列） | 类型词矛盾表收窄；仍不唯一交人 |
| 老版本缺条款号（157）或条款号共用（10） | 外部键用 `planCode-versionNo`；迁移不猜；按附录 A §1.3 组合匹配，共用条款号时失败关闭 |
| 仓库文件放错 | 内容锚点优先 |
| 方案 A 误归 | 只影响销售类字段；可解除归属回退；评委与抽检兜底但不替代归属校验 |
| 综合手册覆盖多款产品 | 首期不挂单一版本；“一份材料挂多个版本”另行设计 |
| 清单过期或缺失 | 固定提交、记录来源；缺失字段为 `unknown`，不阻断现有流程 |
| PV-4 全量重发布 | 元数据发布路径（附录 A §2），单独 Issue、前后核对 Active、不与编译轮次重叠 |
