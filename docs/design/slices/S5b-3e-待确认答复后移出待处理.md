## 1. 规则

在页面上，有没有答复决定一项归哪个页签：

| 页签 | 内容 |
|---|---|
| 待处理 | 未关闭、**还没有答复**的项 |
| 已处理 | 已关闭的项，加上未关闭但**已有答复**的项（等待系统处理） |

平台仍按"未关闭/已关闭"列出待确认项（`listConfirmations(space, 'open' | 'closed')`）。未关闭列表中，每项都带最新答复，所以前端自己就能分出这两组，不需要改平台。

## 2. 页面

1. **待处理**：只读取 `open`，只显示没有答复的项。
2. **已处理**：同时读取 `open` 和 `closed`，先列出已答复、等待处理的项，再列出已关闭的项。
   - 已答复、等待处理的项沿用现有卡片：显示"已选择：{option}，等待系统处理"，可以"修改选择"。平台在项关闭前接受新答复，以较新的为准。改完后这一项仍留在"已处理"，状态行获得焦点。
   - 已关闭的项和以前一样，显示处理结果，没有答复控件。
3. **在"待处理"提交答复成功后**：
   - 这张卡立即从列表里移走，不重新读取列表，计数和空状态同步更新；
   - 页面出现一条状态提示（`data-confirm-moved`，`role="status"`，可获得焦点）："已记录「{option}」，这一项已移到"已处理"，等待系统处理"，焦点移到这条提示上；
   - 提交失败、被拒绝、或这一项已被关闭（`CONFIRMATION_CLOSED`）时，沿用现有处理。
4. **首页工作台**："待确认材料"的计数只算没有答复的未关闭项。
