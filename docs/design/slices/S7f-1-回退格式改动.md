## 2. 改动

### 2.1 回退 129 个文件到上游字节

`tests/architecture/s7f1_format_only_files.txt` 列出 129 个文件：88 个只改格式，加 45 个只改注释中的 41 个。逐个执行：

```
git checkout 3e8b0bfc80b845b2d4b2ed683994748741450a97 -- <path>
```

把文件恢复为上游内容，不做任何其他改动。

### 2.2 lint 的处理（本片唯一非回退改动）

被回退的行几乎都是上游原样的长行（lll 120）、未经 gofumpt 的写法和 revive 不认可的注释格式。CI 的 golangci-lint 用 `--new-from-merge-base` 只检查本 PR 改动的行，所以回退会把这些上游原样写法报成"新问题"。

处理分两步：

1. **本 PR**：在 `.golangci.yml` 加一条**临时**排除，只针对本清单中的 Go 文件，排除 lll、revive 与 gofumpt。排除列表由清单逐条生成（精确路径，不用目录通配），并加注释"S7f-1 临时，S7f-1 收尾删除"。
2. **合并后紧接的收尾 PR**：删除这条排除。合并以后这些行相对合并基线不再是新行，lint 不会再报。

gofmt 检查（`app.yml`）不受影响：上游这些文件都符合 gofmt，已逐个核对。

`frontend/src/views/dev/MarkdownTestPage.vue` 只差空白，前端门禁按现状运行。

## 附录 A：分类方法（可复现）

1. G10 文件集合：`git diff --name-only --diff-filter=MDT <base> --`，去掉 `.github/`。
2. **Go 文件**：两个版本分别用 `go/parser` 解析（`ParseComments`），得到两个哈希：
   - **代码哈希**：用反射遍历 AST，跳过所有 `token.Pos`、`*ast.CommentGroup`、`Obj`、`Scope` 等位置和派生字段；每个 import 块内的 ImportSpec 按路径排序。
   - **注释哈希**：每条注释的文本，空白归一后拼接。
   - 判定：两个哈希都相同为"只改格式"；代码相同、注释不同为"只改注释"；把标识符小写后代码相同为"只改大小写"；其余为"实质改动"。解析失败计为实质。
3. **非 Go 文件**：去掉行尾空白和空行后比较；只有完全相同才算只改格式，其余一律计为实质。
4. **只改注释的文件**：在 diff 中查找 `//go:`、`//nolint`、`// @`、`+build` 等会影响行为或生成物的注释，命中的移出清单（§2.3）。
5. 上游版本的 lint 情况：88 个只改格式的文件中，87 个上游版本有超过 120 列的行（lll）或不符合 gofumpt，这正是 §2.2 需要临时排除的原因。
