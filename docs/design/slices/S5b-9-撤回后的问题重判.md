# S5b-9 · 撤回后的问题重判

> 状态：Claude 2026-11-01 ｜ 实现方 Claude，审核方 Codex ｜ 真实调用 0 ｜ 修订 S5b-7 §2 第 4 条“仍要问人 → 保持原样”

## 1. 问题

S5b-7 §2 第 4 条规定：在旧版规则下提出、尚无 settlement 的 `NEEDS_CONFIRM` 问题，若新规则重判后仍要等人（`NEEDS_CONFIRM`
或 `QUARANTINE`），`uploads run` **保持原样**（`ingest/uploads.py` 的 held 分支），因为有人可能正在回答它。

这条规则默认平台上的项目还开着。2026-11-01 线上出现了它不成立的情况：两份 Office 培训材料的旧问题（规则 2026-11-01.1，品牌候选）
按用户决定被**撤回**——平台项目以 `obsolete` 关闭，答复未落账（`uploads confirm` 在 `answers_withdrawn` 中报出）。之后在
2026-11-01.6 规则下，这两份材料的结论已是隔离（`date_signals_conflict` / `no_registered_version`），但 `uploads run` 仍按“保持原样”
留下旧问题；随后的 `uploads confirm` 会把用户已撤回的旧候选重新推上页面。

## 2. 规则

1. **只在问题的平台项目仍可作答时保持原样。** 对每个“在旧版规则下提出、无 settlement 的 `NEEDS_CONFIRM`”材料，`uploads run`
   读取平台上该材料的确认项目（主题 `material:<knowledge_id>`，`source_ref` 等于当前登记的材料修订；`source_ref` 为空的旧项目按主题算），
   分三种情况：
   - **从未推送**（没有项目）：保持原样（与 S5b-7 相同）；
   - **仍开着**（至少一个项目未关闭，无论是否已有答复）：保持原样（与 S5b-7 相同）；已有答复的照旧由 `uploads confirm` 落账；
   - **已撤回**（有项目，且全部以 `obsolete` 关闭）：**不再保持**——按当前规则重判并照常记录新结论（自动结论，不带 confirmation；
     隔离项带新理由），之后 `uploads confirm` 按新结论的问题身份推送新问题（或者新结论不需要问人时不推）。旧项目与其上被撤回的答复不动，
     仍由 `answers_withdrawn` 报出；**不记为人工决定**。
   - 有项目以 `applied` 关闭：不算撤回，保持原样（该材料应已有落账结论，不由本规则处理）。
2. **读不到平台状态时失败关闭。** 读取确认项目失败（平台错误、响应不合规）时，所有需要判断的旧问题一律保持原样，并在报告中逐个列出，
   不猜测。
3. **不读不需要的东西。** 没有“在旧版规则下提出、无 settlement 的 `NEEDS_CONFIRM`”时，`uploads run` 不访问确认接口（与 S5b-7 相同）。
4. 已持久化的 Settlement 不受影响：带 settlement 的材料本来就不参与重判（`_candidates` 已排除）。当前规则下提出的问题也不参与重判；
   因此**当前规则下**被撤回的问题仍无法重问（平台按问题身份去重，重判得到同一身份会返回已关闭项目），要等规则或措辞版本变化
   ——这是已知限制，与 2026-11-01 Owner 裁定一致（见 Issue #509）。

本片是**归属执行流程**的修订，不改归属规则本身：`attribution_policy.json` 不升版本，重判结论与规则版本由现有 `attribute` 给出。

报告新增两个字段（默认空，旧报告读者不受影响）：
- `withdrawn_rejudged`：因问题已撤回而重判的材料编号；
- `question_state_unknown`：因读不到平台状态而保持原样的材料编号。

## 3. 改动

- 新模块 `ingest/withdrawn_questions.py`：找出需要判断的旧问题、按 §2.1 从平台项目判定“已撤回”、读取失败时返回“状态未知”；
- `ingest/uploads.py`：`attribute_uploads` 增加参数 `withdrawn`（默认空，行为与原来相同）；held 分支与隔离项的“同一问题保持原样”
  对已撤回的材料不再适用；`uploads run` 命令在需要时读取平台确认项目并填写报告新字段。

不改：归属规则与数据、`uploads confirm`、登记表格式、编译、发布、证据与评分代码。

## 4. 验收（RED）

`harness/tests/ingest/test_withdrawn_question_rejudge.py`：
- 已撤回（项目以 obsolete 关闭、答复未落账）→ 重判并记录新结论（隔离理由更新为当前规则的理由；结论相同仅规则版本不同时也记录当前版本），
  之后 `uploads confirm` 推送的是新身份的问题（或不推），旧项目不被再次打开，撤回的答复不成为人工决定；
- 仍开着且无人作答 → 保持原样（与 S5b-7 相同）；
- 仍开着且已有答复、尚未落账 → 保持原样，随后的 `uploads confirm` 照常落账该答复；
- 读不到平台状态 → 保持原样，并在 `question_state_unknown` 报出；
- 没有旧问题时不访问确认接口。

`git diff --check`；手写文件 ≤ 500 行。
