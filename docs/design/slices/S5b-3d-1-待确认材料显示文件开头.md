# S5b-3d-1 · 待确认材料显示文件开头

> 状态：Claude 2026-10-26 提出 ｜ 作者：Claude Code
> 依据：
> - 用户 2026-10-26 验收"待确认材料"页时反馈：卡片上只有文件名，没法判断，也没有链接打开；
> - S5b-3c-2：问题的文字是版本化数据（`confirmation_wording.json`），修订号含文字版本，改文字即是新问题，旧的待答项按"不再询问"关闭；
> - 后续 S5b-3d-2：平台加"打开原文件"（需要迁移，另行批准）。

> 实现方：Claude ｜ 审核方：**Codex** ｜ 真实模型调用：0

## 1. 目标

每个待确认项的说明末尾加一行"文件开头：……"，摘录这份材料前两页的开头文字，让管理员不打开文件也能判断大多数情况。例如 2647 的"费率表.pdf"开头是"《平安智盈金生专属商业养老保险》转换标准表（每万元保单账户价值转换的领取金额）……"，看到这句就能判断它是什么。

只改 Harness 推送的文字，不改平台与页面（页面已按原样显示说明，保留换行）。

## 2. 规则

1. **摘录**：取 `head_of` 读到的前两页文字，做以下处理：
   - 去掉控制字符与 Unicode 私用区字符（字体里的项目符号）；
   - 把连续的空白（含换行、制表符）合成一个空格，去掉首尾空白；
   - 截到 `excerpt_chars`（300）字，截断时末尾加"…"。
2. **文字**（`confirmation_wording.json`，版本 2026-10-26.1）：说明 = 原有的原因说明 + 换行 + `excerpt` 模板（"文件开头：{excerpt}"）。
3. **读取**：同步时每份材料每轮最多读一次页面并缓存（`questions()` 一轮会被调用多次）。应用答案时读开头也用同一个缓存。
4. **读不到时这一轮不问**（实现时发现）：
   - 读取失败（`SourcePagesError`）时，这份材料这一轮记为"无法提问"（错误码计入报告的 `skipped`，每份材料只计一次）：不推送，也不关闭它已有的待答项，下一轮再读；
   - 理由：需要人确认的材料在归属时已经读到过页面，读不到通常是暂时的；
   - 如果改用"读不到"的文字推送，问题内容会随读取成败变化，已作答的项会被当作旧问题关闭，答案就丢了（S5b-3c-2 的受保护测试"读不到的材料跳过、其余照常应用"能复现）。
5. **`question_of` 保持纯函数**：新增必填的关键字参数 `head: str`。摘录为空（前两页没有文字）时是 `QUESTION_INVALID`，同样记为"无法提问"。
6. **已有待答项**：文字版本变了，修订号随之改变，按 S5b-3c-2 的规则推送新问题、关闭旧问题。尚未作答的不受影响；已作答、但答案还没应用的，需要重新作答（目前线上只有 1 项，未作答）。

## 3. 改动

- `harness/src/insurance_harness/ingest/confirmation_questions.py`：摘录函数、`question_of(..., head=)`、文字模型新增 `excerpt`、`excerpt_chars`；
- `harness/src/insurance_harness/ingest/confirmation_wording.json`：版本与新增文字；
- `harness/src/insurance_harness/ingest/confirmations.py`：`_Sync` 每轮缓存每份材料的开头文字，传给 `question_of`；读不到时记为无法提问；应用答案时也读这个缓存。

## 4. 验收（RED，受保护）

`harness/tests/ingest/test_confirmation_excerpt.py`：
1. 说明末尾是"文件开头："加处理后的摘录（空白合并、无控制字符和私用区字符）；
2. 超长的开头截到 300 字并加"…"，整段说明仍在平台上限（2000 字）内；
3. 前两页没有文字时，`question_of` 报 `QUESTION_INVALID`；
4. 同步时推送的说明含该材料的开头；读不到页面的材料这一轮不推送，计入 `skipped`；已推送并作答的项不会因为读不到而关闭，下一轮读得到时照常应用；
5. 文字版本为 2026-10-26.1。

S5b-3c-2 的受保护测试中，"推送的项与 `question_of` 相同"那一条改为把假页面读到的开头传给 `question_of`（单独提交，写明原因）。
