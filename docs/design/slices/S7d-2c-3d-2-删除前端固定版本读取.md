# S7d-2c-3d-2 · 删除前端固定版本读取

> 状态：Claude 2026-10-24 提出；用户 2026-10-22 同意删除旧 830/G3 代码，2026-10-23 决定 S7d-2c 一并退役 ｜ 作者：Claude Code
> 依据：蓝图硬边界 7（不打开当前版本代替历史版本）、核心原则 6（完整前端体验）与 10（删除优于兼容）；S7d-2c-3a（#323）删除了发出 `release_authorities` 的旧 830 Wiki 工具，S7d-2c-3c（#328）删除了 `release-scopes` 接口
> 实现方：Claude ｜ 审核方：Codex（前端；上游文件 `AgentStreamDisplay.vue`、`api/wiki/index.ts`、5 个语言包）｜ 真实模型调用：0
> 并行：S7d-2c-3d-1（Harness 字段目录）写域不重叠

## 1. 背景

问答抽屉打开 Wiki 引用时，若引用来自旧 830 工具（事件 `tool_data.release_authorities`），会按其中固定的版本请求 `release-scopes` 接口。

- 3a 之后 Go 不再发出 `release_authorities`，新会话的引用都走原生 `getWikiPage`；
- 3c 之后该接口已删除，旧会话里的固定引用只会得到 404，再显示"该引用来自旧版本，请重新提问"。

前端这条分支已无用。但它承担一条边界：**旧固定引用不能悄悄改为打开当前版本**。

## 2. 改动

1. **抽屉 `frontend/src/enterprise/useReleaseWikiDrawer.ts`**：
   - `open(kbId, slug)` 只读原生页面，删除 `pin` 参数、`authority` 状态与固定版本的页面映射；
   - 加载、错误、重试与"后到的旧响应不覆盖新引用"的行为不变。
2. **旧固定引用失败关闭**：用 `citesPinnedRelease(events, kbId, slug)` 取代 `resolveWikiReleaseAuthority` 与 `resolveReleaseCitationKb`。
   判定以实际要请求的 `(kbId, slug)` 为准。`kbId` 是 `getKbIdForWiki` 最终选中、即将交给原生接口的 KB，选 KB 的规则与判定由此保持一致（审核 R1，2026-10-24 修正）：
   - 只读可解释的事件：事件与 `tool_data` 都是对象；其余事件跳过，判定函数本身不抛异常；
   - 最新一条在 `found_kbs[slug]` 中列出 `kbId` 的事件（取值为该字符串，或为含该字符串的数组）决定结果：`tool_data` 自有属性 `release_authorities` 存在则返回 true，不论取值（包括 `undefined`、`null`、空数组、对象），不存在则返回 false；
   - 没有事件为 `kbId` 找到该 slug 时，会话中任何可解释事件的 `tool_data` 存在 `release_authorities` 属性，就返回 true（宁可拒绝），否则返回 false。
3. **`AgentStreamDisplay.vue`（上游）**：
   - `openWikiDrawer(kbId, slug)` 在打开前检查 `citesPinnedRelease(events, kbId, slug)`：
     - 为 true 时不发请求，关闭已开的抽屉，提示"该引用来自旧版本，请重新提问"；
     - 判定过程出现任何异常（如事件流本身不是数组）同样按拒绝处理（审核 R2）；
     - 为 false 时 `wikiDrawer.open(kbId, slug)`；
   - `getKbIdForWiki` 删除按固定版本选 KB 的两行，回到上游原样；
   - 图谱链接删除 `v-if="!wikiDrawerAuthority"`，回到上游原样。
4. **`frontend/src/api/wiki/index.ts`（上游）**：删除 `WikiReleaseAuthority` 与 `getReleaseWikiPage`。
5. **语言包**：5 个语言包删除 `wikiBrowser` 下 S7b 之后无人使用的 10 个键：
   - `tabSchemaWiki`、`schemaLoading`、`schemaNotCompiled`、`schemaLoadFailed`；
   - `schemaUnknown`、`schemaUndetermined`、`schemaPresent`、`schemaAbsent`；
   - `schemaCitation`、`schemaCitationUnavailable`。

   `enterpriseKnowledge.nav.schemaWiki` 仍在企业导航使用，保留。

**不做**：
- 不改已发布知识工具的引用（`releaseReferences`）、来源页与企业导航；
- 不改 Go 与 Harness。

## 3. 验收（RED，Claude 编写，受保护）

1. **`frontend/src/enterprise/legacyReleaseReadRemoved.spec.ts`（新）**：
   - `api/wiki` 源码不含 `release-scopes`、`getReleaseWikiPage`、`WikiReleaseAuthority`；
   - `AgentStreamDisplay.vue` 不含 `wikiDrawerAuthority`、`resolveReleaseCitationKb`、`resolveWikiReleaseAuthority`；
   - 5 个语言包不含 §2.5 的 10 个键，仍含 `nav.schemaWiki`。
2. **`releaseRead.spec.ts`（更新"release wiki citations"一组）**：
   - `citesPinnedRelease` 覆盖 §2.2 各分支：
     - 取值畸形的 `release_authorities`，以及值为 `undefined` 但属性存在的情况；
     - `found_kbs[slug]` 为字符串或数组；
     - 新事件只为另一 KB 找到该 slug（R1）；
     - 新事件的 `found_kbs[slug]` 为 `null`；
     - 混入 `null`、字符串、`tool_data: null` 等不可解释事件时不抛异常（R2）；
   - 抽屉只发原生请求（任何请求地址都不含 `release-scopes`），跟随内部链接保持同一 KB；
   - 后到的旧响应不覆盖新引用；失败清空旧内容并可重试。
3. **`releaseReadIntegration.spec.ts`（更新）**：
   - 旧固定引用不打开、关闭已开抽屉并提示旧版本；判定以 `(events, kbId, slug)` 调用；
   - 判定抛异常时同样关闭抽屉、提示旧版本、不发请求；
   - 用真实的 `getKbIdForWiki` 与真实的 `citesPinnedRelease` 串起实际的选 KB 与打开流程：
     - 路由指向旧固定引用的 KB、而较新的原生事件属于另一 KB 时，不发请求；
     - 无路由且较新事件的命中值为 `null` 时，同样不发请求（R1 的两个复现）；
   - 当前引用以 `(kbId, slug)` 打开；
   - `getKbIdForWiki` 在不提供任何固定版本依赖时可运行，并沿用上游的路由优先；
   - 抽屉内链接继续 `follow`。

**门禁**：`frontend/` 下 `npm test`、`npx vitest run src/enterprise`、`npm run type-check`、`npm run build`。
