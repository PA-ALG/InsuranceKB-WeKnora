## 1. 问题

S5b-1 认为条款"以自己的备案编号开头，后接标题"，只在开头 300 字里找编号。实际情况：

- 20 份真实条款（已登记的 13 份加这次的 7 份）都**不是**以编号开头。编号在第 1 页末尾，第 700–2300 字处，紧跟一句二维码验证说明"请扫描以查询验证条款"。每份条款恰好一处；
- 开头是"产品名 + 阅读指引"，或者先有"险种简称：…险种代码：…"标签。20 份里有 19 份在阅读指引中写有"<产品名>产品提供……保障"；
- 已登记的 13 款当初是从原始清单导入的，没有经过归属判定，所以这个问题一直没有暴露。

另有两处规则偏窄：
- 险种按名称后缀判断时，只去掉**末尾**的括号限定词。"平安意外（A款）医疗保险"因此会落到普通医疗险，而不是意外医疗；
- 说明书标题前可能带页码或连字符（"1平安…""-平安…"），导致标题读不出。

## 2. 规则（版本化数据 `attribution_policy.json` 2026-10-26.1，代码只执行）

1. **条款自己的编号**：
   - 在材料前两页（`head`，现状不变）中，紧跟"自有编号标记"（`own_code_marker`："请扫描以查询验证条款"）的备案编号，就是这份条款自己的编号；
   - 出现两个不同的这种编号：`QUARANTINE`、`anchor_conflict`；
   - 没有带标记的编号时，沿用 S5b-1 的规则：开头 300 字内、位于最开头的编号；
   - 只有自己的编号能建产品或判为新版本。正文中引用的其他编号仍然只能用来确认已登记的产品（S5b-1 不变）。
2. **标题**，从两处读：
   - **开头标题**：去掉开头的页码、连字符和"险种简称…险种代码…"标签（`title_prefix_pattern`）；若此时以自己的编号和标记开头，也一并去掉。然后按 S5b-1 读标题（书名号，或截到第一个结束词）；
   - **阅读指引标题**：`guide_title_pattern`（"阅读指引" 与 "产品提供" 之间的名称，先去掉验证说明那句）。**只在开头读不到标题时使用**，不与开头标题比对：
     - 用另一种文字提取器读同样的 13 份条款（S5b-1 的 fixture）时，阅读指引这句话里夹进了验证说明，产品名也缺字（"平安"丢失，"(尊享版26)"被截断）；
     - 如果把两处不一致判为冲突，会把真实条款全部误判为冲突（实现时发现，见 PR）；
   - 标题仍按 S5b-1 规则使用：与已登记名称相同即认定为该产品，长度上限不变。
3. **险种**：
   - 判断后缀前去掉名称中**所有**括号限定词，而不只是末尾的；例如"平安意外（A款）医疗保险"按"平安意外医疗保险"判断，归意外医疗；
   - 新增后缀"专属商业养老保险" → 补充养老（用户 2026-10-26）。
4. **标准化去掉私用区字符**：Unicode 私用区（类别 `Co`）的字符是字体里的项目符号（如 U+F043），没有文字含义；提取后会出现在标题前面，标准化时一并去掉。
5. 其余不变：建产品的编号前缀、哈希长度、角色判断、人工确认、隔离重判。

## 2a. 发布报告带出候选编号（RV5a §6 移入本片）

`uploads publish` 的报告增加 `candidates`：路由为人工的产品 → 发布命令输出的 `candidate_id`。这样操作的人能在人工审核队列（RV5）里找到它们。
- 只记录路由为 `human`，且 `candidate_id` 是非空字符串的产品；
- 字段缺失时不算失败（发布已经成功，回执照常写入），只是不记录；
- 机器路由与"无变化"的产品不记录。

## 4. 验收（RED，受保护）

`harness/tests/identity/test_attribution_onsale.py`。fixture 是 `tests/identity/fixtures/attribution_heads_onsale.json`：7 款官网在售产品 21 份材料的前两页（标准化后，保留开头和编号附近的文字），都是公开文件。

1. 7 份条款对已登记的 13 款都判为 `CREATE`：
   - 编号为 `sc-` 加自有编号的哈希；
   - 名称、险种正确：重疾、意外、意外医疗、定期寿险、护理、失能收入、补充养老各一款。
2. 登记了条款之后，同一产品的说明书与费率表判为 `SUPPLEMENT`（`matched_by_name`）。以下例外：
   - 没有标题的费率表（2613）：`QUARANTINE`；
   - 文件夹里放错的、属于另一产品的说明书（L3223）：`QUARANTINE`；
   - 角色读不出的"转换标准表"（2647）：`NEEDS_CONFIRM`、`role_unresolved`。
3. 出现两个不同的自有编号：`QUARANTINE`、`anchor_conflict`。开头有标题时，阅读指引里的名称不影响结果。
4. 说明书正文引用编号但没有验证标记：不能建产品。
5. S5b-1 原有的 39 份材料测试全部通过，只有两处随本片规则更新（单独提交，写明原因）：
   - 策略版本号断言更新为新版本；
   - "编号前有标签"的条款：开头只有标签、读不到标题，于是按阅读指引读出产品名，引用的编号确认了这款已登记产品，结果从 `anchor_conflict` 变为 `NEEDS_CONFIRM`、`same_role_differs`，由人决定；
   - S5b-1 R3 要保护的内容不变：这个编号不是条款自己的，不能建产品，也不能判为新版本。

6. 发布报告：人工路由的产品带出候选编号，机器路由的不带（`harness/tests/ingest/test_publication_candidates.py`）。

**门禁**：`uv run pytest`（不新增失败）、`uv run ruff check .`、`uv run mypy src tests`、架构守卫。
