# S9c · 专家编辑表单说明不能保存的原因

> 状态：Claude 2026-10-24 提出；用户验收 #299 时反馈"没法保存，也没提示原因，对用户很不友好" ｜ 作者：Claude Code
> 依据：S9b（#298）专家编辑界面；蓝图 §6.4、§11 S9
> 实现方：Claude ｜ 审核方：Codex（前端）｜ 真实模型调用：0

## 1. 问题

用户修改一个当前为"材料未提及"的字段：

- 表单按 S9b 的规定，默认停在字段当前的状态；在这个状态下没有"新值"输入框；
- 用户把要补的内容贴进了"原因"框；
- 状态和值都和当前相同，"保存并发布"按钮被置灰，但页面没有任何说明。

按钮的判断本身是对的：不能发布一个与当前完全相同的修订，原因也必须填写。缺的是把"还差什么"告诉用户。

## 2. 设计

只改 `frontend/src/enterprise/ExpertEditForm.vue` 和语言包，不改保存条件、默认状态和接口。

1. **说明还差什么**：按钮不可用时，在按钮下方显示一行 `data-missing` 提示，只显示第一项未满足的条件，顺序如下：

   | 条件 | 提示 |
   |---|---|
   | 状态不是"有值"，且与当前相同 | 状态与当前相同。要填写内容，请先选择"有值"，再在"新值"里填写 |
   | 状态是"有值"，新值为空 | 请填写新值 |
   | 状态是"有值"，新值与当前相同（忽略首尾空白） | 新值与当前内容相同 |
   | 原因为空 | 请填写修改原因 |
   | 原因超过 2000 字 | 修改原因超过 2000 字 |

   保存中、或这个字段在当前版本中不存在时，不显示提示，沿用现有的状态提示与失败提示。
2. **标签写清楚**：
   - "新值"改为"新值（字段内容）"；
   - "原因"改为"修改原因（必填，说明依据）"。
3. **语言包**：`zh-CN`、`en-US`、`ja-JP`、`ko-KR`、`ru-RU` 同步增加提示文案，并修改两个标签。

不做：
- 不改默认状态。S9b 规定表单先显示当前状态，受保护测试断言了这一点；有了提示，用户能直接看出该怎么做。
- 不改服务端校验，以及失败后的错误文案。

## 3. 上游补丁

不涉及上游文件，G10 不变。

## 4. 验收（RED，Claude 编写，受保护）

`frontend/src/enterprise/ExpertEditFormHint.spec.ts`：

1. 当前为"材料未提及"的字段：状态不变、只填原因 → 按钮不可用，提示含"请先选择"和"有值"；改选"有值"并填写新值后 → 提示消失，按钮可用；
2. 当前有值的字段：
   - 新值清空 → "请填写新值"；
   - 新值与当前相同 → "新值与当前内容相同"；
   - 改了值但没写原因 → "请填写修改原因"；
   - 原因超过 2000 字 → "修改原因超过 2000 字"；
3. 两个标签显示新文案。

S9b 的 `ExpertEditForm.spec.ts` 照常通过。
