# S11f 未采集材料带类型原因

> 状态：Spec 冻结（2026-10-31，Claude）。实现方 Claude，审核方 Codex。计划 #446。
> 真实调用：0。测试只用测试内生成的合成数据；用户的业务样本不进仓库、Issue、PR 或日志。

## 0. 背景

- 企业 RAW KB 的 PDF 首次解析走原生采集（S4c-2c）。只要有一页被判为扫描页，docreader 返回 `page N is scanned`（N 是**第一个**扫描页），
  平台以零 chunk 正常完成该 attempt，不写首次解析记录（S4c-2c §3.3）；之后页接口对该 attempt 返回 409
  `PARSE_ARTIFACT_NOT_CAPTURED`。页号只出现在一条尽力而为的处理阶段输出里（`not_captured_reason: "scanned_page"`，无页号）。
- Office 上传（S11b）采集失败时，平台照常完成上游解析，只在日志里记一个类型码；页接口同样返回 409 `PARSE_ARTIFACT_NOT_CAPTURED`。
- 不能采集的格式（不是 PDF，也不是 `.pptx/.docx/.xlsx`）和采集上线前解析的旧 attempt，也都是同一个 409，不区分原因。
- Harness `uploads run`：页接口报错的材料只以知识 ID 列在 `unreadable` 里，错误码被丢弃；RAW 列表里**解析失败或仍在解析**的材料
  （`parse_status` 不是 `completed`）根本不出现在报告里。运维无从知道原因，容易漏掉。
- 2026-10-31 的扫描件调研（仓库外报告）显示：5 份业务培训 PDF（演示文稿导出）因整页背景图被判为扫描页，整份不能采集；981 份在售产品
  PDF 没有扫描页。

## 1. 目标

1. 页接口的 409 `PARSE_ARTIFACT_NOT_CAPTURED` 带一个**类型化原因**（扫描页时带第一个扫描页的页号），只有原因码与页号，不带任何原始
   错误文本。
2. Harness 上传报告列出每份读不到的材料**为什么**读不到，并列出 RAW 列表中解析失败、仍在解析的材料。
3. 不改采集判定、不改解析结果、不改 PDF/Office 的可采集范围；不新增上游补丁文件（G10 不升）；不改 `contracts/`。

## 2. 原因码（冻结）

### 2.1 平台（页接口 409 的 `reason`）

| `reason` | 含义 | 来源 |
|---|---|---|
| `SCANNED_PAGE` | PDF 有扫描页，整份未采集；同时给 `page_number`（第一个扫描页，≥1） | 解析时写下的采集备注 |
| `OFFICE_STRUCTURE_UNREADABLE` | Office 文件的结构读不出或封存失败 | 解析时写下的采集备注 |
| `UNSUPPORTED_FORMAT` | 文件类型不在可采集范围（PDF、`.pptx`、`.docx`、`.xlsx` 之外） | 读取时按知识的文件类型判断 |
| `CAPTURE_NOT_RECORDED` | 可采集的类型，但这个 attempt 既没有采集也没有备注（如采集上线前解析的旧 attempt、URL 导入、备注写入失败） | 读取时兜底 |

- 响应体：`{"success": false, "code": "PARSE_ARTIFACT_NOT_CAPTURED", "error": "parse artifact was not captured", "reason": "...",
  "page_number": N}`；`page_number` 只在 `SCANNED_PAGE` 时出现。其他错误码的响应体不变。
- 引用、MCP、发布回验等其他调用方只看错误码，行为不变。

### 2.2 Harness（上传报告）

- 页接口错误：报告里的 `code` 是平台错误码（已有的白名单），`reason`、`page` 只在 `PARSE_ARTIFACT_NOT_CAPTURED` 且取值在 §2.1 白名单内时
  保留（`page` 只随 `SCANNED_PAGE`，严格正整数，`true` 不算 1）；不认识的取值丢弃为空，不报错。
- RAW 列表中未完成的材料：`failed` → `PARSE_FAILED`，`cancelled` → `PARSE_CANCELLED`，`pending`/`processing`/`finalizing` →
  `NOT_CAPTURED_YET`，`deleting` 不列，其他取值 → `PARSE_STATE_UNKNOWN`。只用列表里的状态字段，**从不读取或输出 `error_message`**。

## 3. 设计

### 3.1 采集备注（`internal/enterprise/capture`）

- 新的签名记录“采集备注”：`{"contract": "enterprise-capture-note.v1", "identity": <与采集相同的 Identity>, "reason": ...,
  "page_number": N}`，用采集的同一签名环封存；键为 `note-` + sha256(合同名 + `\x00` + 规范化 Identity)，与采集键（`first-…`）
  天然不同，签名绑定键名，两类记录不能互换。
- 存在采集目录的**兄弟目录** `<采集目录>-notes`（部署中为 `$LOCAL_STORAGE_BASE_DIR/.concept-source-reuse-v1-notes`）：采集目录本身
  不多任何文件，S4c-2c §3.3“不写首次解析记录、不留临时文件”与其测试保持成立。
- 写入一次即不可变：同字节重复写成功，不同内容写同一键失败（与采集相同的硬链接发布）。备注只用于说明原因，写入失败只记日志（类型码），
  **不改变解析结果**；读不到备注时兜底为 `CAPTURE_NOT_RECORDED`。
- 读取：采集存在时只读采集，备注被忽略；采集不存在时读备注——签名不对、合同或 Identity 不符、原因不在白名单、页号与原因不配 →
  `PARSE_ARTIFACT_INTEGRITY`（失败关闭）；备注也不存在 → 按知识文件类型给 `UNSUPPORTED_FORMAT` 或 `CAPTURE_NOT_RECORDED`。
- 读取前的归属、修订与指纹检查不变；读不到任何东西都不触发解析。

### 3.2 写入点

- 扫描 PDF：`knowledge_process.go` 中现有的企业扫描分支把“结束 docreader 阶段”的三行换成一次 `s.noteScannedPDF(...)` 调用；该方法在
  自有文件 `g3_first_parse.go` 中，阶段输出与今天**逐字相同**，另按与 Office 采集相同的修订绑定检查写一条 `SCANNED_PAGE` 备注
  （页号从原始错误串按同一正则取出）。上游补丁文件数不变，该文件的补丁行数减少。
- Office：`captureOffice`（自有文件）在修订绑定成立而结构读取或封存失败时写 `OFFICE_STRUCTURE_UNREADABLE` 备注；修订绑定不成立时
  不写（没有可信的 Identity）。

### 3.3 页接口（`internal/enterprise/source`、`mount.go`）

- `source.Error` 增加 `Reason`、`Page` 两个字段，只用于 `PARSE_ARTIFACT_NOT_CAPTURED`；新类型 `source.NotCaptured{Reason, Page}` 满足
  `errors.Is(err, source.ErrNotCaptured)`，现有判断不变。
- `writeSourceError` 只在 `PARSE_ARTIFACT_NOT_CAPTURED` 且原因非空时加 `reason`（与 `page_number`）。

### 3.4 Harness

- `SourcePagesError` 增加只读的 `reason`、`page`（§2.2）。
- `RawSources.listing(raw_kb_id)` 一次读完整个列表，返回已完成材料（与今天 `completed()` 相同）和未完成材料
  （知识 ID、文件名、§2.2 状态）；`completed()` 保留并复用它。
- `UploadReport` 现有字段不变；新增 `unreadable_reasons`（每份读不到的材料：知识 ID、文件名、`code`、`reason`、`page`）与
  `unfinished`（未完成材料：知识 ID、文件名、`state`）。`uploads run` 输出这两项；dry-run 也输出。
