**Architecture:** 扩展当前数据合同，复用 G1 `PresentationProfileV1` 与 `schema_wiki_sha256`。Catalog 是配置制品，不是第二 Wiki 或知识事实层。正文、字段、审核和发布仍沿既有 WeKnora 链。

**Tech Stack:** Python 3.12 / Pydantic / XLSX 标准 ZIP/XML 读取，现有 Go/Vue 接口。

## 首切片合同

- `schema-pack-catalog.830.g3.v1`：catalog_id、catalog_version、workbook_sha256、mapping_config_sha256、entries、field_name_union_count、field_name_intersection_count、catalog_sha256。hash 复用 schema_wiki_sha256(contract, payload excluding own hash)。所有对象完整内联保存以便重算，无时间戳混入内容 hash。
- entry：pack + profile + profile_confirmation_status=PENDING_PRODUCT_OWNER_CONFIRMATION + quality_status=REGISTERED_NOT_QUALITY_ADMITTED。不能接收任意自称已批准的状态来放行。
- `schema-pack-definition.830.g3.v1` pack：schema_pack_id、schema_version、display_name、entity_type=insurance_product、applicable_classifications、workbook_sha256、workbook_sheet、fields、presentation_profile_ref(id/version)、schema_pack_sha256。pack 不嵌入 profile hash，避免循环；profile 使用既有 v1，绑定 pack hash；catalog hash 同时绑定两者。
- FieldDefinition：field_key=原英文名；short_title=原中文名；schema_category、value_spec、description、source_guidance、formation_method、knowledge_role、common_field_marker、other_applicable_products、usage_frequency 原值保留；source_row、semantic_sha256。完整 metadata 参与语义 hash；身份限定在 pack+field_key，不跨 pack 按同名合并。空单元格为 null，绝不解释成实体值 unknown/absent。
- 映射配置是独立版本化数据：每包 sheet/id/分类和有序 sections，每 section key/display_name、category_codes、可选 field_keys 明示覆盖。禁止 FieldDefinition 存展示 section；匹配必须恰好一次，不准过滤掉空 section 掩盖错误。
- 接受 Profile 的唯一拓扑校验沿 G1；额外要求 field key 集合严格等于对应 pack。展示重排不改变 FieldDefinition semantic hash 或稳定 ID。
- 首切片不产生 classification/entity/model output；批量 disposition、TrustPolicy 阈值在真实 corpus 冻结后同 G3 下一个切片制定，不能拿本配置冒充自动识别。
