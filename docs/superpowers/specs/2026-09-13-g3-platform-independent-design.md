## Architecture

Use the existing deployed-platform boundary: WeKnora owns browser upload, original files, parsed revisions, ACL and sole serving Active Release. Python Harness owns insurance semantics, compilation and governance. Extend the existing wiki-api/wiki-worker and PostgreSQL JobStore with a product ingestion plugin; these are long-lived platform processes, not Codex subprocesses or per-material scripts. Integrate exclusively by versioned REST/source lifecycle contracts; do not share WeKnora database or Asynq.

Alternatives considered: moving all insurance logic into Go duplicates existing compiler contracts; wrapping the historical temporary recovery scripts retains per-run admission and repeated history replay. Both are rejected. Reuse pure routing, field-task, evidence and compiler functions behind persistent service-owned jobs instead.

# Scheduling correction: bounded stages, finalizer last

Root jobs must not wait while holding a worker slot for child jobs. Admission queues a short upload reconciliation stage. Each stage performs bounded work, commits its artifacts and outbox event with its P1 completion, and releases the slot. Pending source/upload observations use configured P1 retry_wait with a bounded deadline; they never retry a model dispatch. Outbox consumers idempotently enqueue the next stage or field windows. A scoped periodic product reconciler repairs crash gaps and observes terminal children that produced no event. Only after the final publication/probe barrier, or a terminal product failure, does it enqueue the root finalizer. The existing root authority check stays intact. This uses the existing Harness P1 queue and does not change claim filtering or share WeKnora's queue.

Non-field checkpoints use immutable ProductArtifact rows, keyed by run/kind/key and bound to exact dependency, payload bytes/hash, producer job/generation, and optional actual model call. Source/base/routing/compile artifacts identify a rule or source producer, never a fake model receipt. Non-field provider calls have their own ProductStageModelCall audit rows and the same active-lease fence: reserve before dispatch, commit exact request before network, commit original response before projection, recorded replay without network, uncertain dispatch becomes interrupted. Artifact writes join stage settlement and outbox in one P1 report_success transaction. Source/native/parser and previous Active projection checkpoints remain available after restart.

## Incremental compiler contract closure (2026-09-13 implementation finding)

The old batch request requires every existing entity to have a MATCH decision in the current model-backed C corpus. That condition would replay historical classification and is incompatible with G3-AUTO-3. Extend the existing request with an optional `published_base` binding; absence preserves exact legacy canonical bytes/validation. The binding contains contract `published-base-binding.830.g3.v1`, exact `release_id`, `activation_epoch`, `candidate_sha256`, `manifest_digest`, complete previous `entity_bindings`, and a domain-separated `binding_sha256`. It is derived only from the verified signed platform base snapshot. It is a claim to check, never standalone authority: Go's existing current-base validation compares every carried binding and identity with the actual Ready parent and still compares all previous definitions/fields/pages/versions and member digests.

Current C inputs contain only selected product materials. Old entity bindings can be carried from `published_base`; new or selected existing entities still require replay-valid current C decisions. Bound source evidence for carried entities is checked against unchanged parent source closure, not invented current model proposals. The base binding must cover exactly the parent's entity set; no extra/missing or changed identities. The compiler merges carried bindings with new bindings by entity ID and never fabricates model receipts for the carried subset. Browser never provides this binding. Keeping previous source/field bytes in the immutable release is distinct from rerunning their model/validation work.

The request can additionally carry optional `refresh_fields` (canonical `{entity_id, field_key}` rows) for existing fields selected by a new source dependency or a platform failed-field retry. Each pair must exist in the actual base and belong to a current replay-valid C entity binding. Those fields are excluded from deterministic carry and replaced exactly once in the delta; all other previous fields remain exact. The source/Schema cache dependency decides whether the replacement needs a provider call. Retry may reuse previous recorded C semantics with stable knowledge-based material IDs and run the deterministic resolver against the new exact Head; it does not fabricate or resend historical model calls.
