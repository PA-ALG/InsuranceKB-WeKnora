# 11 · 解析组件、模板抽取与图表处理

> 回答三个决定抽取上限的问题：① 同构文档（如分红险说明书）如何用模板做专项抽取而不引入大量人工；② 解析/OCR 基础组件怎么选；③ 说明书里的图表怎么处理。
> 关联：[04-extraction-harness.md](04-extraction-harness.md)（通用管道）· [08-tech-selection.md](08-tech-selection.md)（选型总表）· [05-golden-set-eval.md](05-golden-set-eval.md)（一切选择用分数裁决）

## 1. 模板抽取：三层设计，模板是"归纳"出来的，不是人写的

**核心原则：人工只审核模板，不编写模板；建不建模板由评测分数决定，不由感觉决定。**

### 1.1 文档族识别（自动）

同一版式的文档构成一个**文档族**（family），如"分红险产品说明书 2026 版式"。族的识别用**结构指纹**自动聚类：章节标题序列、表格列名集合、版式特征（页眉页脚模式、目录结构）做哈希/相似度。族内文档 ≥3 份才有建模板的价值。eval runner 增加**按族分组出分**——哪个族分数低，一目了然。

### 1.2 模板归纳（强模型一次性投入，弱模型日常复用）

模板 = 数据（YAML，入 schema 注册表版本管理），内容是字段→锚点规则：

```yaml
family: par-product-brochure-2026        # 分红险说明书族
fields:
  - field_id: dividend_distribution
    anchors: {section: "红利分配", regex: "以(现金|增额交清)方式", table_column: null}
    few_shots: [ {quote: "…", value: "…"} ]   # 来自金标的真实示例
  - field_id: illustrated_rate_basis
    anchors: {section: "利益演示", table_column: "演示利率"}
```

**模板的来源就是金标的副产品**：gs 里每个字段带 (page, quote)，族内多产品同字段的证据上下文模式（所在章节、前后文、表格列）可自动归纳出锚点；归纳由强模型一次执行，产出模板草案 → 人工**只做审核**（对照 2~3 份文档确认锚点），不从零编写。这与 master plan P1-3"基于知识背景自动生成 Schema/提示词，人工确认后用于生产"完全同构。

### 1.3 运行时 fast path（模板命中优先，失败回退通用管道）

```
文档 → 族识别 → 命中模板？
  ├─ 是：锚点定位章节/表格列 → 确定性抽取或单字段小 LLM 调用 → 引文回验
  │       置信不足/锚点未命中的字段 → 降级进通用管道
  └─ 否：通用八步管道（04）
```

效果：同构文档上大幅削减 LLM 调用且更稳；模板失配不致错——回退路径永远存在，且一切产出仍过统一校验链（回验/清洗/三态）。

### 1.4 闭环（"定点解决一类问题"的机制化）

按族出分 → 低分族触发"模板归纳"任务 → 模板上线 → 该族分数回归对比 → 模板版本化留痕。**这个循环里人工只出现在"审核模板草案"一处。** 落地排期：004 先交付族指纹 + 按族出分（成本极低）；模板归纳与 fast path 作为 006 change，等基线分数指出哪些族值得建。

## 2. 解析/OCR 基础组件：分层升级链 + 用金标分数做 A/B

2026 年现状（OmniDocBench v1.6）：PaddleOCR-VL-1.6、MinerU2.5-Pro 综合领先；**所有模型中文准确率低于英文**——组件选择必须用我们自己的金标回归验证，不能只看公开榜单。

| 层 | 组件 | 适用 | 状态 |
|---|---|---|---|
| L0 文本层直读 | pdfplumber（现用） | 文本型 PDF（本批样本全部适用） | ✅ 已在 002 |
| L1 版面+表格结构 | **PaddleOCR 3.x / PP-StructureV3**（表格结构识别→HTML/markdown） | 含复杂表格的说明书/费率表；扫描件 OCR | 004~006 引入 |
| L2 复杂版面一体化 | **MinerU 2.5**（08 已选为对照解析器，AGPL 进程隔离） | L0/L1 质量抽检不过关的文档 | 按需启用 |
| L3 VLM 直读 | **qwen-VL（生产已有）**；备选 DeepSeek-OCR-2 | 图表页、疑难页兜底 | §3 |

机制两条：
- **自动升级链**：每层出口有质量检测（乱码率、字符密度、表格完整性启发式），不达标自动升级下一层——继承 LLM-wiki-black"4 级 fallback"的经验但配上确定性检测；
- **解析器 A/B**：换/升级任何解析组件，跑同一套金标回归看**最终字段分数**变化（不是看解析中间产物），eval runner 天然支持。平台侧 WeKnora docreader 保持不动，本节只管 harness 抽取线。

## 3. 图表处理：按对象类型分流 + 证据风控

说明书中的"图表"实际是三类对象，分开处理：

1. **真表格**（费率表、利益演示表、责任对照表）→ PP-StructureV3 表格结构识别 → markdown 表 → 按字段口径抽取（如费率只抽"典型示例"，原表整体登记为证据）。**分红险利益演示表是模板抽取的最佳场景**：族内列结构一致，模板直接锚定列名。
2. **图形图表**（现金价值曲线、流程图、组织图）→ **caption-first**（继承 LLM-wiki-black `plans/multimodal-images.md` 设计）：qwen-VL 生成结构化描述 JSON（图类型/坐标轴/关键数值/结论）→ 作为文本进通用管道；图片本身按 master plan P3-3 登记为图片证据（页码+位置），Claim 可引用。
3. **装饰性图片** → 跳过（VLM 一次分类完成 1/2/3 分流）。

**证据风控规则（硬约束）**：高风险字段（risk_level=high）**不允许只有图形图表证据**——图表数字的 VLM 误读风险高；必须有文本或结构化表格证据佐证，否则该字段标 low confidence 进复核。这条写入 04 校验链。
