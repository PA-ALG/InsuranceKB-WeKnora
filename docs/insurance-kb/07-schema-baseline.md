> 业务方于 2026-07-10 提供《产品知识库字段标签维度》Excel，作为产品知识 schema 的**基线**（baseline-2026-07-10）。本文记录基线的接入结果、与旧项目字典的关系、字段元属性增强计划，以及我方评估后提出的**扩展字段提案**（候选状态，待业务确认后并入 v1.1）。

与 LLM-wiki-black 字段字典（06-asset-migration.md）的关系：基线覆盖了旧字典的 6 险种并**新增 4 个险种**（两全/护理/补充养老/失能收入）；旧字典中每字段的 `valueType/extractable` 标注、模块分组、险种白名单等**工程元数据仍从旧字典继承**。两者合并后构成 schema 注册表 v1。

注意两点差异（符合已定架构，无需修改基线）：
- 基线基础字段**不含 QA 字段**——QA 已定为一等知识对象（03-knowledge-model.md §2），不进产品实体；旧字典里的 QA 字段不再迁移为字段。
- `取值来源` 列（官网同步/产品条款/人工填充/保险责任/免责条款/核保数据…）将映射为 Evidence 的**来源权威等级**与抽取路由（哪类文档才允许填该字段），这是基线里最有价值的治理信息。

## 2. 字段元属性增强计划

基线只有 5 列（字段名/取值/英文名/说明/取值来源）。进入 schema 注册表 v1 时每字段补齐以下元属性（继承旧字典 + 新增）：

| 元属性 | 用途 | 初值来源 |
|---|---|---|
| `field_id` / 英文名 | 稳定标识（基线英文名列大量为空，需补） | 翻译 + 旧字典对照 |
| `value_type` | short/long/enum/number/date/table | 旧字典 + 取值列推断 |
| `extractable` | 可否从文档自动抽取 vs 人工/系统填充 | 取值来源列映射 |
| `allowed_sources` | 允许取值的文档类型（条款/说明书/费率表/官网/人工） | 取值来源列 |
| `risk_level` | high/medium/low；高风险字段（豁免、等待期、免责、理赔限制、给付比例）触发自一致性投票与强制审核（04 §5、05 §7） | 我方标注+业务确认 |
| `aliases` | 同义词/否定表达（定向补漏检索用，04 §6） | 旧字典 + 逐步积累 |
| `evidence_required` | 是否必须携带原文证据才可发布 | 高风险字段默认 true |

## 3. 扩展字段提案（候选状态，待确认）

评估依据：样本产品文档实际结构（条款/说明书/费率表）、LLM-wiki-black registry schema、监管条款必备要素。**全部为新增提案，不改动基线既有字段**。
>
> **✅ 2026-07-11 业务方确认：18 条全部接受**，已并入 v1.1（机器可读：[`schema-baseline/extensions-v1.1.yaml`](schema-baseline/extensions-v1.1.yaml)）。开发中若某字段确实无法从样本抽取，降级/移除需留痕。

### 3.1 基础字段（全险种）

| # | 提案字段 | 依据 | 风险 | 抽取难度 |
|---|---|---|---|---|
| B-1 | 条款备案/批复文号 | 条款首页必有；监管溯源与产品唯一性对齐的锚点（多产品文档路由时最可靠的确定性特征） | 低 | 易 |
| B-2 | 条款版本标识 + 条款生效日期 | 版本治理核心（03 §4）；"开始使用时间"是销售口径，与条款版本不是一回事 | 高 | 中 |
| B-3 | 责任免除（结构化清单） | 各险种仅有"特殊免责/免责少"等亮点式字段，缺完整免责清单；旧字典 exclusions_official 已验证可抽 | 高 | 中 |
| B-4 | 等待期内出险处理 | 条款必有（返还保费 vs 现金价值），理赔高频争议点 | 高 | 中 |
| B-5 | 复效条款（效力中止与复效条件） | 条款必有，保全高频问题 | 中 | 中 |
| B-6 | 理赔申请时效与申请材料 | 条款必有，理赔线刚需 | 中 | 易 |
| B-7 | 销售地区限制 | 版本/适用性判断维度（master plan §1.3 版本正确率依赖） | 中 | 难（常不在条款内，需运营数据） |
| B-8 | 减额缴清 | 长期险条款常见保全选项 | 中 | 中 |

### 3.2 险种级

| # | 险种 | 提案字段 | 依据 |
|---|---|---|---|
| C-1 | 重疾 | 疾病定义标准版本（如 2020 重疾新定义） | 决定疾病释义整体口径，影响所有疾病字段 |
| C-2 | 重疾 | 身故责任（是否含身故/给付什么） | 与寿险搭配销售的核心问题；基线缺 |
| C-3 | 重疾 | 多次赔付间隔期与恶性肿瘤二次赔条件 | "赔付次数"字段的必要细化，高风险 |
| C-4 | 重疾/护理/失能 | 健康告知 | 寿险/两全 sheet 有该字段，重疾/护理/失能缺（仅有核保方式） |
| C-5 | 医疗 | 既往症定义与处理 | 理赔争议第一来源 |
| C-6 | 医疗 | 外购药/特药责任 | 近年产品竞争焦点，说明书必提 |
| C-7 | 医疗 | 停售后续保安排 | "保证续保期"的必要补充，监管重点 |
| C-8 | 年金/补充养老 | 年金领取起始年龄、身故保险金口径（已交保费/现价取大等） | 条款必有；基线"领取规则"过粗，建议拆分 |
| C-9 | 意外 | 伤残评定标准、公共交通意外额外给付 | 条款必有；"意外伤残"字段的细化 |
| C-10 | 寿险（分红型） | 红利分配方式与演示利率口径 | 样本中 6/13 个产品为分红型，基线只有"有分红"是/否 |

### 3.3 处理流程

1. 本表连同依据材料提交业务方逐条确认（接受/拒绝/修改）；
2. 接受项并入 schema 注册表 v1.1（版本化，03 §8）；
3. 生产运行后，抽取管道 extras 通道（04 §8）发现的新候选字段按同一流程转正。
