注意两点差异（符合已定架构，无需修改基线）：
- 基线基础字段**不含 QA 字段**——QA 已定为一等知识对象（03-knowledge-model.md §3），不进产品实体；旧字典里的 QA 字段不再迁移为字段。
- `取值来源` 列（官网同步/产品条款/人工填充/保险责任/免责条款/核保数据…）只映射为候选 source role 与抽取路由。Evidence 的实际 authority 必须来自可信来源注册/ingest trust policy，分类模型、schema 或模板都不能据字段名提权。

## 2. 字段元属性增强计划

基线只有 5 列（字段名/取值/英文名/说明/取值来源）。进入生产 schema registry 前，每字段只按有权业务资料、领域专家决定与经 provenance/Golden Slice 批准的规格补齐以下元属性：

| 元属性 | 用途 | 初值来源 |
|---|---|---|
| `field_id` / 英文名 | 稳定标识（基线英文名列大量为空，需补） | 领域命名规范 + 人工复核；旧系统只作行为对照 |
| `value_type` | short/long/enum/number/date/table | 基线取值 + 样本/业务规则独立推断 |
| `extractable` | 可否从文档自动抽取 vs 人工/系统填充 | 取值来源列映射 |
| `allowed_sources` | 允许取值的文档类型（条款/说明书/费率表/官网/人工） | 取值来源列 |
| `risk_level` | high/medium/low；高风险字段（豁免、等待期、免责、理赔限制、给付比例）触发自一致性投票与强制审核（04 §5、05 §7） | 我方标注+业务确认 |
| `aliases` | 同义词/否定表达（定向补漏检索用，04 §6） | 有权语料/领域专家 + 逐步积累；不复制旧 prompt/词表表达 |
| `evidence_required` | 是否必须携带可回验 Evidence 才可发布 | **所有可发布 Claim 恒为 true，模板不可覆写为 false**；高风险字段再叠加来源白名单、多证据/共识与人工门禁 |

## 3. 扩展字段 v1.1（已确认）

评估依据：公司有权使用的样本产品文档（条款/说明书/费率表）、监管资料与领域专家确认。与旧 registry 的概念重合只记录“能力曾存在”，不作为实现 provenance，也不得据此复制字段元数据、映射或 prompt。**全部为新增提案，不改动基线既有字段**。
