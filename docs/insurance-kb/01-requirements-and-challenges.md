# 01 · 总体需求与技术难点

> 本文固化业务方提出的痛点、需求与约束（2026-07-11 讨论定稿），并给出每一项到设计文档的映射。它是"我们为什么做这些设计"的依据；设计本身见 02~07。

## 1. 业务痛点（为什么要做）

| # | 痛点 | 展开 |
|---|---|---|
| 1 | 知识静态，入库即"死" | 业务规则在变而知识不更新；组织停留在"文档+片段"，同一概念散落多文档、口径冲突无人裁决；答错不会自我修正；产品责任调整后难以维护 |
| 2 | 各业务线各自维护，无全局视角 | 代理人问题横跨产品/理赔/权益，回答有缺漏；覆盖了什么、缺什么、重复什么，平台与专家都不可见 |
| 3 | 知识加工易出错，质量难保证 | 复杂条款 PDF、嵌套规则表、跨文档关联处理失败即丢弃或人工返工；依赖人工经验 |
| 4 | 发现问题慢，更新严重滞后 | 系统答了什么、对不对，平台不知晓；靠事后人工抽检；无自动反馈机制 |

**目标**：结合 Karpathy LLM Wiki 范式，把知识体系从"给人看的文档库"升级为"给 Agent 用的知识基础设施"——可自动更新、可进化、有版本、可溯源，同时对人保持真实 wiki 般的可读可审。

## 2. 十二项技术难题 → 设计落点

| # | 难题 | 设计落点 |
|---|---|---|
| 1 | 一份文件涉及多产品，实体对齐不准 | 事实必须绑定 `(product_id, concept_id, evidence)` 才入库；备案号/产品代码确定性对齐优先，LLM 只做候选；对齐不了进 unassigned 池（03 §1、04 §7） |
| 2 | 结构化产品知识库无法自动拆分接入 | 结构化直入通道：JSON/FAQ 不走 docreader，直接规范化为 Claim/QA 批次（master plan P0-2） |
| 3 | 无明显结构的字段抽不到（如豁免） | 三态字段 + 同义词检索定向补漏"判断题"pass（04 §6） |
| 4 | 缺口不可见 | 完整度 = 产品×schema字段填充率矩阵，null 即缺口；叠加问答日志信号（master plan P1-1、workbench） |
| 5 | QA 怎么挂 | QA 为一等知识对象（权威/派生两类），实体页聚合展示，不做实体字段（03 §2） |
| 6 | 第二/三批材料自动补全+发现冲突 | 增量合并三分支：新增/一致(追加证据)/冲突；冲突走裁决序（03 §5、04 §7） |
| 7 | 版本与回退（类 git） | Claim/页面 revision 链 + 库级 release 快照，回滚=切快照指针（03 §4） |
| 8 | 对人友好的 wiki + 概念义项（如"在线问诊"跨产品） | 三层页面模型：概念主页/产品限定页/义项索引（03 §3）；阅读在 WeKnora Wiki 界面 |
| 9 | 弱模型下抽取准确率与覆盖率 | 八步抽取管道：短任务拆分、引文回验、投票、补漏、分级路由（04 全文） |
| 10 | 几十万片段的编译工作量 | 不全量编译：优先级驱动（在售>停售存量>归档）+ 模板化批处理 + 增量编译；成本估算模型（04 §9） |
| 11 | 片段关联到已有 wiki、冲突采信 | 增量合并 + 六级权威序五步裁决，自动裁决全留痕可翻案，兜底人工（03 §5） |
| 12 | 评估标准/golden set | 独立金标注 Agent 子系统，最强模型直读标注，eval runner 一键回归（05 全文） |

## 4. 全局约束（所有设计必须遵守）

1. **弱模型是全局约束**：生产模型为 minimax 2.5 / qwen 3.6 / qwen-VL 级；DeepSeek v4 作裁决/升级模型。设计"用 harness 鲁棒性补模型能力"，不依赖强模型单次长输出。
2. **金标 = 最强模型标注**（2026-07 决策）：金标注是独立可持续维护的 Agent 子系统；本阶段不引入人工，最强模型即标准。评测目标 = harness+弱模型逼近强模型直读，达到即达标。
3. **插件式架构**：WeKnora 原样跟随官方上游；保险能力全部在 `harness/`（ADR-001，02 §硬边界三条）。
4. **Python 优先**：抽取、校验、harness 工程用 Python；多成员协作。
5. **SDD/TDD + 文档驱动**：先设计文档 → OpenSpec（proposal/specs/design/tasks）→ 开发；能用成熟开源不自研。
6. **示范项目标准**：文档与代码结构必须让任何人随时可接手；HANDOFF.md 持续更新。
7. **样例文件仅为理解数据形态**，不作验收目标；验收用能力标准（05 的指标与门槛）。
