## 新增范围与执行顺序

1. **先隔离数据库进程。** 新增专用 PostgreSQL 容器 `weknora-g3-830-postgres-recovery-01` 与专用数据卷 `weknora-g3-830-postgres-recovery-01-data`，只复用本机 exact image `sha256:af585013f97f622715de01e48d00558f7edf17055d7b40deafc9f98ca8d99a56`，build=0、pull=0。加入原计划的 G3 内部网络，使用 `postgres-g3` 别名；不再把旧 PostgreSQL 连接到 G3 网络。新 PG 不映射宿主机端口；应用仍仅使用原定本地端口。
2. 实现前冻结现有隔离计划的有限修订和新恢复执行器设计，独立复核初始化参数、镜像启动所需文件、资源限制、私有凭据路径与读写对象。不得直接复制包含密码的 inspect 输出到仓库。新容器初始化仅使用新数据卷；不挂载原 PG 数据卷，不重启、改配置、删除旧容器或旧空库。
3. 新执行器及测试写入新的 recovery 文件，保留全部原 v3 字节。范围只包括独立 PG 初始化、完整错误回执、一次备份恢复及原来源环境剩余步骤的显式接续。已关闭的产品代码、上传 v2、embedding guard、材料清单与发送正文不变。此为回到设计后的独立恢复切片，不把旧 v3 两轮修复额度重置；新增切片最多一轮集中修复复审，仍有阻断则停止。
4. 用模拟反例验证目标漂移/同名对象预存在/错误数据卷/不完整输出/超时/二次执行均拒绝，原流程下游约束保留。独立 Reviewer 验证冻结代码、测试、命令、权限与完整执行包后才能执行。若隔离或初始化所需配置不能在此范围内明确，就停止，不猜测配置。
5. 真实执行时重新核验旧 PG 容器 ID、镜像、选定来源快照及文件身份；旧库仅做只读检查和一次一致性备份。备份只在内存中保留，记录长度、SHA、工具版本与只读完整解码结果；不写宿主机备份文件。新独立 PG 内创建目标库并执行**最多一次**事务性恢复。没有数据库恢复自动重试、清库、删除或换名重跑。
6. 恢复前持久化 STARTED 记录；每个操作保留具体阶段、退出码、输出长度/SHA、脱敏错误类别。原始错误输出仅存新私有目录（0700/0600），仓库中不放凭据、原始 SQL 或数据库内容。任何异常、超时或结果不明都立即 STOP 并保存现场；新 PG 异常不得触发旧 PG 的重启或修复动作。
7. 只有新 PG 恢复成功、来源快照/文件校验和隔离前置全部通过，才接续原先已经批准的应用/文档解析器/独立队列配置。随后仍使用冻结的上传 v2 与 guard，完成原 **11 份新 PDF、204 段、693129 字节、最多 11 次 DashScope 向量请求、15 份来源登记**。先验证新 provision PASS 回执能被原上传程序完整接受，不扩大或绕过其准入检查。不能接受时停止，另记设计缺口。
8. 执行器冻结时为环境阶段设定总时限及逐操作时限；外发阶段沿用原 24 分钟窗口、首次失败即停止、失败/不明占用请求额度的规则。本恢复只允许一个执行窗口。收到本方案批准后，若独立复核通过且范围不变，总控可直接执行，不再重复询问同一范围。

## 验收与边界

完成标准：独立 PG 健康与 exact 身份有回执；来源环境 provision PASS；上传/向量/15 来源登记分别有真实回执；旧库选定快照前后校验；所有实际创建对象和失败均独立记账。本地代码通过不替代这些执行结果。

新建 PG 仍共享本机 Colima 主机资源；独立进程只能隔离数据库进程崩溃，不能承诺完全消除主机资源竞争。执行前应读取现有资源配置并冻结可用的限制，不自动增加主机资源或调整旧容器。

本方案不包含产品识别/候选编译模型调用、审核模型、人工批准、发布、激活、生产部署，也不把 G3 改记为 PASS。具名结构确认人/待办负责人仍不推测、不重复索取。
