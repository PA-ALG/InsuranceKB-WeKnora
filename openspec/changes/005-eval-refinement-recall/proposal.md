# 005 · 评测尺子升级与召回改进

## 为什么做

004 基线（micro F1 0.184）的失分归因显示两个系统性问题，且**必须先修尺子再优化抽取**，否则后续所有迭代都在按失真的分数调优：

1. **长文本字段逐字等价判定过苛**：责任免除清单、既往症定义、续保规则等 long 型字段，弱模型抽取内容基本正确但表述/截取范围与金标不同，被判 ❌（高风险字段表的错误多数属此类）。真实抽取质量被显著低估。
2. **漏抽是真实召回缺口**：25 条金标 present → 预测 unknown，需逐条归因（路由没送到？prompt 没问对？清洗误杀？）。

## 做什么

### A. 尺子升级（eval v2）

1. **值等价三级判定**：短值（enum/number/date/short）保持现有确定性归一化；**long 型字段改为"关键要点匹配"**——金标值在入库时拆为要点清单（key points，由金标构建时的强模型一次性产出，作为金标 release 的一部分），预测值按要点覆盖率计分（要点召回 ≥80% 且无矛盾要点 = 正确；引入 partial 计分列展示但主指标仍按阈值二值化）；
2. **judge 兜底通道**（可选开关）：要点匹配不确定的样本落 eval-judge-queue，复用 claude-session 批处理形态；默认关闭，报告标注未裁决计数；
3. **报告增强**：错误明细按错误类型分类（值粒度/漏抽/幻觉/三态混淆/证据错位），给出可执行的归因标签——报告直接生成下一轮改进的工单清单；
4. gs-v0.1 wip 金标补要点清单（11 产品 long 字段，强模型一次性任务，**列入遗留清单 B 类**，本 change 先交付机制与小样验证）。

### B. 召回改进

5. **漏抽归因工具**：对金标 present / 预测 unknown 的字段自动定位——金标证据页是否在路由结果中（路由问题）/在路由中但抽取为空（prompt 问题）/抽到但被清洗（清洗误杀），输出归因统计；
6. 按归因结果做定向修复（路由关键词补充 / prompt 变体 / 清洗白名单），**每次修复必须跑 3 产品基线对比出分**（低成本回归，单产品 ~6-12 万网关 token，属可接受）；
7. 死信自动复跑策略：截断类死信自动升 max_tokens 重试一档（B4 的机制化）。

## 不做什么

- 不动金标已有标注值；不做全量基线（遗留 B2）；不引入新模型。

## 验收

- eval 自洽性仍满分；对 004 已有 3 产品 pred 重跑 eval v2，报告呈现"尺子修正后"的分数与错误类型分布（预期 long 字段误判显著下降，真实缺口凸显）；
- 漏抽 25 条全部带归因标签；至少一类归因完成定向修复并有 before/after 对比分数；
- 门禁全绿，002 既有 eval 测试兼容（v1 口径保留可切换）。

## 依赖

004 合入；金标要点清单的全量生成列遗留清单（机制交付即可验收本 change）。
